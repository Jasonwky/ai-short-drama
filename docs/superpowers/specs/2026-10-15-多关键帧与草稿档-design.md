## 一、切镜说明(只改文案)

一段固定说明,出现在两处:编辑段落页的「关键帧」区(紧挨着时间轴)、视频面板顶部的限制说明里。

> H3 在一条 8 秒片里通常会**自己切 1–3 次镜头**,提示词写「固定机位」或首尾帧钉同一张图都挡不住(2026-10-14 实测)。
> 要锁住某一刻的画面,用关键帧;两张关键帧之间若是连续动作,常能在一个镜头里过渡过去。

文案放在 `readiness` 旁的一个常量里(`CUT_NOTE`),两个模板引用同一份,改一处两处都变。

## 二、多关键帧

### 2.1 库结构 v10:新表 `segment_keyframe`

| 列 | 含义 |
|---|---|
| `id INTEGER PRIMARY KEY AUTOINCREMENT` | **编号永不复用**(与段落编号同理:删了的关键帧,历史任务里的 `keyframe_id` 不能指到别人) |
| `segment_id INTEGER NOT NULL REFERENCES segment(id) ON DELETE CASCADE` | |
| `time_sec REAL NOT NULL` | 第几秒 |
| `image_prompt TEXT NOT NULL DEFAULT ''` | 关键帧图提示词(`@角色` 写法同首帧) |
| `frame_path TEXT` | 当前用的那版图 |
| `legacy_v9 INTEGER NOT NULL DEFAULT 0` | 1 = 从 v9 段落列搬来的那张(只用于解释 P12 时代的旧任务,见 2.3) |

- 迁移(v9 → v10):建表;`key_time_sec` 不为空的段落搬一行进来(时刻、提示词、图原样,`legacy_v9 = 1`);
  然后 **`ALTER TABLE segment DROP COLUMN`** 删掉段落上的三列(本仓 Python 3.14 自带的 SQLite 支持删列,`tests/llm/test_runs.py` 造旧库就是这么删的;
  三列没被索引 / 触发器引用)。删掉比留着不读写好:漏改的读写点会当场报错,而不是静默读到旧值
  - 造旧版本库的测试夹具(`test_migration`、`test_runs` 等)要同时 DROP 新表
- 一个段落 0–3 行;**上限在代码里判**(`readiness`),不用触发器 —— 超了要给人话原因
- `repo` 白名单加 `segment_keyframe` 的 `time_sec / image_prompt / frame_path`
- 工程包:导出 / 导入带上这张表,`frame_path` 走同样的路径前缀重映射与 sha256 校验;
  **任务参数里的 `keyframe_id` 也要按新编号重映射**(导入时 id 全部重新分配,不改就指到别的剧的关键帧或空号)
- 删段落:关键帧行跟着删(CASCADE);生成历史与文件保留(与删段落现行规则一致)

### 2.2 规则(`readiness.key_problems` 改为逐张判)

- 每张:离两头 ≥ 0.5 秒(现行 `KEY_MARGIN_SEC`);帧号不与首帧 / 尾帧锚点重合;有提示词;有图
- 张与张之间:**相隔 ≥ 0.5 秒**(按秒判,同时帧号不能相同)
- 张数:> 3 → 阻塞「最多 3 张」;= 3 → 警告项「3 张关键帧:此数量未经真机验证(实测到 2 张)」
- 现有的「首尾帧 + 关键帧未经真机验证」警告保留(任何张数都算)

### 2.3 任务怎么指向「哪一张」

生成任务仍挂在**段落**上(`target_type = 'segment'`,不改 task 表),参数里:
`"writes": "key_frame_path", "keyframe_id": <行号>`。

新增一个小函数 `targets.slot(store, task) -> (表, 行号, 字段)`,把「这条任务写到哪」集中算:
关键帧任务 → `("segment_keyframe", keyframe_id, "frame_path")`,其它 → `(target_type, target_id, writes)`。
用它的地方:worker 写回(`collect`)、挑历史版本(`versions`)、参考帧面板按目标分组、留痕里「同目标的其它尝试」、改参重跑(参数原样带上 `keyframe_id`)。

- 关键帧行被删后任务才完成:任务照常记 done,产物留在任务记录,备注「关键帧已删除」;不写回
- 旧库里 P12 时代的关键帧任务没有 `keyframe_id`(任务参数不可改,补不进去):`targets.slot` 把它解释为**该段 `legacy_v9 = 1` 的那行**;
  那行被删了 = 「关键帧已删除」。**不能**用「该段 id 最小的那行」—— 人删掉搬来的那张再加新的,旧任务就会误指到新的那张

### 2.4 出视频

`plan_video`:模式锚点之后,**按时间升序**逐张追加 `(图, 帧号)`;`build_h3` 已支持任意个锚点,串 AddGuide 不改。

### 2.5 作废传播

- 改某张关键帧的**时刻**:本段视频作废
- 改某张的**提示词**:那张的图作废 + 本段视频作废
- 加一张 / 删一张:本段视频作废(删的那张图随行一起没了)
- 换某张的历史版本:本段视频作废
- 段落其它字段的作废规则不变;原「清 `key_frame_path`」的三处改成清关键帧行的 `frame_path`:
  `invalidation.apply`(换角色 / 场景 / 道具参考图、改段落提示词 → 本段**所有**关键帧图作废)、`storyboard.save`(改某张提示词 → 只清那张)、
  `versions`(`_FRAME_FIELDS` 判断换的是哪类帧)

### 2.6 界面

- **编辑段落页**:关键帧区变成列表,每张一行(第几秒 · 提示词 · 删除),底下「加一张」(满 3 张时置灰并写原因);
  时间轴上画出每张的位置;切镜说明在这里
  - 保存走现有的两态(先算作废代价,确认才落盘)—— 关键帧的增删改与段落其它字段一起进同一个确认页
  - **表单带每张的行号**(新加的行号为空):靠行号判断「改了哪张、删了哪张、加了哪张」—— 只改第 2 张的时刻时,第 1 张的图不能被清;
    确认页把这些隐藏字段原样回传(现有 `confirm_page` 已支持列表字段,如 `character_ids`)
- **参考帧面板**:每段的关键帧卡变成每张一个子卡(图 · 第几秒 · 提示词 · 生成按钮 · 历史版本)
- **视频面板**:「关键帧钉住了吗」逐张显示(锚点图 vs 那一帧并排 + 差值);`keycheck.check` 改为返回列表,
  数据仍**从视频任务参数的 `anchors` 读**(所有帧号 > 0 的锚点,尾帧锚点是 -1 不算),每张单独判 stale
- **增量补全**:「关键帧」类按**张**列目标(「第 2 段 · 第 3.0 秒」);确认时只认确认页列出的**关键帧行号**(补全的两态规则)

### 2.7 锚点变多后的模板预设

- `build_h3` 的锚点节点编号是 `40 + 2k / 41 + 2k`,最多 5 个锚点(首尾 2 + 关键帧 3)占用 40–49
- 模板预设保存前的试拼(`presets.trials`)现在只试 0–2 个锚点 → **扩到 0–5 个**,否则多锚点的段落会在 dispatch 时才炸
- `graphs.apply` 对「加节点」**撞上已有节点号直接覆盖**,不报错 —— 预设里画布新加的节点若恰好编号 42–49,会静默顶掉锚点。
  改为撞号即 `ValueError`(fail-loud);已存的预设在多锚点下撞号的,规划时报出原因
- **规划时就试拼**:`plan_video` 建任务前把内置拼法叠上当前预设试一次,叠不上就拒绝规划并给原因(不等到云机上才失败)

## 三、草稿档(10 步)

- **视频面板**生成按钮旁加档位:「定稿 · 20 步(默认)」/「草稿 · 10 步」
- 档位进任务参数:`"steps": 10`(定稿不写这个键,保持与现有任务一致);**dispatch 时在叠完模板预设之后设步数** ——
  草稿档压过预设里的步数(人当场选的比全局预设具体)。按 `class_type == BasicScheduler` 找节点设,不认节点号(预设可能动过)
- **「定稿」档写实际步数,不写死 20**:当前视频预设若改过步数,按钮写「定稿 · N 步(当前预设)」
- **判「这条视频是几步出的」只有一个函数** `steps_of(task)`:拼出这条任务实际交出去的图再读 `BasicScheduler.steps`
  (改参重跑的自定义图、预设改过步数、草稿档三种来源一视同仁)。视频卡片的标记、导出提醒都用它:**< 20 步就标「少步数」**,
  不只认 `params.steps`
- 估时:草稿按 10 步算(`estimate.basis(...).video(..., steps=10)`),按钮旁两档各写一个预计时长
  - 已知偏差:锚点多每步会慢一点(实测 3 个锚点比 1 个慢约 4%),估时不计,界面不另说明(在估时的误差内)
- **视频卡片**:草稿片标「草稿 · 10 步」,旁注:「画质与定稿肉眼相近,但实测出过道具重复这类结构错误;定稿前用 20 步重出」
- **导出**:不拦。导出面板在「开始导出」之前列出「第 N 段只用了 K 步」(`steps_of` < 20);
  溯源报告不加新字段 —— 它本来就带每段任务的完整参数(含 `steps` / 自定义图)
- 增量补全、改参重跑:不加档位(补全一律定稿;重跑在画布里本来就能改步数)

## 四、纯文字模式

不实现视频生成(维持现状)。只改两处文案:编辑段落页的下拉项「纯文字(视频生成未实现)」→「纯文字(不支持:实测场景和道具守不住)」;
`video_problems` 对 `text_only` 的报错写同一个原因并带调研文档名。

## 五、测试与验收

- 单测:迁移(v9 库 → v10,带一张关键帧的段落搬过去、P12 时代任务的 `targets.slot` 解释);规则(张数、间距、上限、警告);
  规划(锚点按时间升序);写回 / 挑版本 / 删行后完成;作废传播各分支;草稿参数进 workflow 且压过预设;估时;导出提醒;工程包往返
- Playwright 有头自测:编辑页加到 3 张(第 3 张出警告、加第 4 张按钮置灰)、参考帧面板逐张卡、视频面板档位与草稿标记;
  `KEY_SELECTOR` 判据随面板变化更新
- 验收第 4 层(要开卡):真链路段落设 **2 张关键帧**,出一条片,两张都钉中(差值 < 20);另出一条草稿档片,验步数 = 10、
  耗时约为定稿一半

## 六、不做的

- 不做纯文字视频生成;不做 14 步档(两档够用,14 步同样出道具重复)
- 不改分镜 LLM(它不产出关键帧,现行如此;重拆分镜删段落时关键帧随 CASCADE 一起删)
- 不承诺切镜位置;不做「一镜到底」开关(实测做不到)
