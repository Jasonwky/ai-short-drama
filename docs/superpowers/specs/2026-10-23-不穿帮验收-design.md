## 1. 验收清单(取代单个「看过,没有穿帮」按钮)

清单在 `tools/cut/checklist.py`,一项一行,每项写明**出处**和**怎么判**:

| key | 检查项 | 出处 | 怎么判 |
|---|---|---|---|
| identity | 每个人认得出是谁(脸、发饰与角色一致,前后段没换脸) | 平台「人物建模」 | 人勾 |
| costume | 服装、发型、配饰与角色造型字段一致,和上一段一样 | 平台「服化道不一致」;场记连续性 | 人勾(卡片旁列出角色造型字段) |
| anatomy | 人数对、没有重复的人;手脚数对、没有多出来的手 | 平台「三条腿」;10-22 第 4 段多一只手 | 人勾(第 3 节标定后可转自动) |
| physics | 人在家具里、人与家具比例合理(不横出床、不比床长);动作不反常识 | 平台「违背物理或空间逻辑」;10-23 躺姿 | 人勾 |
| props | 道具大小、数量合理,在该在的手里 | 10-21 / 10-22 银针 | 人勾(卡片旁列场记表的手持) |
| direction | 朝向和视线对、没越轴(人物左右没无故对调) | 场记 180 度线;10-22 跪向 | 人勾;场记表的左右对调提示显示在旁边 |
| set | 场景对、陈设属于这个场景 | 10-22 床在正堂 | 自动:`furnish.problems`;人勾 |
| seam | 和上一段接得上(接缝两帧、切镜帧) | 场记连续性;平台「场景突兀切换」 | 人勾(看接缝并排图) |
| frozen | 画面没有异常静止 | 平台「画面异常静止」 | 人勾(暂不自动,没标定) |
| text | 画面里没有烧进去的字、没有双轨字幕 | 平台「双轨字幕」 | 自动:`textscan`(已有,拦导出) |
| blank | 没有影棚白底 | 10-21 | 自动:`blankscan`(已有,拦导出) |
| lipsync | 台词对得上、字幕对齐判卷通过 | 平台「音画不同步」 | 自动:字幕对齐判卷(已有) |

- **数据**:`segment_review` 加列 `checks_json`(库结构 v14),内容是人勾过的 key 列表。
  - 仍然写下不可改,仍然只认那条视频的 sha256;
  - 写入时校验:清单里所有「人勾」项都要勾上,才能存;
  - 没勾全不许确认,因为确认的意思就是「这些我都看过了」。
- **自动项**:卡片上显示通过 / 不通过,不过的照旧拦导出(已有逻辑不变)。
- **旧确认**:v13 时代的确认没有 `checks_json`,就绪清单视为「按旧清单确认的,需要按新清单重看」。题甲第 1 集的 9 段本来就都还没确认,没有损失。
- **快照与溯源**:导出 `begin` 把每段勾过的项快照进 `inputs_json`,溯源报告逐段列出。
- **面板**:视频卡片的「看片」区改成清单。
  - 每项一行:勾选框、出处小字、旁边是可对照的东西(造型字段、场记表一句话、接缝图);
  - 全勾了「确认」按钮才可点。

**为什么这样算「达到真人剧集水平」**(调研结论 1 + 反证 1):
- 平台审核条目最接近「能不能上线」,但只覆盖明显穿帮;
- 我们自己踩过的比例、常识问题补进清单;
- 每一项都有人或代码负责,缺一项就拦。

## 2. 竖屏可拍性(分镜阶段就拦)

纯函数 `tools/drama/framing.py`,`problems(aspect, entries, shot_type) -> list[str]`:

| 规则 | 依据 | 处理 |
|---|---|---|
| 竖屏 + 场记表里有人仰躺 / 侧躺 / 趴 + 同框 ≥ 2 人 → 景别必须是「近景」或「特写」 | 10-23 对照:全景原样 4/4 出床、床尾纵深 2/2 出床、近景 2/2 合理 | **拦**:分镜判卷打回;人手改的段落就绪清单拦首帧生成(与陈设表同级) |
| 竖屏 + 同框 ≥ 3 人 | 《生活对我下手了》主创「三个人以上的群戏比较少,即便有群戏也是会分批次」 | 只提示 |

- **景别**:`segment.shot_type` 现在是自由文本。分镜 schema 改成闭集(特写 / 近景 / 中景 / 全景);老数据不在闭集里的视为「没填」,只在规则命中时要求补。
- **场记表拼句**:
  - `blocking.POSE_PHRASE` 去掉否定句「身体不横出床沿」(实测没用,否定句可能起反作用);
  - 躺姿 + 近景时,代码追加「近景,画面只拍到躺着的人胸口以上,站着的人在画面上方」—— 这正是 10-23 对照里 a1 组的写法。
- 分镜提示词告诉 LLM 这条规则;判卷只认字面闭集。
- 共用:P17 的分镜方案 `shot_options` 判卷也调这个函数。

## 3. 生成后计数(先标定,再决定)

调研说人数、肢体这类问题,确定性检测比视觉大模型靠谱,但要**新增依赖**(MediaPipe 或 DWPose),而且在古装宽袖、多人遮挡、躺姿上的误报没有数据。

- **本期只做标定 spike**:
  - 在实战首帧上跑 MediaPipe(本机 CPU),量人数、手数与人工判的一致率;
  - 样本是题甲已有的 30 多张首帧,含 10-22 那几张重复人物、多一只手的;
  - 结果落档。
- **标定结果决定下一步**:
  - 准 → 下一期接成清单 `anatomy` 项的自动部分,不符就提示,或自动换种子重出;
  - 不准 → 不引入依赖,`anatomy` 继续人勾。
- 采用前读 LICENSE 原文(调研里的许可证都是子 agent 转述的)。

## 4. 不做的

- **骨架控制图**:2511 实测 0/4,骨架线还被画成琴弦、书本。换 2509 要在共用云机新增模型,另议。
- **两遍合成床面框**:实测人不出床,但被压短、有接缝,暂不采用。
- **视觉抽检加问题**:SynScale 不可用,且调研说判不准;等服务恢复再议。

## 5. 测试与验收

- **单测**:
  - `checklist` 的项表完整(每项有出处、有判法);
  - `segment_review.checks_json` 必须勾全、写下不可改、旧确认判为需重看;
  - `framing.problems` 的拦与提示分支;
  - `POSE_PHRASE` 不再含否定句;
  - 分镜判卷对躺姿多人非近景打回;
  - 库结构 v14 迁移。
- **真 LLM 契约测试**:分镜任务的现有契约测试加一个躺姿多人样本(题甲第 6 段),看 4 轮内能不能收敛到近景。
  - SynScale 不可用时 SKIP,不算通过。
- **Playwright 有头自测**:视频卡片清单勾全才能确认;少勾一项按钮不可点;导出检查列出未确认段落。截图存档。
- **实片验收**:题甲第 3、6 段按新规则重出首帧(近景),人眼判合格后,按新清单逐段确认,再导出。
