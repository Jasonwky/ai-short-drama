# 操作留痕查看 · 设计

- **日期**:2026-10-09
- **需求**(用户 2026-10-09):补齐 CLAUDE.md「三支柱」里的「一键拉取式可视化查看器(含复盘定位可视化)」。
  主用途 = **从产物倒查**(这张图 / 这条视频 / 这版成片是怎么来的);另带**失败归类**与**时间线**(用户定「三个都做」)
- **选定方案 A**:时间线以数据库的四张表为主(task / llm_run / export / workflow_preset,都带时间戳与目标、多数不可改),
  `journal/worker.log` 只作原始流水补充;**不改库结构、不改现有写日志的地方**
- **不做**:解析 worker.log 的自由文本成结构(方案 B,脆)、把日志改成 JSONL(方案 C,要动十几处调用点、新旧两种格式并存)

## 一、现状

| 留痕在哪 | 是什么 | 控制台里看得到吗 |
|---|---|---|
| `journal/worker.log` | 一行一条的自由文本流水:worker 每轮动作、控制台操作、导出、节点清单刷新 | 只有「主机」面板最后 40 行 |
| `journal/llm/*.json` | 每次 LLM 运行:输入、schema、每轮原文与问题、用量 | LLM 审阅页 |
| `task` 表 | 每次生成:参数、种子、提示词、参考、产物与 sha256、云机、出错原因、各时刻;生成参数不可变 | 各面板的「生成记录」只列状态 |
| `llm_run` / `export` / `workflow_preset` 表 | LLM 产物与审批、成片导出、模板预设 | 各自页面 |
| `outputs/tasks/<id>/workflow.json` | 实际提交给云机的工作流(P10) | 改参重跑时打开 |
| 溯源报告(`tools/cut/provenance.py`) | 从视频按「产物路径 → 产出它的 task → 它的参考」往回追的树,逐个核 sha256 | **只在导出成片时生成**,控制台里看不到 |

缺的是:一条任务的全貌、从产物倒推、把散在各处的失败放在一起看。

## 二、页面与入口

### 2.1 「留痕」面板(`/trace`,全局面板,默认筛当前剧)

登记进 `panels.REGISTRY`(自测随之覆盖)。自上而下三块:

1. **失败归类**:失败的任务、LLM 运行、导出按出错原因归类计数(§3.3),每类显示条数与最近一条,点开列出每一条、可进现场
2. **时间线**:四张表的事件(§3.2)按时间倒序,筛选:剧 / 集 / 云机 / 事件类型 / 时间段;每页 100 条;每条可点进详情
3. **原始流水**:`worker.log` 按时间段与前缀(`host=N`、`console`、`workflows`、`runtime`)过滤;行内 `task N` / `llm_run N` / `export N` 变成链接

### 2.2 倒查页(`/trace/product?path=<相对素材根的路径>`)

从一个产物往回追出一棵树。每个节点:

- 缩略图(图 / 视频 / 字幕文本);模型、种子、提示词、云机、创建 / 开跑 / 完成时刻与耗时;
- **sha256 核对**:文件哈希 ≠ task 表记的 → 标红;文件不在本机 → 标灰;没有生成记录 → 标「人工提供或导入的素材,没有生成记录」;
  导入的工程照实显示「未登记的机器(导入的工程)」(沿用溯源报告)
- **LLM 来源**(§3.4):确证的标「确证」,其余标「按时间推断」
- **同一目标的其它尝试**:失败的、被换下的旧版本(同目标、同写回字段)

**成片导出**不重新追:展示**导出时的溯源报告 JSON**(那是当时的快照,也是备案材料),再与当前状态对比,标出「之后换过的节点」。

### 2.3 任务详情页(`/task/{id}`)

参数(含绑定的模板预设)、参考图(每张可再进倒查页)、种子、提示词;实际提交的工作流(`outputs/tasks/<id>/workflow.json`,
有就显示并链到「在 ComfyUI 中编辑」);状态与各时刻(创建 / 开跑 / 完成 / 进入当前状态);出错原因;流水里提到这条任务的所有行。

### 2.4 入口

- 各面板产物旁一个小的「溯源」链接:参考帧、视频、资产图、四视图、字幕;成片面板的导出记录加「在控制台里看」(进导出的倒查页)
- 各面板「生成记录」的每一条 → 任务详情页
- 时间线 / 失败归类里的 LLM 运行 → 现有的 LLM 审阅页 `/llm/run/{id}`

## 三、口径

### 3.1 模块(只读;唯一的写见 §四)

| 文件 | 职责 |
|---|---|
| `tools/serve/trace.py` | 纯查询:`timeline`、`failures`、`failure_key`、`attribute`(事件归属)、`task_view`、`product_tree`、`export_view`、`llm_sources`、`siblings` |
| `tools/cut/provenance.py` | `_node` 改为公开的 `node`,倒查页与导出共用同一棵树;sha256 走 §3.6 的缓存 |
| `tools/serve/journal.py` | 加 `read(data_root, *, since, until, prefixes, limit=500)`:逐行流式读整个文件、过滤、识别链接 |
| `tools/serve/panels/trace.py` + `templates/trace.html`、`trace_product.html`、`task.html` | 三个页面 |
| `tools/llm/runs.py` + `tools/serve/runtime.py` | `runs.fail_stale` 与启动时调用(§四) |

### 3.2 时间线的事件(只用表里已有的时间戳,不编时间)

| 来源 | 事件 |
|---|---|
| task | 创建(`created_at`)· 开跑(`started_at`,**为空就不出这个事件** —— 4 步出图可能在两次轮询之间就跑完)· 完成 / 失败(`finished_at`,失败附原因) |
| task(本机生成:尾帧衔接、上传参考图) | 创建即完成,三个时刻相同 → **合并成一条**「本机生成」/「上传」 |
| llm_run | 发起(`created_at`)· 批准 / 驳回(`decided_at`);**失败没有单独时间戳**,记在发起时刻并附原因;`proposed` 没有时间戳,不出事件 |
| export | 开始(`created_at`)· 完成 / 失败(`finished_at`) |
| workflow_preset | 保存(`created_at`),打「全局」标签,任何剧的筛选下都显示 |

时间:库与日志都是 UTC,页面换成**北京时间**显示,悬停可见原始字符串(方便对照日志)。

### 3.3 归属(事件属于哪部剧 / 哪一集)

- 段落 → 集 → 剧;角色 / 场景 / 道具 → 剧;导出 → 集;LLM 运行按自己的目标同理;预设为全局
- **段落已删**(重拆分镜删段落、保留生成历史):目标段落不在表里,任务参数也没记集号 →
  **顺着这条任务的参考图往上追**,直到遇到目标是角色 / 场景 / 道具的任务(这些不会被删),由它定剧;
  追不到 → 「归属不明(段落已删)」,只在筛选「全部」时出现,**不硬塞进某一部剧**;集一律定不了,不猜

### 3.4 失败归类

`failure_key(error)`:把原文里的数字、路径、编号替换掉,在第一个冒号或「——」处截断。纯函数。
按 key 计数,显示最近一条;点开是该类的全部条目。

### 3.5 LLM 来源

**能用数据证明的不推断**:

- **声音描述 = 确证**:视频提示词里逐字写着「<角色>的声音:<声音描述>」(`planner.plan_video`)。
  某次批准的声音描述 LLM 运行的输出原文出现在任务提示词里 → 标「确证」
- 其余按**时间推断**,只取任务**创建之前**批准的(驳回 / 失败的不算),每类 LLM 任务各取最近一条,标「按时间推断」:
  - 段落节点:所属集的分镜拆解、剧本,所属剧的大纲
  - 角色 / 场景 / 道具节点:自己的反推描述、声音描述
- **不用「当前的绑定」去推断**:段落绑哪些角色 / 场景可以事后改。参考图节点在倒查树里各自出现,各显示自己的 LLM 来源

### 3.6 sha256 与安全

- sha256 按「路径 + 修改时间 + 大小」在内存里缓存:整集倒查要算十几段视频(每段几十 MB),每次现算要几秒;文件变了三者跟着变,缓存自然失效
- 倒查页的 `path` 沿用 `/media` 的规矩:跳出素材根的路径一律 404;任务 / 导出编号不存在 → 404 并写明原因

### 3.7 原始流水

逐行流式读整个 `worker.log`(不整体载入),按时间段与前缀过滤,**最多显示 500 条匹配**,超出时写明「还有 N 条,缩小时间段」。
不只读最后若干行 —— 那样更早的时间段永远筛不到。

### 3.8 边界

留痕页只覆盖**控制台与 worker 做过的事**。验收脚本自己的失败(例如 2026-10-09 第一次第 4 层:没交任何任务就因隧道未通退出)
不进库,只在验收报告与 `4_e2e.log` 里 —— 看验收报告,不在这里看。

## 四、顺带修的现有缺陷:LLM 运行卡在「运行中」

控制台被关掉或被系统回收时,正在跑的 LLM 运行会永远停在 `running`(导出有 `export.fail_stale`,LLM 运行没有)。
留痕页上它只有「发起」、没有结尾,失败归类也统计不到。

修法照搬导出:`runs.fail_stale(store)` 把 `running` 的标为失败,原因「控制台重启时仍在运行」;`runtime` 启动时调用并记一行日志。
**这是本功能唯一的写库操作**,其余一律只读。

## 五、出错处理

- 产物路径没有生成记录 → 照常显示,标「人工提供或导入的素材」,不 500
- 文件不在本机 → 节点标灰,树照样往上追(task 表里有参考路径)
- 流水文件不存在 → 写「还没有流水」
- 筛选结果为空 → 写明「没有符合条件的事件」,不留空白

### 6.2 Playwright 有头自测

- 登记「留痕」面板。**面板判据看结构**(筛选栏与时间线容器渲染出来):自测先遍历全部面板、后跑操作链,
  遍历时演示数据里还一条任务都没有 —— 空的时候页面必须明确写「还没有失败」「没有符合条件的事件」,不能是空白
- 新增 3 条操作链(都排在能提供数据的链路之后):
  1. 视频面板点「溯源」→ 倒查页,树里看得到首帧缩略图、能点进下一层(排在「生成视频」之后)
  2. 生成记录点一条 → 任务详情,参数与流水行都在
  3. 留痕面板按「失败」筛选 → 时间线只剩失败事件、失败归类里有那次反推描述(排在「从图反推描述」失败之后)
