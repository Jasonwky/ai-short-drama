# ComfyUI 工作流编辑 · 设计

- **日期**:2026-10-08
- **需求**(用户 2026-10-03 / 10-08):把 ComfyUI 的节点编辑界面嵌进控制台,**本机改好再提交到云机**;**云机关着也能改**;
  改完的工作流既能**存成模板预设**(之后新规划的任务都按它拼),也能**对某一条任务改参重跑**
- **依据**:`spike-results/2026-10-08-ComfyUI前端本机离线编辑实测.md`(前端离线可跑、8 个接口垫片、API 格式无损往返、子路径可挂、GPL-3.0)
- **选定方案 A**:控制台在本机提供 ComfyUI 前端 + 轻量后端垫片;所有提交走控制台任务表

---

## 一、总原则

**画布里随便改,「提交 / 保存」那一刻由代码把关。** 画布改出来的工作流和 LLM 输出一样,是要被审的输入:
模型白名单、画幅、帧数、单一输出、控制台字段锁定、从工作流提取溯源字段 —— 不过就拒绝并逐条写明原因,不建任务、不存预设。
画布里的「运行」不直接打云机,**一切提交都经任务表**,溯源不断。

## 二、整体结构

### 2.1 前端托管

- 控制台在 `/comfy/` 下提供 ComfyUI 前端(与控制台同源),编辑页用 iframe 嵌入。
  实测:挂在子路径下时所有接口都打到 `/comfy/api/...`、`/comfy/ws`,不与控制台自己的 `/api/...` 撞车;
  只有两个图标文件仍请求根路径 `/assets/...` —— 控制台要接住(否则 404 进有头自测的报错)
- 前端包版本钉成云机要求的版本(当前 `comfyui-frontend-package==1.51.9`),首次使用时下载到 gitignore 的 `thirdparty/comfyui-frontend/<版本>/`。
  **GPL-3.0,不进仓库**;只在本机使用(若将来把控制台打包给别人,要重新评估)
- 没下载:编辑入口报 400,写明下载命令

### 2.2 轻量后端垫片(`/comfy/api/*`)

| 接口 | 处理 |
|---|---|
| `users` `features` `system_stats` `extensions` `embeddings` `i18n` | 固定回答(实测的最小集) |
| `object_info` | 本机缓存(§2.3) |
| `settings`(GET / `POST settings/<键>`) | 存本机文件;**下发时强制关掉「恢复上次打开的工作流」**(配合 §四 #9 的编辑令牌) |
| `userdata/<文件名>` | 存本机白名单目录;**文件名防路径穿越** |
| `ws` | 给一个空连接(免得前端不停重连刷报错) |
| `prompt`(画布里点「运行」)、`upload/image`(画布里上传图) | **一律拒绝**,提示「回控制台提交 / 去资产面板上传」 |
| 其余(`jobs`、`workflow_templates` 等) | 空结果 |

### 2.3 节点清单缓存

- 文件 `<data_root>/comfy_cache/object_info.json` + 元数据(抓取时间、来源云机、云机要求的前端版本、sha256);不进库
- 刷新:主机面板「刷新节点清单」;worker 发现云机连通且缓存超过一天时自动刷一次
- 编辑页顶部常驻「节点清单:<时间> 抓自 <云机>,离线中 / 在线」
- 从没抓过:编辑入口报「先开云机刷新一次节点清单」
- 前端版本 ≠ 云机要求的版本:编辑时提示;**提交时若云机在线则硬拦**

### 2.4 两种用法共用一个编辑页

编辑页 = 上方控制台操作栏(写明「正在改什么」+「提交为新版本 / 保存为预设」)+ 下方 ComfyUI 画布。
控制台经同源 iframe 调 `app.loadApiJson` 载入、`app.graphToPrompt().output` 导出(实测往返无损,§2.5)。

- **改某一条任务(改参重跑)**:任务历史每个版本有「在 ComfyUI 中编辑」。打开的是**这条任务当时实际提交的工作流**(§五,dispatch 时存下);
  「提交为新版本」= 同一目标(首帧 / 尾帧 / 视频 / 四视图 / 资产图)的一条新任务,与旧版并列在历史里可挑(不自动替换当前版)
- **改模板(模板预设)**:§三

### 2.5 往返的已知差异

载入再导出时,前端会给我们模板**没写**的可选输入补上默认值(实测 H3:`CreateVideo.color_space = sRGB`、`SaveVideo` 的 `format.codec = auto`),
语义不变。**锁定比对只看归控制台的字段**,这些默认值不会被误判成「改了」。

## 三、模板预设

### 3.1 分类

首帧 / 尾帧 / 四视图(Qwen 快档)、资产图(Qwen 标准档)、视频(H3)。
现在 Qwen 的快档 / 标准档靠 `preset` 参数切步数与 CFG —— **改成各是一个独立模板**,免得「画布里改了步数」和「快档」互相覆盖。

### 3.2 哪些字段归控制台

每类模板一张表(代码里固定):提示词、参考图节点、种子、宽高 / 帧数、锚点节点、输出文件名前缀。
模板编辑时看得到,但保存时忽略,用时由控制台填。

### 3.3 保存:把改动提取成三类

打开模板编辑时,用一个「标准例子」(如 2 张参考图、1 个锚点)拼出完整工作流放进画布。保存时代码对比「标准例子的拼法」与「改后的画布」,提取:

1. **改了的参数**:不归控制台的「节点.参数 → 新值」(含改了连线的输入)
2. **新加的节点**及其连线:编号统一改成 `u1`、`u2`……(避开控制台动态生成的编号,锚点用 40 起)
3. **删掉的节点**(删了归控制台的节点 → 拒绝,提示「这个节点归控制台,不能删」)

### 3.4 使用:叠加

控制台照常按实际情况拼(几张参考图、几个锚点)→ 按三类改动叠上去 → 过 §四 的提交把关。

### 3.5 保存前把关(两态)

- 确认页列出与内置模板的差异(如「采样器 res_multistep → euler;新增 LoraLoaderModelOnly(强度 0.8);步数 20 → 30」)
- 用典型情况(1–3 张参考图 × 0–2 个锚点)各试拼一次,**任一种拼不出或过不了 §四 把关 → 拒绝保存**,写明哪种情况、为什么
- 确认后才落盘

### 3.6 版本

- 预设不可改、不可删(触发器);再改 = 新版本,记「从哪版改来」
- 每类一个「当前」指针(空 = 内置);切换当前也先确认
- 任务参数记**预设版本号 + 预设改动内容的副本**(§五):任务自带全部信息,离开本库(如工程包导入)也能复现

## 四、提交把关(改参重跑与预设试拼共用)

| # | 把关 | 不过时 |
|---|---|---|
| 1 | **模型白名单**:工作流里所有模型文件都在声明表里(文件名、用途、**许可证结论**);不在表里的模型(例:共用云机上的 `flux1-dev`,非商用)拒绝 | 「模型 X 没有登记许可证」 |
| 2 | **画幅**:宽高 = 剧的画幅对应尺寸 | 写明期望与实际 |
| 3 | **帧数**:过 `capability` 校验,且与段落时长一致 | 写明期望与实际 |
| 4 | **单一输出**:恰好 1 个输出节点,类型与写回字段对得上(首帧 png、视频 mp4) | 列出多余 / 缺少的输出节点 |
| 5 | **控制台字段锁定**(只对改参重跑):提示词、参考图、宽高、帧数与原任务一致 | 「去段落编辑里改」 |
| 6 | **参考图来源**:「加载图像」节点只认素材库里的相对路径(由控制台上传);云机 input 目录里的别的文件拒绝 | 列出不认识的图 |
| 7 | **种子锁定**:角色锁了种子,改参重跑也必须用锁定种子 | 「种子已锁定为 N」 |
| 8 | **提取溯源字段**:任务表的种子 / 提示词 / 参考图由代码**从工作流提取**,不信表单;提取不出(如两个种子节点) | 拒绝,写明歧义 |
| 9 | **编辑令牌**:当前画布标签带本次编辑的令牌,对不上(人在别的标签上改)拒绝 | 「提交的不是本次打开的工作流」 |
| 10 | **前端版本**:云机在线时,本机前端版本须等于云机要求的版本 | 提示升级前端 |
| 11 | **节点清单**:云机在线时用实时清单再核一次,节点与模型都在 | 列出缺的节点 / 模型 |

LoRA 能否叠在底模上照旧由 dispatch 时的 LoRA 预检把关(要 ssh,离线编辑时不做)。

## 五、数据

- 库结构 **v7**:
  - `workflow_preset`:类别、版本号、改动(三类,JSON)、从哪版改来、说明、创建时间;**不可改、不可删**(触发器)
  - `workflow_preset_active`:每类当前版本(空 = 内置)
- **dispatch 时存下实际提交的工作流** `outputs/tasks/<id>/workflow.json` + sha256(§2.4「改参重跑」打开的就是它)。
  老任务没有这个文件 → 按当前代码重建,界面标明「按当前代码重建,可能与当时不同」
- 改参重跑的任务参数:`{"workflow": "custom", "graph": <改后的 API 工作流>, "from_task": <id>, "writes": …, "expect_ext": …}`;
  dispatch 对 custom 工作流:按「加载图像」节点里的相对路径上传并替换成上传名
- 预设任务的参数:原有参数 + `{"preset_id": N, "preset_diff": <副本>}`
- 工程包:导出带上用到的预设;导入时**改写 custom 工作流里「加载图像」节点的路径**(加 `imports/<编号>/` 前缀)
- 估算耗时:从最终工作流读步数与帧数(预设改了步数、改参重跑改了帧数都要反映到确认页)

## 六、界面入口

- 新面板「工作流」(登记进 `REGISTRY`、`selftest.KEY_SELECTOR` 给判据):按类别列预设各版本及其相对内置的差异;「在 ComfyUI 中编辑」「设为当前」;
  顶部节点清单的时间与在线状态
- 首帧 / 尾帧 / 视频 / 四视图 / 资产面板的历史版本:「在 ComfyUI 中编辑」
- 主机面板:「刷新节点清单」
- 模型白名单声明表:在「工作流」面板只读展示(改它要改代码并写明许可证结论)

## 七、失败处理(全部 fail-loud)

前端包没下载 → 400 + 下载命令;节点清单没抓过 → 提示先开云机刷新;前端版本不一致 → 编辑提示、在线提交硬拦;
§四 任一把关不过 → 拒绝并逐条列原因;画布里「运行」/ 上传 → 垫片拒绝并提示回控制台。

## 八、测试

- **单测**:叠加合并(改参 / 加节点 / 删节点 / 删控制台节点被拦 / 动态槽位下的连线);§四 每条把关;从工作流提取溯源字段;
  垫片接口(含路径穿越);v7 迁移;预设不可改;工程包导入改写工作流路径;估算读工作流步数
  —— 用**真实节点清单的瘦身版**作测试数据(只保留会用到的节点)
- **Playwright 有头自测**:新面板 + 两条链路:
  ① 打开编辑页 → 在 iframe 里改种子 → 提交为新版本 → 历史出现新任务;
  ② 改模板(插一个 LoRA)→ 确认页列出差异 → 保存 → 设为当前。
  自测需要前端包与瘦身节点清单:前端包没下载 → **判失败,不跳过**
- **真云机整链**(验收第 4 层):加一步「用一个非内置预设出一张首帧」,验证叠出来的工作流云机真能跑
