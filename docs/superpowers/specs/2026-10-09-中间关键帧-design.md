# 中间关键帧 · 设计

- **日期**:2026-10-09
- **需求**(用户 2026-10-09):段落里加中间关键帧,用途**控制动作过程**与**段内切镜**两个都要;第一版两个都做,切镜**标明限制**;
  出片后要能看到「关键帧图 vs 视频那一帧的实际画面」(用户:「要」)
- **依据**:`spike-results/2026-10-09-中间关键帧锚定实测.md`(3 条 8 秒片,单一变量)
  - 关键帧钉得中(第 96 帧差 8.7–9.9,对照 54–65)
  - 同景别 → 连续动作走过去;不同景别 → 硬切过去,但切点**提前**(第 72 帧),之后保持到关键帧
  - 钉中后 1–4 帧内常再切;说话特写的切点(124–126)不受关键帧影响;H3 本来就会自发切镜
  - 同素材同种子逐帧复现
- **能承诺的**:「**第 N 秒的画面是这张图**」。**不承诺**「在第 N 秒切镜」

---

## 一、数据与生成

### 1.1 关键帧是叠加项,不是新参考模式

首帧 / 尾帧 / 首尾帧三种参考模式都可以**再叠加 0 或 1 张关键帧**。实测它就是多串一个锚点,与首尾锚定互不相干;
做成新模式要多出 3 种组合,界面与规划都膨胀。

### 1.2 库结构 v9:段落表加 3 列

| 列 | 含义 |
|---|---|
| `key_time_sec REAL` | 关键帧在第几秒;**空 = 不用关键帧** |
| `key_image_prompt TEXT NOT NULL DEFAULT ''` | 关键帧图的提示词(`@角色` 写法同首帧) |
| `key_frame_path TEXT` | 当前用的那版关键帧图 |

`repo` 字段白名单加这 3 列;分镜 LLM 不产出它们(默认空,现有 schema 与判卷不动)。

### 1.3 出图

与尾帧同一条路(Qwen 快档、同画幅、同一个「首帧 / 尾帧」模板预设),提示词换成关键帧的。
**检查函数单独写** `key_frame_problems`:现有 `_plan_frame` 靠参考模式判断要不要这一帧(`FRAMES[field] = (适用模式, 提示词字段, 名称)`),
关键帧与参考模式无关,看的是 `key_time_sec` 设没设;拼提示词 / 工作流的部分复用。历史版本可挑;增量补全多一类「关键帧」(估时按图片单张)。

### 1.4 出视频

`plan_video` 在参考模式原有的锚点之后再加 `(关键帧图, 帧号)`:
**帧号 = round(秒 × `MINIMAX_H3.fps`)**,校验按**实际帧数** `MINIMAX_H3.frames_for(时长)`(时长会吸附到 17k+5 帧网格),不写死 24。
关键帧图只当锚点、不占参考图槽(3 个);它在任务的 `refs` 里,溯源链 / 留痕倒查 / 导出「溯源成立」检查自动覆盖。
**没设关键帧时生成的工作流与现在逐字节一致**(单测守着,防回归)。

### 1.5 readiness(硬校验,不过不能出视频)

- 时刻在 **0.5 秒 ~ 段落时长 − 0.5 秒**;换算出的帧号**不与首帧(第 0 帧)/ 尾帧(最后一帧)锚点重合**
- 设了时刻就必须有关键帧提示词与关键帧图
- 段落时长改短、关键帧落到片外 → 直接报出来
- 「首尾帧 + 关键帧」三个锚点同时用:**挂警告「此组合未经真机验证」**(实测只做了首帧 + 关键帧)

### 1.6 失效传播

| 改了什么 | 作废什么 | 实现 |
|---|---|---|
| 只改关键帧**时刻** | **只作废本段视频**(关键帧图仍有效) | `storyboard.save` 加分支:只有 `key_time_sec` 变了 → `invalidation.one_video` |
| 改关键帧**提示词**(或其它段落文字) | 与现有一致:`segment_prompt` 事件(首帧 / 尾帧 / **关键帧** / 视频) | 现状不变,只是作废范围包含关键帧 |
| 换角色 / 场景 / 道具的参考图 | 绑定段落的参考帧(**含关键帧**)与视频 | `invalidation._FRAME_FIELDS` 与 `apply` 加 `key_frame_path` —— 漏了的话换了角色正面图,旧关键帧图还会被钉进视频 |
| 挑一版关键帧图 | 只作废本段视频 | `versions._FRAME_FIELDS` 加 `key_frame_path` |

工程包导出 / 导入:关键帧图路径与首尾帧一样改写(`bundle` 按列名)。

### 1.7 估时

实测多一个锚点每步约 +3%(74.4 vs 72.3 s/步),**估时不变**,这里写明。

## 二、界面

1. **编辑段落页**「中间关键帧(可选)」:时刻(秒,步长 0.1,留空 = 不用,旁边显示可填范围与本段实际帧数)、关键帧图提示词;
   一条**时间轴示意**:首帧锚点 / 关键帧 / 尾帧锚点各落在第几帧
2. **参考帧面板**每段多一张「关键帧卡」:当前图、提示词、时刻、「生成关键帧」+ 种子、生成记录(复用历史组件,带任务号与「溯源」);
   没设关键帧时写「没设关键帧(在编辑段落里设)」;「补全本集缺的关键帧」先出确认页
3. **视频面板**:readiness 多「关键帧(第 X 秒)已就绪」;首尾帧 + 关键帧挂未验证警告。
   **出片后的对比(用数据审)**:每段并排显示「这条视频钉的关键帧图 vs 视频第 N 帧的实际画面」+ 差值
   - 图与帧号**从产出这条视频的任务参数 `anchors` 读**(不可变),**不是**当前的关键帧图 —— 出片后换过关键帧图 / 改过时刻的,
     多写一行「关键帧之后换过,视频还没重出」
   - 量法**沿用调研**:两边都直接缩到 72×128 灰度、平均绝对差(调研「约 10 = 钉中、对照 50 以上」就是这么量的)。
     注:AddGuide 实际是按视频比例中心裁切后缩放,两种宽高比差约 2%;为了参照数可直接用,**不换口径**
   - 抽帧在本机用 ffmpeg(确定性),结果按「视频 sha256(`provenance.cached_sha256`)+ 帧号」缓存
   - 视频取不到那一帧(如自测假片只有 24 帧)→ 写「视频只有 N 帧,取不到第 M 帧」,不 500
4. **限制说明**(关键帧卡与编辑页上,原文):
   > 保证**第 N 秒的画面是这张图**(实测钉中精度与首帧锚定相当)。
   > · 关键帧与当前镜头**景别相同** → 人物会**连续动作**走到这个姿态;
   > · **景别不同**(如中景 → 特写)→ 会**硬切**过去,但切点通常**提前**(实测提前 1 秒),之后保持到第 N 秒;
   > · 钉中后 1–4 帧内常**再切一次**,**之后的内容不受控**;
   > · **说话特写在哪儿切由台词决定**,关键帧改不了。
   > 依据:spike-results/2026-10-09-中间关键帧锚定实测.md(每种 1 个样本)

## 三、不做(都记为待测)

一段多张关键帧;首帧作为 Qwen 出关键帧的参考图(实测 C 面部与首帧有出入,可能缓解);片段锚定;音频锚定;
关键帧位置对切点的影响(第 60 / 130 帧);关键帧 + 尾帧能否约束后半段。

## 四、测试与验收

### 4.1 单测(确定性,不要云机)

- `key_frame_problems`:没设 / 越界 / 与首尾锚点同帧 / 缺提示词 / 缺图
- `plan_video`:关键帧锚点追加、帧号按 `frames_for` 与 `fps`;**没设关键帧时工作流逐字节不变**
- 失效:只改时刻 → 只视频;改提示词 → 同尾帧;换角色正面图 → 关键帧图作废;挑关键帧版本 → 只视频
- 补全关键帧;工程包路径改写;库结构 v8 → v9
- 对比:本机 ffmpeg 现生成的样片 + 图 → 差值(量法与调研一致);按 sha256 + 帧号缓存;取不到帧如实报;
  图与帧号取自视频任务的 `anchors`、出片后换过关键帧时提示「换过」

### 4.2 有头自测(Playwright,一律有头)

- 演示段落设关键帧 **0.5 秒**(第 12 帧,假片只有 24 帧)
- 新链路:①编辑段落设时刻与提示词 → 参考帧面板「生成关键帧」→ 关键帧卡出现图;
  ②生成视频 → 视频面板出现「关键帧 vs 第 N 帧」并排与差值(假片是测试图样,差值大;验的是**对比真渲染出来了**)

### 4.3 真云机(第 4 层整链)

- 整链加一张关键帧:**调研 B 的提示词与时刻**(转身背对镜头,第 4 秒),同景别
- 判据(用数据):视频第 N 帧与关键帧图的差 **< 20**(调研 8.7–9.9,对照 54–65)
- 若规划器展开出的 Qwen 提示词与调研一字不差,这条整链应**逐帧复现**调研 B(差值 9.9)—— 顺带验复现;
  对不上不算失败,只是少一个对照
- 代价:只多 1 张关键帧图(约 30 秒)、视频每步慢约 3%;整链出片与以往基准不同,以后不能再拿它对「同种子复现原片」
