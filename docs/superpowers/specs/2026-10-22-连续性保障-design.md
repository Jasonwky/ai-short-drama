# 连续性保障(P16)设计:切镜计数 · 看片确认 · 场景陈设表 · 场记表 · 视觉抽检

- **日期**:2026-10-22;**用户定**:方案五项「都做」(`spike-results/2026-10-22-内容与镜头不违和的保障方案.md`)
- **目标**:三道防线 —— 生成前把状态写清(场记表、陈设表)、生成后自动抓(切镜计数、视觉抽检)、人终审(看片确认)
- **非目标**:让 H3 不自己切镜(实测做不到);任何检测当成「保证不穿帮」

## 标定先行(2026-10-22,`tmp/seam/feat.py`,实战库只读)

| 量 | 结果 | 用法 |
|---|---|---|
| 段内相邻帧差(72×128 灰度,平均绝对差),25 条实战片 4435 对 | > 30 的 45 对,几乎都是单帧尖峰(硬切);20–30 是连续多帧的快动作(转身);25–30 之间只有 3 对 | **切镜 = 帧差 > 30,连续几帧合并成一次** |
| 段与段接缝(第 N 段末帧 vs 第 N+1 段首帧),第 1 集 8 个接缝 | 灰度差 38–61、色相直方图距离 0.28–0.48 —— 每个接缝本来就是一次剪切,数值大小与「穿帮」无关 | **不做数值判据**;接缝两帧并排给人看,前后状态接不接得上交给场记表 |

## 1. 切镜计数(`tools/cut/cuts.py`)

- `detect(path) -> list[Cut]`,`Cut(frame, sec, diff)`;量法同上,参数 `PARAMS = {"w": 72, "h": 128, "threshold": 30}`。
- 缓存 `<视频>.cuts.json`(`video_sha256` + `params` + 切点),与 `blankscan` 同一套「sha256 + 参数变了就作废」。
- **什么时候算**:视频面板渲染时当场算、按 sha256 缓存(与 `keycheck` 同一做法,一条约 1 秒;首次打开一集多等几秒),
  不往 worker 里加钩子;ffmpeg 失败在卡片上显示原因。
- **显示**:视频卡片「本段自动切镜 N 次:2.04 s、4.58 s」+ 每次切镜后那一帧的缩略图(切镜后正是背景换屋、帽子丢失的高发处)。

## 2. 看片确认(`segment_review` 表,库结构 v13)

- 表:`segment_review(id, segment_id FK CASCADE, video_path, sha256, note, created_at)`,**写下不可改**(触发器),只认那条视频的 sha256 —— 换视频自动失效。照 `blank_override` 的样子。
- 视频卡片底部「看片」区:
  - 上一段末帧 | 本段首帧 并排(接缝);切镜帧缩略图(第 1 项);
  - 场记表(第 4 项)渲染成一句话对照;
  - 按钮「看过,没有穿帮」(备注可空)→ 记一条;已确认显示「已看片确认 · 时间 · 备注」。
- **导出**:`readiness` 列出「段落 N 还没看片确认」→ **拦导出**;`begin` 把每段确认快照进 `inputs_json`,溯源报告列「看片确认」。
- 自测、验收里的导出流程要先点确认(selftest 增一条链路)。

## 3. 场景陈设表(scene 加两列,库结构 v13)

- `scene.purpose`:用途枚举 `卧房 / 厅堂 / 书房 / 庭院 / 街市 / 野外 / 其他`(可空 = 没填)
- `scene.furnishings`:固定陈设,顿号或逗号分隔的自由文本(如「雕花床榻、屏风、梳妆台」)
- 资产面板场景卡片可编辑两项(写回 `repo` 白名单)
- **分镜判卷**:代码里有一张通用陈设词表(床、床榻、屏风、梳妆台、书案、案几、香炉、灶台、秋千、龙椅、桌、椅、柜……);
  首帧提示词里出现词表里的词,而本段场景填了陈设、清单里没有它 → 打回「@场景 里没有 X(陈设:…)」。场景没填陈设就不查。
  分镜 user_message 里把每个场景的用途与陈设写给 LLM。
- 编剧的「厅堂里写到床」保留(编剧阶段还没有场景资产);分镜阶段今天加的「躺姿」「朝向」字面判卷由场记表取代(见下)。

## 4. 场记表(`segment.blocking_json`,库结构 v13)

- **分镜 LLM 多交一份结构化状态**,每段每个绑定角色一项(闭集):
  - `pose`:`站 / 坐 / 跪 / 仰躺 / 侧躺 / 趴 / 走`
  - `facing`:本段其他角色名之一 / `镜头` / `侧对镜头` / `背对镜头`
  - `side`:`左 / 中 / 右`(画面里的位置)
  - `holding`:本段道具之一 / `无`
- **首帧提示词由代码拼**:在 LLM 写的首帧提示词后追加「@沈玉瑶 跪着,面朝@萧珩,在画面左侧;@萧珩 坐着,……」;
  姿态词由代码给(仰躺 → 「仰面平躺,全身在床内」),LLM 不写这部分 —— 不会漏。拼在 `planner._plan_image` 展开 @ 之前。
- **对表判卷**(相邻两段同场景时):
  - 姿态变了,前一段描述里要有对应动作(→跪:跪 / 跪下;→站:起身 / 站起;→坐:坐下 / 坐起;→躺:躺下 / 倒)→ 否则打回「没交代就从跪变站」
  - 同一道具同一段在两人手里 → 打回
  - 左右站位对调(两人在相邻段 side 互换)→ **只提示**(越轴没有真片证据,先不打回)
- 取代今天加的 `_INTERACT/_FACING`、`_LYING/_POSTURE` 字面判卷(由表保证写了)。
- 分镜面板段落编辑页可改场记表(下拉框),改了即写回;已出的首帧不自动重出。
- 老段落 `blocking_json` 为空 = 不拼、不对表(兼容)。

## 5. 视觉抽检(LLM 任务 `vision_check`)

- 输入:本段首帧 + 每次切镜后那一帧(印校验数字,同 `describe`),加本段场记表;
- 输出(闭集):每帧每个角色 `看得见 是/否/看不出`、`pose` 同上枚举 + `看不出`、`facing` 同上 + `看不出`;
- 代码比对场记表,不一致列在视频卡片「抽检提示(模型判断,仅供看片参考)」,**不拦导出**(模型判模型,不当闸门)。
- 走 `service.TASKS` 登记(视觉模型 `VISION_MODEL`),`apply` 不写回任何字段;结果进 `llm_run` 留痕。
- 契约测试:用今天用户截图里的第 7 段那帧(背对求饶)当正例 —— **SynScale 恢复后才能跑**。

## 验收

- 单测:切镜(合成片:两段不同纯色拼接 = 1 次;渐变 = 0 次)、看片确认触发器 / 失效 / 拦导出、陈设判卷、场记拼提示词与对表判卷、抽检比对。
- Playwright 有头全面自测:新增链路「视频卡片显示切镜 → 看片确认 → 导出检查不再列」「场记表改姿态」「场景填陈设」。
