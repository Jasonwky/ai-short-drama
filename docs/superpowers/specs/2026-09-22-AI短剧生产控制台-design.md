# AI 短剧生产控制台 —— 设计

- **日期**:2026-09-22
- **状态**:🔴 **设计已定,闸门 0 未跑**。闸门 0 不过,本设计不成立。
- **调研依据**:`docs/superpowers/spike-results/2026-09-22-*.md` 共 6 份

## 一、这是什么

**单人可操作的 AI 短剧生产控制台。** 输入小说 / 梗概 / 自带剧本,输出**可上架**的成片
(含合规标识与溯源材料)。

> 「可上架」是刻意选的词,不是「能生成视频」。
> 调研显示能不能上架卡在**合规与溯源**,不卡在生成。

| 决策 | 结论 |
|---|---|
| 入口 | 小说改编 / 梗概生成 / 自带剧本,**三者都要**,汇到同一份结构化剧本 |
| 算力 | 云端 AutoDL GPU + ComfyUI,SSH 隧道由控制面自建 |
| 视频 | **MiniMax H3 (ref2va)** —— 视频与音频联合生成 |
| 图片 | **Qwen-Image-Edit-2511**(Apache-2.0)+ Multiple-Angles LoRA |
| 字幕 | **Qwen3-ForcedAligner-0.6B**(Apache-2.0)强制对齐 |
| 形态 | 列表分步 + 深度环节面板 |
| 产能目标 | 先做通**单集**,架构预留多机不实现 |
| 市场 | 🔴 **仅国内**(见 §三许可证约束) |

**非目标**:不做真人素材导入(留口子)· 不做多机调度(留数据模型)· 不做跨剧素材库(留字段)
· 不做多租户。

## 二、三条硬约束决定架构

| 约束 | 依据 | 推出什么 |
|---|---|---|
| **单集约 5–8 小时**(20 步,待 0-4 实测后校准) | 闸门 0 实测:8 秒片 20 步 **44.4 s/it ≈ 14.8 分钟/条**;加速档目前不可用(见 §6.2)。用户决定 2026-09-23:**先接受 20 步** | 队列必须**能过夜跑、断点续跑、只重跑受影响部分** |
| **图与视频模型抢显存** | H3 实测 23/23GB;Qwen fp8 + 编码器 ≈28.5GB | 调度**按模型分组**,不逐镜交替。⚠️ 显存容量是**机器的声明属性**,升级后此约束自动放宽 |
| **溯源留痕是上架前提** | 广电备案要「AI 工具溯源材料」 | 每个任务**从创建那一刻**存全量参数,不可变,可导出 |

## 四、分层

```
控制面(本机)                         执行面(云机,无状态可丢弃)
┌────────────────────────┐        ┌──────────────────────────┐
│ Web 控制台              │        │ ComfyUI :8188            │
│ ├ store   唯一真相源    │──隧道──▶│ ├ MiniMax H3 (ref2va)    │
│ ├ worker  常驻轮询      │ ssh -L │ └ Qwen-Image-Edit-2511   │
│ ├ tunnel  自建 SSH 隧道 │        └──────────────────────────┘
│ ├ compose 字幕/标识/拼接 │
│ └ 产物库 + 溯源日志     │
└────────────────────────┘
```

**字幕对齐放控制面**:`Qwen3-ForcedAligner-0.6B` 只有 0.6B,而成片已经落在控制面本地,
放云机反而要把音轨传回去 —— 就近处理更简单,也不跟两个大模型抢显存。

**隧道纪律**(照 ai-ecommerce 已踩坑的做法):
- 控制面**自己起** `ssh -N -L`(AutoDL 每次重启换端口)
- **两层判活**:进程活着 ≠ 转发通;第二层用 `queue_counts()`
- **接管**已存在的隧道(控制面重启后 `_procs` 为空但旧 ssh 还占着端口)
- 退避 5s → 封顶 300s;**私钥不入库、不进日志、不进 git**

## 五、数据模型

### 5.1 主干三层 + 大纲

```
drama(剧) ──▶ outline(分集大纲) ──▶ episode(集) ──▶ segment(分镜段落)
```

| 表 | 关键字段 |
|---|---|
| `drama` | `aspect_ratio`(**建后不可改**)· `style` · `total_episodes` |
| `episode` | `source_text`(原始)· `script`(改写后)—— **分存可回溯** · `source_type`(预留真人素材枚举) |
| `segment` | `scene_id` · `duration` · 景别/角度/运镜 · `description`(【镜头N】逐子镜头)· `result` · `atmosphere` · **四路提示词**(图/视频/BGM/音效)· `first_frame` / `last_frame` · `reference_mode` · `layout` · `video_path` · `subtitle_path` |

**两个关键字段**:

- **`reference_mode`** ∈ `first / last / key / first_last / first_last_key / text_only / anchors`
 —— 每镜可选。转场空镜走 `text_only` 不出图。`anchors` 对应 `MiniMaxH3AddGuide` 的任意帧锚定(🟡 待验)。
- **`layout`(空间合同)** —— 画面布局与人物站位的文字描述,**首帧与尾帧提示词共用这一份**,
 强制两端构图一致。治「站位漂移」。

### 5.2 资产层:挂剧级

| 资产 | 参考形态 | 关键字段 |
|---|---|---|
| `character` | **四视图**(正脸/正身/侧身/背身) | `appearance` · `styling` · `final_prompt` · `seed` · `turnaround_images` · **`voice_ref`(音色参考音频)** · `library_id`(预留) |
| `scene` | **固定视角无人空镜** | `location` · `time` · `lighting` · `final_prompt` · `episode_id`(可空,按集收窄)· `library_id` |
| `prop` | **白底单品静物** | `name` · `description` · `final_prompt` · `library_id` |

> **角色 = 形象 + 音色。** `voice_ref` 送进 H3 的 `ref_audios` 槽位锁音色,与四视图送进
> `ref_images` 完全同构。这是音色一致性的工程做法,不是指望模型天然一致。
>
> **场景图必须无人**:不能出现任何人,含背影、剪影、倒影、照片里的人。

绑定:`segment_character` / `segment_prop` 多对多;**`segment.scene_id` 一对一**
(因为「段落不跨场景」是硬规则,数据模型直接编码)。

### 5.3 任务与溯源

`task` 统一承载图/视频/对齐三类任务:

```
kind · target(segment/character/scene/prop) · model + 权重哈希 · params(步数/CFG/分辨率/帧数/ref_image_size)
· seed · 完整提示词 · 参考素材清单 · host_id · external_id · result_path + 产物哈希
· state · error · created/started/finished
```

🔴 **task 不可变**,重跑生成新记录不覆盖 —— 这同时白送了「历史版本不覆盖,人可以挑」。
🔴 **所有长任务一律进这张表**,不给自己留内存态的口子。

`host` 表:`ssh_host/port/user/key_ref` · `local_port` · `remote_comfy_port` · **`vram_gb`** · `label`
—— 显存是声明属性,调度策略由它推导。

## 六、关键机制

### 6.1 提示词引用参考素材的语法

**「模型不会自己知道哪张图管什么」**,引用必须显式。

```
人写 / LLM 生成:  @林小雨 推开 @老宅大门,回头看了一眼
        ↓ 按该 segment 绑定资产的顺序建立 名字 → 序号 映射
提交生成时展开:   <Picture 1> 为林小雨…  <Picture 2> 为老宅大门…
                  正文引用 <Picture 1> / <Picture 2>
```

- **人看到的永远是名字**,机器拿到的是带编号的标签
- `video_prompt` 第一行是**信息头**:列出本镜出场的人物与场景
- H3 的标签按类型各自 1 起编号:`<Picture i>` / `<Video k>` / `<Audio j>`,
 排列顺序固定为 **图 → 视频(其音轨的 `<Audio j>` 紧接其前)→ 独立音频**

🔴 **ComfyUI 节点对标签零校验**,写错编号会静默错位。**双向断言必须我们自己做**:
①提示词里每个标签都有对应素材 ②每个接入的素材都被引用过。任一不满足 readiness 不通过。

> **这不是假想风险**:云机上 ai-ecommerce 一个**已经出片**的工作流里,提示词写着
> 「…and `<Audio 1>` exactly as it is」,而整个工作流没有任何音频输入,`ref_audios` 为空。
> ComfyUI 照样跑完不报错。

### 🔴 画幅由 latent 决定,不由提示词决定

闸门 0-3 实测:合成首帧时 latent 取自参考图 1(横向四视图拼图),提示词写 "vertical 9:16" 仍出 2.3:1 横屏。
**合成首帧必须用目标尺寸的空 latent**(`EmptySD3LatentImage`,尺寸来自 drama 画幅);只有改背景、出四视图这类「保持原图」的编辑才让 latent 跟随参考图 1。

### 🔴 参考素材的槽位取舍(Qwen-Image-Edit 只有 3 槽)

H3 有 9 个图槽,但**出首帧图用的是 Qwen-Image-Edit,它只有 `image1/2/3`**。
「角色四视图 + 场景空镜 + 道具白底」正好占满,**一个镜头出现两个角色就放不下**。

取舍规则(按优先级填槽,超出的降级到文字描述):

```
1. 本镜台词最多的角色(四视图)
2. 场景空镜
3. 第二角色(四视图) —— 有则占掉道具的位置
4. 关键道具(白底单品)
```

超出 3 个的素材**不静默丢弃**,在 readiness 里明确报「道具「玉佩」因槽位不足未作为参考图,
仅以文字描述参与」,由人决定是否调整。

### 6.2 生成参数(H3 ref2va)

| 参数 | 值 | 说明 |
|---|---|---|
| `length` | **124–362 帧**,step 17,24fps | 🔴 **模型训练区间**(=5.2–15.1 秒),不是业务规则。由后端 `Capability` 声明,换模型跟着变 |
| `ref_image_size` | `match` / `max` | 🔴 `max` 用 2048px 短边,**identity fidelity 最好但可能慢几倍**。默认档**待闸门 0 实测定** |
| 参考上限 | H3:图 **9** / 视频 **3** / 音频 **3**;🔴 **Qwen-Image-Edit 只有 3 个图槽**(`image1/2/3`,固定非 Autogrow) | 均已在云机源码核实 |
| `width × height` | **768 × 1344**(竖屏) | 🟢 云机上 ai-ecommerce 的工作流**已真机出片**(`SaveVideo` 前缀 `video/H3_10s_vertical`),跑得通;**画质评价仍待闸门 0** |
| 加速 | 🔴 **当前无可用档** | PDD 8 步 LoRA 与云机的**剪枝版**底模不兼容(`adaln_proj` 输入维 8 vs 2688,50 层打不上);Turbo 4 步已被 ai-ecommerce 实测否决(形象崩坏)。候选:Spectrum(碰共享环境,待用户批准)、未剪枝底模+PDD(需扩盘) |
| LoRA 预检 | `tools/gen/lora_compat.py` | 🔴 **ComfyUI 遇到 LoRA 与底模形状不符只打日志、照样出片**。提交前必须读 safetensors 头核对形状,**任何不符即拒绝**——打了一半的 LoRA 比不打更糟,它会被当成已加速 |
| `vae` / `audio_vae` | **必须接** | 不接的话参考图/音频**只作用于文本编码器**,形同虚设 |

### 6.3 可量化规则 → 代码断言

```
总时长       = 剧本字数 ÷ 500 字/分钟
段落数       ≈ 总时长 ÷ 12 秒, ±20%
段落时长     ∈ Capability 声明的区间(H3: 5.2–15.1 秒)
段落时长下限 = 台词字数 ÷ 4.5 字/秒 + 2 秒表演余量
子镜头数     ∈ [2, 4]
段落不跨场景
参考素材数   ≤ Capability 上限
提示词长度   ≤ Capability 上限
```

🔴 **LLM 拆完由代码判卷,不合格带错误回炉,轮次上限后 fail-loud。**
🔴 **禁止静默默认值填空** —— huobao 的 `duration = LLM给的 || 10` 是反面教材。

### 6.4 readiness:带人话的检查项清单

```
[ {key:'assets_bound',     ok:false, msg:'角色「林小雨」未绑定参考图'},
  {key:'tags_consistent',  ok:false, msg:'提示词引用了 <Picture 3>,但只接入 2 张参考图'},
  {key:'refs_ready',       ok:false, msg:'参考模式 first_last,缺少尾帧'},
  {key:'duration_valid',   ok:false, msg:'台词 68 字需 ≥17.1 秒,当前 12 秒'},
  {key:'prompt_ready',     ok:true,  msg:'四路提示词齐备'},
  {key:'video_model_ready',ok:true,  msg:'MiniMax H3 可用'},
  {key:'host_ready',       ok:false, msg:'云机隧道未连通'} ]
```

**包含外部依赖**(模型配没配、密钥、云机通不通),不只是内容就绪。
界面直接显示「还差什么」,不是一个红叉。

### 6.5 失效传播 + 重跑前报代价

| 改了什么 | 波及 |
|---|---|
| 剧本 / 风格预设 | 整集重来 |
| 角色四视图 / 种子 / **音色** | 所有绑定该角色的 segment 的参考帧 → 视频 |
| 场景空镜 | 该场景下所有 segment |
| `layout`(空间合同) | 该 segment 的**首帧与尾帧** → 视频 |
| 某 segment 提示词 | 只有它自己 |

点重跑先弹「**这会重跑 9 条视频,约 2.2 小时**」,人确认才开跑。

> **诚实说明**:三个开源项目没有一个做了失效传播。不是他们疏漏 ——
> 他们走云 API 一条几十秒到几分钟,我们是十几到三十几分钟,**代价差两个数量级**。

### 6.6 尾帧衔接:从已完成视频抽帧

```
当前 segment 最新 done 的视频(本地文件)
  → ffmpeg 抽最后一帧 → 找 number 更大的下一个 segment → 设为其 first_frame
```

保证**物理连续**,不是"看起来像"。三种前置校验各给可操作错误:
没有可用本地视频 / 没有下一个 segment / ffmpeg 不可用。

### 6.7 字幕:强制对齐,不是 ASR

我们**已知台词文本**(在 `segment.description` 的【镜头N】里),
**也有 H3 生成的音轨** → 这是**强制对齐**问题:

```
台词文本 + 生成视频的音轨
  → Qwen3-ForcedAligner-0.6B (Apache-2.0)
  → 字符级时间轴 → SRT/ASS → ffmpeg 烧录
```

备选 FunASR Paraformer(MIT,原生字符级时间戳)。

> 🔴 **三个开源项目没有一个实现了字幕**(huobao 的 `subtitle_url` 是死字段,
> 但 README 宣称有)。这一环**必须自己设计**。

### 6.8 合规:显式标识 + 隐式元数据

**GB 45438-2025**(强制性国标,2025-09-01 实施)+《人工智能生成合成内容标识办法》。
**我们是"生成合成服务提供者"**,义务是加显式 + 隐式标识。

| 类型 | 要求 |
|---|---|
| **显式** | **视频起始画面** + 播放中**持续显示**的提示文字;须同时含「人工智能」或「AI」+「生成」和/或「合成」;**不得缩小、虚化** |
| **隐式** | 文件元数据五要素:生成合成标签 · 服务提供者 · 内容制作编号 · 传播服务提供者 · 传播编号 |

元数据形态(⚠️ **来自律所解读,非国标原文**):

```json
{ "AIGC": { "Label": "1", "ContentProducer": "<主体名称或编码>", "ProduceID": "<内容编号>" } }
```

**设计要求**:
- `ProduceID` 由我们生成并保证唯一,**与溯源报告的作品编号是同一个 ID**
- 导出时额外提供**无显式标识版本**(隐式标识仍保留)—— 办法允许应用户申请提供
- 🔴 **落地前必须拿 GB 45438-2025 附录 E 原文核对字段**(在线全文不可得)

### 6.9 溯源报告

平台备案要「AI 工具溯源材料」。成片导出时把整集的 `task` 链导成报告:
每个 segment 用了哪个模型、什么参数、什么种子、什么提示词、哪些参考素材、何时在哪台机器生成。

## 七、环节与面板

| # | 面板 | 要给人的东西 |
|---|---|---|
| 1 | **立项** | 画幅(建后不可改)、风格预设(**是数据不是代码**,结构化 prompt 前缀 + `avoid` 项)、集数 |
| 2 | **大纲** | 分集大纲;小说改编时由章节事件生成 |

## 八、🔴 闸门 0:不过就不动工

整条路线目前**零实测**。顺序跑,一道不过就停下重新选型。

| 闸门 | 验什么 | 判据 | 不过怎么办 |
|---|---|---|---|
