# 剧本 / 分镜修改回路(P19-C)设计

- **日期**:2026-10-24
- **用户原话**:「希望每一集的剧本以及分镜都由 AI 出,人工检查每一集,不满意的地方提出修改点由 AI 重新修改,直到满意」
- **用户定**:
  - 拆成三块,顺序 C → B → A:
    - C:修改回路(本文);
    - B:每集自动出剧本 / 分镜;
    - A:原创分集,从立项出骨架,逐幕展开成分集大纲,有问题的集再单集发散;
  - AI 交**逐条替换**,不交整集重写;
  - 自查出的 8 处漏洞全部并入设计。
- **目标**:人用自己的话提修改点,AI 只改被点到的地方,人逐条审,一轮一轮改到满意;没被改到的地方保证一个字不变。
- **非目标**:
  - 不做开放聊天(spec 2026-10-23-剧集脑爆系统 第 5 节);
  - AI 不整集重写:满意的地方会被顺手改掉,只能靠人眼在 diff 里找;
  - 分镜修改不增删、不拆并段落(段号永不复用;结构性改动走现有「重拆分镜」,先报代价、要确认)。

## 0. 共同机制

两个新 LLM 任务都登记在 `service.TASKS`,走 `gate.run_gated`(strict 工具调用、schema 校验、代码判卷、回炉、轮次上限、落 `journal/llm/`),
产物进 `llm_run`,**人在审阅页批准才写回**。人的选择存进已有的 `llm_run.decision_json`,**不改库结构**。

### 0.1 修改意见(人写)

- 一行一条,1–10 条;
- 每条可选:
  - 「针对」:剧本里的一段原文,或分镜的段号列表;
  - 「必须改」:勾上后,AI 不能回答「这条不改」。
- **发起前的确定性预检**(不调 LLM,直接 400 报原因):
  - 「针对」的原文要逐字在剧本里(`verbatim.restore`);「针对」的段号要存在;
  - 新角色(漏洞 6):**自由文本里认人名只能猜,不做**。确定性的做法分两处:
    - 发起页把本剧角色名单列在意见框旁边,写明「要加新角色先去资产里建」;
    - 判卷遇到「说话人不是本剧角色」时,这条问题**不回炉**、直接让本次运行失败,失败原因原样写「X 不是本剧角色,先在资产里建」。
      回炉也改不好,重试只会白烧轮次,同 CLAUDE.md 里 `max_tokens` 不进重试的道理。
      需要 `run_gated` 支持「判卷问题标记为不可回炉」—— 实现时先读 `gate.py`,没有就加一个最小开关。
  - 分镜意见里出现「拆成 / 合并 / 新增一段 / 删掉这段」→ 提示走「重拆分镜」。

### 0.2 AI 的回应结构

```
responses: 每条意见一项(按序号,一条不能少)
  note: 意见序号
  verdict: "改" | "不改"
  reason: 不改时必填;改时写一句用意
  edits / patches: verdict = 改 时至少 1 个
```

### 0.3 共同判卷

- 每条意见恰好一项回应;
- 「改」至少 1 处修改;「不改」必须有理由;**「必须改」的意见不许「不改」**(漏洞 4);
- 带「针对」的意见,修改只能落在针对的范围内(漏洞 5);
- 修改之间不重叠:剧本按行区间比,分镜按「段号 + 字段」比 —— **任意组合都能干净写回**。

### 0.4 批准:按意见整组接受 / 驳回(漏洞 1)

- `decision = {"accept": [意见序号…], "reject": [意见序号…]}`,每条「改」的意见都要表态(`decision_problems` 校验);
- 同一条意见下的修改要么全写回、要么全不写 —— 「删开头 + 把冲突插到最前」这类有依赖的修改不会被拆散;
- 全部驳回 = 合法,什么都不写。

### 0.5 写回后范围审计(漏洞 2)

写回后由代码重算一遍「旧内容只替换接受的那几处」应得的结果,与库里实际比较,**不一致即抛错**(不吞)。

### 0.6 回滚(漏洞 2)

- 每轮写回前的内容就是那次 `llm_run` 的输入(上下文里存着剧本全文 / 各段字段),天然是快照;
- 剧本页、分镜页的修改历史里,每一轮带「回到这一轮之前」:两态(先 diff 预览,确认才写),只回滚这一轮动过的范围;
- **回滚的前提**:现在的内容与「这一轮写回后」一致(之后又改过就拒绝,提示先回滚更晚的轮次)。

### 0.7 多轮

- 每轮一条 `llm_run`,人点一次发一次,不会自己循环;AI 内部重试由 `run_gated` 的轮次上限管;
- 下一轮的输入自动带上**最近一轮被驳回的修改**(「不要再往这个方向改」),它们进输入指纹;
- 审阅页把 AI 回答「不改」的意见单独醒目列出(漏洞 4),下一轮可以把它勾成「必须改」;
- 发起后内容被别处改过:输入指纹对不上,批准被拒,要重跑 —— 现有机制,不另做。

## 1. 剧本修改 `script_revise`(目标是集)

### 1.1 输入
- 本集剧本全文(数据,放在 `<script>` 里)、角色名单、修改意见、上一轮被驳回的修改;
- 前提:本集有剧本。

### 1.2 每处修改 `edit`
- `old`:剧本里逐字的连续整行(一行或多行);
- `new`:替换后的文字,可以为空(删除),也可以多于原文(插入:把锚定行连同新行一起写进 `new`);
- 判卷:
  - `old` 逐字在剧本里(标点宽度不同也认,写回用剧本原文的写法);
  - 只选了半行时自动扩成整行;
  - **整行还不唯一**(「【场景 · 时间】」标题、重复的动作行)→ 打回,要求多带一行上下文(漏洞 8);
  - `new ≠ old`;
  - `new` 里的台词行符合「角色名说：「…」」,说话人是本剧角色。说话人的认法与 `rules.dialogue_lines` 同一口径,复用 `rewrite` 的检查;
  - 全部修改代进去以后,整集还能被分镜正常解析:场景标题格式、台词格式。

### 1.3 审阅页
- 按意见分组,每组显示原文 / 改成并排,外加 AI 的用意;
- 「AI 没改的意见」单独一栏;
- **篇幅提示**(只提示不拦,漏洞 7):
  - 改前 / 改后字数;
  - `rules.expected_segment_range` 推算的段落数区间;
  - 本集已有段落数落在区间外时标黄。

### 1.4 写回与已有分镜
- 按接受的意见替换剧本,做范围审计;
- 本集已有段落时**不删段落、不作废任何已生成的东西**(用户 2026-10-23 原则):
  - 对每处被接受的修改,复用 `rewrite._sync_segment`:台词恰好全在某一个段落里、句数与说话人顺序一致时,把那段描述里的台词逐句换新;
  - 对不上就只改剧本。

### 1.5 剧本与分镜常驻对账(漏洞 3)
- 新纯函数 `rules.script_segment_drift(script, segments, names)`:
  - 剧本里有、段落里没有的台词;
  - 段落里有、剧本里已经没有的台词;
- 剧本页每集、分镜页顶部**每次渲染都算**,有差异就列出来(只提示不拦)。不靠某次批准时弹一次。

## 2. 分镜修改 `storyboard_revise`(目标是集)

### 2.1 输入
- 本集剧本(只读参考)、各段当前字段、资产名单(角色 / 场景 / 道具)、各场景的固定陈设、画幅、修改意见、上一轮被驳回的补丁;
- 前提:本集有段落。

### 2.2 每个补丁 `patch`
- `segment`:段号(闭集 = 本集现有段号);
- `field`:闭集,值的形状按字段定:

| field | 值 | 写回 |
|---|---|---|
| `subshots` | 本段完整的子镜头列表(画面 / 说话人 / 台词)+ `pace` | 代码用 `storyboard.describe` 重拼描述,用 `storyboard.duration` 重算时长 |
| `image_prompt` | 文本 | 原样 |
| `video_prompt` | 文本 | 原样 |
| `blocking` | 场记表(闭集,同 `storyboard` schema) | `blocking_json` |
| `camera` | 景别 / 机位 / 运镜(闭集,`framing`) | `shot_type` / `angle` / `movement` |
| `bindings` | 本段角色、道具(资产闭集;场景不改) | `segment_character` / `segment_prop` |

### 2.3 判卷
- 把补丁代入当前各段,**整集重过分镜的全套判卷**:
  - 台词逐字出自剧本、顺序不变、一句不漏;
  - `rules.check_segment` / `check_episode`;
  - @名字与绑定一致;
  - `furnish`、`blocking`、`framing`;
  - 同场景相邻段姿态衔接(`blocking.transition_problems`)。
- **实现**:把 `storyboard.judge_factory` 里「检查一段」与「整集收尾」的逻辑抽成函数。
  抽出来的函数吃的是「段落视图」(描述文本 + 绑定 + 提示词 + 场记表 + 景别),不吃 LLM 的原始子镜头。
  台词改用 `rules.dialogue_lines(描述)` 取,首次拆分镜与修改两边共用;**首次拆分镜的判卷结果必须不变**,用现有测试守。
- 同一个「段号 + 字段」被两条意见都改了 → 打回(0.3)。

### 2.4 审阅页
- 按意见分组,每个补丁显示「第 N 段 · 字段:旧 → 新」;
- **代价预览**:列出会让哪几段的首帧 / 视频过期、重出估时。复用 `invalidation` 的估算口径与 `gen/estimate`,只算不改。

### 2.5 写回与已生成产物
- **不作废,只标过期**(用户原则,同 `shot_options`):
  - 首帧相关字段(`image_prompt` / `blocking` / `camera` 的景别机位 / `bindings`)改了:
    现有 `frames.frame_stale` 按首帧快照比对,自然提示「当前首帧还是旧方案」,不需要新机制;
  - 视频相关字段(`subshots` / `video_prompt` / `camera` 的运镜 / 时长)改了:
    视频任务参数里的台本快照已经存了描述、提示词、时长,现在只比台词(`rules.stale_lines` / `dropped_lines`);
    新增比对描述 / 视频提示词 / 时长,视频卡片提示「当前视频是按旧分镜出的」。
    旧视频没有快照的,不提示(不知道当时用的什么,不猜)。
- 写回做范围审计:只有接受的「段号 + 字段」变了。

## 3. 面板

- **剧本页**每集:
  - 「提修改意见」:一行一条,每条可展开填「针对」、勾「必须改」;
  - 「让 AI 按这些改」;
  - 修改历史:按轮列出意见 → 接受了哪几条 → 「回到这一轮之前」;
  - 剧本与分镜对账提示。
- **分镜页**每集:同上,「针对」填段号。
- **审阅页**:按意见分组、整组单选「接受 / 驳回」、「AI 没改的意见」一栏、篇幅提示 / 代价预览。

## 4. 测试与验收

- **单测**(FakeLLM 只测确定性路径):
  - 0.1 预检;0.3 共同判卷各分支;
  - 整行扩展与「不唯一」打回;
  - 整组接受的写回与范围审计(含故意篡改触发抛错);
  - 回滚两态与前提;
  - `script_segment_drift`;
  - 分镜补丁代入后的全套判卷;
  - 抽函数后首次拆分镜判卷不变;
  - 视频过期的扩展比对。
- **真 LLM 契约测试**:两个任务各一条,黄金样本用题甲第 1 集,意见里各含一条「必须改」、一条带「针对」。
- **Playwright 有头自测**:剧本页、分镜页各一条链路(假 LLM 出修改 → 审阅页分组渲染 → 假产物不许批准),截图存档;全面自测全绿。

## 5. 不做的与边界

- 不做 AI 主动提修改(那是评审团 `critique`;采纳的评审问题以后可以一键带进修改意见,本期不做);
- 不改场景绑定(换场景等于换段落,走重拆);
- 不自动重出首帧 / 视频:只标过期,人自己点。
