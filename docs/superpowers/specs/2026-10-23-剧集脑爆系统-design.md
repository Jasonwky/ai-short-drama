# 剧集脑爆系统(P17)设计:发散 · 评审团 · 局部改写

- **日期**:2026-10-23
- **用户定**:三种形态都要(多方案发散 + 人挑、多角色评审团、人机对话共创);覆盖立项、大纲、单集剧本、分镜四个环节;方向已认可
- **依据**:`spike-results/2026-10-23-剧集脑爆系统调研.md`
- **目标**:创作阶段多给人几个**真不一样**的选择,并把问题在生成视频前挑出来;人始终拍板
- **非目标**(调研给的理由):
  - agent 之间互相辩论:没有证据比分阶段单 agent 好;
  - LLM 给方案打分、选优、自动采纳:LLM 评委与专家判断不正相关,还偏爱自己写的;
  - 开放式聊天:没法判卷、没法复现;
  - 靠调温度或换模型求多样:证据显示无效。

## 0. 总体

三种形态都是普通的 LLM 任务,登记在 `service.TASKS`,走 `gate.run_gated`(strict 工具调用、schema 校验、代码判卷、回炉、落 `journal/llm/`),产物进 `llm_run`,**人在审阅页批准才写回**。

| 形态 | 产物 | 人做什么 | 写回 |
|---|---|---|---|
| 发散 | N 个方案,每个在代码定死的「维度」上取闭集值 + 相对典型度 0..1 | 挑一个,或逐字段从不同方案里拼(由代码拼,不再问 LLM) | 挑中或拼出的那份 |
| 评审团 | 一个视角的问题清单,每条带逐字原文引用 | 逐条采纳或驳回(必须每条都表态) | 不写回内容;采纳的问题可以一键发起局部改写 |
| 局部改写(= 对话共创) | 针对人选中的一段原文,2–3 个替换候选 | 挑一个 | 只替换那一段 |

**新增的通用机制**:人在批准时做的选择要留痕、可复现。
- `llm_run` 加列 `decision_json`(库结构 v15):批准时写入人的选择,例如 `{"pick": 2}`、`{"assemble": {"title": 0, "hook": 2}}`、`{"adopt": [0, 3], "reject": [1, 2]}`;
- 批准后与 `output_json` 一样不可改(扩展现有触发器);
- `service.approve(..., decision=)` 把它交给模块的 `apply(store, target_id, args, ctx, decision)`;
- 现有任务不需要选择,`decision` 为空,行为不变。

### 共用的纯函数(`tools/llm/diverge.py`)

- `distinct_problems(candidates, dims, min_diff=2)`:任意两个方案在维度上至少差 `min_diff` 个取值,否则判卷打回「方案 2 和 4 只在『题材』上不同」;
- `overlap(candidates, dims) -> float`:两两维度取值相同的比例的平均。面板上 > 0.5 时提示「本批趋同」。这是**用数据审发散**,不是 LLM 自评;
- `assemble(candidates, picks) -> dict`:按人逐字段的选择拼出一份,纯代码;
- 典型度只用来给最高的那个打「套路款」标签,**不排序、不淘汰**。

调研结论「一次出多个 + 各自概率」与「先定维度再强制分化」都落在这里:维度由代码给闭集,LLM 只能在闭集里取值,判卷保证方案之间真的不同。

## 1. 立项:`premise`(目标是剧)

- **输入**:人写的一句话想法(必填)+ 可选约束(题材、受众);
- **维度**(代码定死的闭集,可以在 `diverge.PREMISE_DIMS` 里扩):
  - 题材:古装权谋 / 古装甜宠 / 都市逆袭 / 都市情感 / 悬疑 / 重生复仇 / 家庭伦理 / 其他;
  - 核心爽点:打脸 / 逆袭 / 复仇 / 甜宠 / 身份揭晓 / 智斗;
  - 核心冲突:身份错位 / 利益争夺 / 情感背叛 / 生死危机 / 误会;
  - 开场钩子类型:直接冲突 / 强悬念 / 极致反差。
- **每个方案**:片名、一句话卖点、维度取值、主角(名字、身份标签、反差点)、对手、开场 3 秒钩子(一句画面描述)、典型度。
- **判卷**:
  - 方案数等于人要的数(3–12;2026-10-24 应用户要求从 3–6 放宽,真 LLM 契约 n=12 一轮通过);
  - `distinct_problems`;
  - 片名、卖点过敏感词表(`drama/compliance.py`,词表来自广电「霸总」「爽而有度」管理提示,标出处);
  - 角色名不在本剧已有角色名里重名。
- **写回**:新列 `drama.premise_json`(v15,`repo` 白名单);片名为空时一并写。
- **下游**:大纲、编剧的 user_message 带上立项结果。
- **面板**:立项页加「脑爆立项」区,N 张方案卡并排,「套路款」角标,每个字段一组单选,用来拼。

## 2. 大纲

### 2a. 节拍标注 `beats`(目标是剧,大纲已有之后)

- LLM 逐集标注闭集字段:结尾有没有悬念、反转(无 / 小 / 大)、情绪(压 / 放 / 平)、是不是付费卡点候选。每项带一句**逐字引用**自该集大纲(`verbatim.restore` 核对,防编造)。
- 批准写回新列 `episode.beats_json`(v15)。
- **代码统计**(`tools/drama/pacing.py`,纯函数):
  - 前 10 集结尾悬念覆盖率;
  - 相邻两次反转的间隔集数;
  - 付费卡点集号;
  - 连续「压」的最长集数。
- **阈值**:在 `pacing.THRESHOLDS` 里配,每条标「经验值 + 出处 + 档位」,只收调研里的 A / B 档。
- **只提示不拦**。大纲面板画一条逐集的节拍条(压 / 放 / 反转 / 卡点),命中阈值的标黄。

### 2b. 单集变体 `outline_variants`(目标是集)

- 维度:开场钩子类型、中段反转类型(身份反转 / 立场反转 / 真相揭露 / 无)、结尾悬念类型(危机未解 / 身份待揭 / 新人物登场 / 抉择)。
- N 个变体,每个是该集大纲的完整重写;判卷用 `distinct_problems`;人挑一个写回 `episode.outline`。
- **本集已有剧本时拒绝**(fail-loud,提示先清剧本)—— 不做「大纲改了、剧本悄悄过期」。

## 3. 单集剧本

### 3a. 评审团 `critique`(目标是集,参数 `role`)

- **视角**(闭集,各自一套问题类别):
  - 编剧:动机不足 / 逻辑漏洞 / 台词不自然 / 铺垫过长;
  - 导演:不可拍(竖屏放不下、动作说不清)/ 场景过多 / 节奏拖;
  - 观众:开头不抓人 / 看不懂 / 不爽 / 没有追下去的理由;
  - 制片:场景或角色超预算 / 道具难做;
  - 合规:触碰管理提示 / 真实人物或品牌。
- 一次运行一个视角,人想听几个就发起几个,**按固定顺序、互不可见**(不辩论)。
- **每条问题**:原文引用、类别、严重度(高 / 中 / 低)、改法。
- **判卷**:
  - 引用必须逐字在剧本里(`verbatim.restore`);
  - 类别属于该视角的闭集;
  - 条数 1–8。
- **批准**:`decision = {adopt, reject}`,必须每条都表态才能批准;不写回剧本。
- 面板按视角显示**历史采纳率**(从 `decision_json` 算)。采纳率长期低的视角,说明对这部剧没价值,人可以不再用(调研反证第 2 条)。

### 3b. 局部改写 `rewrite`(目标是集)

- **入口两个**:
  - 剧本页选中一段文字;
  - 评审清单里某条已采纳问题旁边的「按这条改」(自动带上引用和改法)。
- **参数**:原文片段(必须逐字在剧本里)、意图(闭集:加强冲突 / 提前钩子 / 删铺垫 / 换台词风格 / 按评审意见改)、补充说明。
- **LLM**:回 2–3 个替换候选。
- **判卷**:
  - 候选彼此不同、与原文不同;
  - 长度在原文的 0.3–3 倍;
  - 原文里有台词行时,候选保持「角色名:台词」格式,角色名只能是本剧角色。
- **批准**:`decision = {pick}`;`apply` 只替换那一段,替换前再核一次片段仍逐字存在,输入指纹已经守住。
- **本集已有段落时不删段落**(用户 2026-10-23 定:已经生成的要保留,新的是否成为当前视频由人选):
  - 原片段里的台词如果恰好全在某一个段落的描述里、新旧台词句数和说话人顺序一致,就把那个段落描述里的旧台词换成新的;
    别的段落不动。对不上(改的是旁白动作、台词跨段、句数变了)就只改剧本,剧本面板提示「这次改写没对上任何段落」;
  - 段落现有的首帧、视频、字幕都保留,当前视频不换。视频卡片按「描述里的台词是否都在当前视频的提示词里」判断,
    对不上就提示「台词改过,当前视频还是旧台词」;
  - 人点重出,新视频进历史版本;要不要成为当前视频,人在历史里点「调用」—— 沿用现有规则「后出的版本不自动顶替当前版本」;
  - **每条视频记下台本快照**(用户 2026-10-23 追加):视频任务参数里存生成时的段落描述、逐句台词、声音设定、视频提示词、时长
    (任务参数不可改,天然是记录);视频卡片列出各版本当时的台词,「台词改过」也按快照比。
- 面板:diff 预览(原文 vs 每个候选)并排。

## 4. 分镜:`shot_options`(目标是段落)

- 2–3 个镜头方案,每个包括:景别(特写 / 近景 / 中景 / 全景)、机位(平视 / 俯拍 / 仰拍 / 过肩)、运镜(固定 / 推 / 拉 / 摇 / 跟)、场记表、首帧提示词。
- **判卷**:
  - 方案之间至少在「景别、机位」上差一项;
  - 每个方案过 `blocking.problems`、`furnish.problems`;
  - 过不穿帮设计里的**竖屏可拍性规则** `framing.problems`(P18,见 `specs/2026-10-23-不穿帮验收-design.md`)。
- **批准**:`decision = {pick}`,写回段落的这几列 + `blocking_json`;按现有 `invalidation` 作废这段的首帧、视频、字幕指针(和改提示词同一语义)。
- 面板:段落编辑页「出几个镜头方案」,方案卡并排。

## 5. 不做的与边界

- 不做多轮自由对话;「对话共创」就是 3b 的局部改写,可以连续多次,每次都是一条可审、可复现的 `llm_run`。
- 不做方案打分、排名、自动采纳;典型度只当标签。
- 所有提示、清单只提示不拦;唯一的拦是判卷不过(结构不合法、引用编造、方案雷同)。

## 6. 测试与验收

- **单测**(FakeLLM 只测确定性路径):`diverge` 三个函数、`pacing` 统计、`compliance` 词表、各模块判卷分支、`decision` 的写入与不可改触发器、`apply` 的拼装与片段替换、库结构 v15 迁移。
- **真 LLM 契约测试**:6 个新任务各一条(premise、beats、outline_variants、critique、rewrite、shot_options),黄金样本用题甲第 1 集。
  - **风险**:SynScale 2026-10-22 起拒绝连接,契约测试会是 SKIP,**不算通过**;功能可以先做,但「做完」要等契约测试跑绿。
- **Playwright 有头自测**:四个面板各一条链路(假 LLM 出方案 → 面板渲染方案卡 / 清单 / diff → 点批准 → 显示「假 LLM 产物不许批准」),截图存档。
