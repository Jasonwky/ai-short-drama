# 逐集批量出剧本 / 分镜(P19-B)设计

- **日期**:2026-10-24
- **用户原话**:「希望每一集的剧本以及分镜都由 AI 出,人工检查每一集,不满意的地方提出修改点由 AI 重新修改,直到满意」
  —— 拆成 C(修改回路,已交付 `specs/2026-10-24-剧本分镜修改回路-design.md`)→ **B(本文)** → A(原创分集)。
- **用户定**:
  - 剧本批准后**自动出分镜**;
  - 新增「逐集」面板;
  - 批量**不设上限**,确认页报代价;
  - 自查出的 7 处漏洞全部并入。
- **目标**:一部剧几十上百集时,一次排好「缺剧本的集全部出剧本」,人在一个总览里逐集审;
  剧本批准后分镜自动跟上;不满意的用 C 的修改回路改。
- **非目标**:
  - 不做「一键全部批准」(用户要人审每一集);
  - 不做「等上一集批准了才写下一集」的串行门控:100 集会退化成一集一集等,衔接靠大纲兜底(见 5.2 残余风险);
  - 不做原创分集大纲(那是 A)。

## 1. 逐集面板 `episodes`(新,目标是剧)

- 地址 `/drama/{id}/episodes`,登记进 `panels.REGISTRY`(scope = drama,排在「剧本」之后),自测判据 `[data-episode-row]`。
- 一集一行,三列状态:
  - **大纲**:有 / 没有;
  - **剧本** / **分镜**:取这一集最近一条相关的队列项或 LLM 运行:

| 状态 | 判定 | 显示 |
|---|---|---|
| 没有 | 没有剧本 / 段落,也没有队列项和运行 | — |
| 排队中 | 队列项 `waiting` | 第几位 |
| 生成中 | 运行 `running` | — |
| **待你审** | 运行 `proposed` | 链到审阅页 |
| **输入已变** | 运行 `proposed`,但现在算出的输入指纹 ≠ 记录的(漏洞 6) | 提示「要重跑」 |
| 已有 | 有剧本 / 有段落 | 剧本字数 / 段落数 |
| 失败 | 最近的运行 `failed` | 失败原因(截断),链到审阅页 |

  剧本的「相关运行」= `script_synopsis` / `script_adapt` / `script_outline`;分镜 = `storyboard`。
- 顶部:
  - 「待你审 N 集」计数;
  - 按钮「给缺剧本的集出剧本」(两态,第 2 节)、「停掉还没开始的(N 条)」;
  - 队列暂停时显示原因和「继续」按钮(第 4 节)。
- 每行链到剧本页的那一集锚点(`#ep-{id}`)和分镜页。

## 2. 批量出剧本:两态(照搬 `gen/fill.py` 的规则)

- **第一态 `plan`**:逐集归入四类,确认页逐条列出:
  - `todo`:要出;
  - `has`:已有剧本 —— 跳过;
  - `in_flight`:队列里已有它 / 正在生成 / 有待审的 —— 跳过(漏洞 1);
  - `blocked`:既没有大纲也没有原文 —— 跳过,写明「先写大纲或梗概」。
  另外:
  - 目标时长(1 / 2 / 3 分钟)在确认页选一次,整批共用;
  - 预计总时长 = 要出的集数 × 30–80 秒,**报区间**(不编一个点估计)。
- **第二态 `confirm`**:**只认确认页上列出的那几集**,逐集再判一次,状态变了的跳过(漏洞 3);其余按集号顺序入队。
- 每集用哪个入口,由代码按这一集有什么来定:

| 这一集有 | 任务 |
|---|---|
| 小说原文 + 大纲(`source_type = novel`) | 现有 `script_adapt` |
| 只有大纲 | **新任务 `script_outline`**(第 3 节) |
| 都没有 | blocked |

## 3. 新任务 `script_outline`:大纲 → 剧本(目标是集)

- 与 `script_synopsis` / `script_adapt` 同一个模块 `script_writer`、同一份结构化剧本 schema 和判卷(篇幅 ±20%、格式、厅堂不摆床……),
  只多一种 `kind = "outline"`。
- **输入**:本集大纲 + **前一集和后一集的大纲**(有就带,漏洞 5)+ 立项(有就带)+ 已有角色名单。
  另两个入口的提示词逐字节不变(锁定版照样命中)。
- **前提**:本集有大纲;本集不是小说集(小说集走 `script_adapt`,不让同一集两个入口)。
- `resets_segments=True`(与另两个入口相同):已有段落的集批准时要确认删除。
- 剧本页对「有大纲、没原文」的集也显示这个入口(单集手动用)。
- **真 LLM 契约测试**一条:题甲第 1 集的大纲,带前后集大纲。

## 4. 持久队列 `llm_queue`(库结构 v19)

```
llm_queue(id, task, target_type, target_id, params_json, state, run_id, reason, created_at, started_at)
  state ∈ waiting / started / cancelled
```

- **入队**:批量确认(第 2 节)、剧本批准后自动排分镜(第 5 节)。
- **出队**:后台一次只跑一条(LLM 池本来就是 1 个线程)。
  每条 LLM 运行结束(不论成败)、控制台启动、入队时,检查「没有在跑的队列项」就取最早的 `waiting`,
  调 `start_llm` 开运行,记下 `run_id`,置 `started`。
  - 开运行当场失败(前提不满足,`ValueError`):置 `started`,`reason` 写原因,接着取下一条 —— 单集问题不卡队列;
  - 命中锁定版(复用,不调 LLM):照常置 `started`,接着取下一条。
- **停掉**:把所有 `waiting` 置 `cancelled`;正在跑的那条不打断。
- **重启**(漏洞 4):
  - 现有 `runs.fail_stale` 把重启时 `running` 的运行标失败;对应的队列项保持 `started`,**不自动重试**;
  - 面板显示失败,下次批量时它归入 `todo`(没剧本)重新入队。
  - `waiting` 的照常接着跑。
- **断路器**(漏洞 2):
  - **连续 3 条**队列项的运行以「LLM 不可用 / 连不上 / 截断 / 拒答」失败(`LLMError` 类,不含判卷没过 `GateFailed`),
    就把队列置为暂停:`setting` 表记暂停原因(新白名单键 `llm_queue_paused`);
  - 暂停时不出队,面板醒目显示原因,人点「继续」才清掉;
  - 判卷没过算单集问题,不计入。
  - **怎么区分失败类别**:不解析错误文本。`service.finish` 加返回值 ——
    `None`(产出待审)/ `"judge"`(`GateFailed`)/ `"llm"`(`LLMError`)/ `"input"`(`ValueError`,前提变了);
    `runtime._finish_llm` 拿它给断路器计数。只有 `"llm"` 计入连败,其他任何结果把连败清零。

## 5. 剧本批准 → 自动排分镜

### 5.1 规则

- 批准的是「整集剧本」任务(`script_synopsis` / `script_adapt` / `script_outline`),批准后本集**没有段落**
  → 把 `storyboard` 入队(去重:队列里已有、正在跑、有待审的就不排)。
- `script_revise`(C 的逐处修改)不触发:那时段落已在。
- 入口在审阅页的「批准」路由里,单集手动批准也触发,和批量来的同一条规则。

### 5.2 残余风险(写明,不装作解决)

批量时第 N 集可能在第 N−1 集剧本审完之前就写好了,只能参考第 N−1 集的**大纲**,不是它最终的剧本 —— 两集交界处可能不严丝合缝。
缓解:「大纲 → 剧本」带前后集大纲;接不上的在审阅时用修改回路改。

## 6. 假 LLM 与自测

- `fake.py` 补 `submit_script`、`submit_storyboard` 的样例(取自自测演示剧),让有头自测能走通
  「批量 → 确认 → 队列 → 待审 → (假产物不能批准)」整条链路;
  自动排分镜的「批准后入队」用单测覆盖(假产物过不了审批闸门,自测里批准不了)。
- 自测新增链路:逐集面板点「给缺剧本的集出剧本」→ 确认页 → 确认 → 面板出现「待你审」。

## 7. 测试与验收

- **单测**(FakeLLM 只测确定性路径):
  - 四类归类与去重;确认时只认列出的、状态变了跳过;
  - 队列出队顺序、一次只跑一条、停掉、重启后 `waiting` 接着跑、`started` 不重试;
  - 断路器:3 条 `LLMError` 连败暂停、判卷失败不计、「继续」恢复;
  - `script_outline` 的前提、前后集大纲进提示词、另两个入口提示词逐字节不变;
  - 批准整集剧本后自动入队分镜(有段落 / 已在队 / `script_revise` 不触发);
  - 逐集面板各状态(含「输入已变」);
  - 库结构 v19 迁移。
- **真 LLM 契约测试**:`script_outline` 一条。
- **Playwright 有头全面自测**:新面板登记 + 一条链路,截图存档。
