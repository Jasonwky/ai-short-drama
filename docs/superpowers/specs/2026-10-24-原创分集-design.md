# 原创分集(P19-A)设计:立项 → 骨架 → 逐段展开 → 单集变体

- **日期**:2026-10-24
- **用户原话**:「脑暴的过程不完善,现在只是立项了大概,具体每一集的 AI 脑暴过程没有」;要求 C → B → A 的顺序,本文是 A。
- **用户定**:
  - 先骨架后展开(骨架 2–3 个方案挑一个,再逐段展开成分集大纲,每批 ≤ 30 集);
  - 展开先出一版,哪集不满意再单集发散;
  - 开发用多 agent 并行(实施方式,见第 6 节)。
- **衔接**:展开出的每集大纲写进 `episode.outline`,B 的「逐集」批量出剧本(`script_outline`)直接接上。

## 1. 骨架 `skeleton`(目标是剧)

- **前提**:立项已批准(`premise.load` 非空),否则拒,提示先去脑爆立项。
- **输入**:总集数 1–200、方案数 2–3、可选约束。
- **每个方案**:
  - 闭集维度:
    - `arc` 主线类型:逆袭升级 / 复仇清算 / 身份揭晓 / 情感拉扯;
    - `rhythm` 节奏型:前密后疏 / 均匀推进 / 层层加码;
    - `ending` 结局类型:圆满 / 开放 / 反转;
  - `acts` 2–8 幕,每幕 `title` / `goal`(主角在这一幕的目标)/ `climax`(幕末大事件)/ `weight`(相对权重,0 < w ≤ 1);
  - `typicality` 0..1(只标「套路款」)。
- **集数由代码分**:`skeleton.allocate(total, weights)`,按权重最大余数分配(复用 `outline.split_episodes`),每幕至少 1 集。LLM 不出绝对数。
- **判卷**:方案数对;`diverge.distinct_problems(min_diff=2)`;幕数 2–8 且 ≤ 总集数;字段非空;weight 在 (0, 1]。
- **只提示不拦**:第 9–10 集落在哪一幕(付费卡点,`pacing.THRESHOLDS["paywall_window"]`)。
- **批准**:`decision = {"pick": i}`,写 `drama.skeleton_json`(库结构 v20,`repo` 白名单),带代码算好的各幕集号区间。
- **换骨架**:允许;审阅页醒目提示「已有大纲的 X 集不会变」,之后展开照样不覆盖已有大纲。

## 2. 逐段展开 `expand`(目标是剧,参数 `start` / `end`)

- **前提**:骨架已批准;`(start, end)` 必须是 `skeleton.batches(骨架)` 里的一批(每幕按 ≤ 30 集切,`outline.MAX_EPISODES`)。
- **输入**:立项、整部骨架(`skeleton.render`)、本幕目标与幕末大事件、本批集号、上一集(`start - 1`)的大纲、已有角色名单。
- **输出**:`episodes`,按顺序每集 `title`(≤ 12 字)/ `summary` / `events`(2–8 条)。集号由代码按顺序编,LLM 不出集号。
- **判卷**:集数正好 `end - start + 1`;字段非空;事件 2–8 条;标题 ≤ 12 字。
- **批次顺序**:上一集大纲在输入里 —— 上一批批准前就生成的下一批,批准时输入指纹对不上被拒(同小说分批)。
- **写回**(每个集号):没这一集 → 新建(`source_type = "script"`,只有大纲);有但没大纲也没剧本 → 填大纲;**已有大纲或剧本 → 不覆盖**,审阅页标「已有,不覆盖」。
  大纲文本格式与小说大纲一致(`outline.render_outline`)。
- 不进 B 的队列:每批要等上一批批准(衔接),一批一批手动点。

## 3. 单集变体加强(`outline_variants`)

- 有骨架时,输入额外带上前后集大纲和本幕目标(`<context>`),让改出来的版本前后接得上;没有骨架时提示词逐字节不变(锁定版照样命中)。

## 4. 共用的纯函数(`tools/llm/skeleton.py`,地基,先于并行开发写好)

```
load(store, drama_id) -> dict | None            # drama.skeleton_json
allocate(total, weights) -> list[(start, end)]  # 按权重分集数,每幕 ≥ 1
batches(skel) -> list[(act_no, start, end)]      # 每幕按 ≤ MAX_EPISODES 切,各批集数尽量相等
act_for(skel, number) -> (act_no, act) | None    # 某集属于哪一幕
render(skel) -> str                              # 喂给 LLM 的人读版本
```

存的骨架:`{"arc", "rhythm", "ending", "total", "acts": [{"title", "goal", "climax", "weight", "start", "end"}]}`。

## 5. 残余风险与边界

- **跨批角色改名**:第 2 批可能把第 1 批起的配角改名。缓解:输入带立项的主角 / 对手和资产角色名单,并要求沿用;
  不能保证,B 的「缺资产」检查会在出分镜前拦下陌生名字。
- 新建的集 `source_type = "script"`,与 B「新建空集」一致;不为区分来源改 `episode` 的 CHECK。

## 6. 实施方式(用户要求多 agent)

CLAUDE.md M-21「写操作保持单线程」:并行写在各自的 git worktree 里,**合并由主会话逐个进行**,每合并一个跑全量测试。
- 主会话先写地基(本 spec、v20、第 4 节纯函数)并提交;
- 3 个 agent 并行:骨架任务模块、展开任务模块、单集变体加强 —— 各自只动自己的文件(含各自的单测、契约测试新文件、假样例函数);
- 共用文件(`service.TASKS`、`panels/llm.py`、模板、`fake.py` 登记、`selftest.py`、文档)由主会话合并后串行改;
- 合并后另派一个 agent 不带结论地独立复查整体 diff。

## 7. 测试与验收

- 单测(FakeLLM 只测确定性路径):地基纯函数;两个任务的前提 / 判卷 / 写回;变体的上下文;v20 迁移。
- 真 LLM 契约:骨架、展开各一条。
- Playwright 有头全面自测:大纲页「原创:从立项出分集」→ 骨架审阅页渲染(假 LLM 不能批准)。
