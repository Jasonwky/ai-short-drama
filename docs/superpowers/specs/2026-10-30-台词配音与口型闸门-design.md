# 台词配音与口型闸门(设计)

> 根因与实测:`spike-results/2026-10-29-台词与口型匹配方案调研.md`(第 2 节语音检查证据、第 4 节 AddGuide 实测、4.2 节 Qwen3-TTS 实测)。
> 用户 2026-10-29 定:**每段都必须有台词,台词与嘴型要对上**;不接受「无台词段静音导出」;功能沉淀进工作流、换剧通用。
> 用户 2026-10-30:Qwen3-TTS 中文「念得自然,两个角色分得清」;方案确认。

## 1. 问题与目标

H3 是音画联合生成,台词由它**自己编**:提示词里出现的中文都可能被念出来(第 2 段两版都念了「全程没有人说话」),
有台词的段也常常念错、念不全(第 1 段只听到「啊」)。现有闸门只能事后发现,没法让它说对。

目标(可验证):

1. 每段至少一句画面里的人说的台词(旁白不算)—— 分镜判卷与视频规划都拦;
2. 成片音轨的台词**由我们定**:先用 TTS 合成,再钉进 H3;
3. 成片过两道闸门:台词逐句对得上(拼音比对),嘴型随台词动(口型相关度 ≥ 合格线);不过自动换种子重出,有上限;
4. 全部挂在「角色」「段落」上,不写死剧名、角色名。

## 2. 流程总览

```
角色「声音描述」 ──VoiceDesign 3 版──> 人试听定稿(asset_approval,slot = voice)──> character.voice_ref_path + voice_ref_text
                                                                                          │
段落台词(rules.dialogue_lines) ──Base 逐句克隆 + 拼接──> Whisper 回听(拼音比)──> segment.line_audio_path,段长由音频定
                                                                                          │
视频规划 ──H3 + MiniMaxH3AddGuide(音频, 第 0 帧)──> 成片 ──语音检查(拼音)+ 口型检查──> 不过:自动换种子重出 ≤ 2 次 → 人看
```

## 3. 角色音色(资产「声音」槽)

- **生成**:`kind = 'voice'` 的任务,目标是角色。参数记 `instruct`(= 声音描述原文)、`text`(试听句)、种子;
  一次规划 3 个种子 = 3 条任务,和资产图一样进历史、人挑「用这一版」才写 `voice_ref_path`。
  试听句默认取这个角色剧本里的第一句台词(没有就用固定试听句),写进 `voice_ref_text`(v24 新列)—— 克隆时要它当参考文本。
- **定稿**:复用 `asset_approval`,`approval.SLOTS` 加 `("character", "voice"): "voice_ref_path"`。
  定稿前代码查一次:Whisper 回听试听音,拼音对得上试听句(参考文本错了,克隆会串字)。不过的要写理由才能定稿(与资产图同规则)。
- **面板**:「资产图审」里角色卡片多一行声音:3 个 `<audio>` 播放器 + 用这一版 + 定稿。资产面板的声音描述旁加「生成试听」。
- **不做**:音色一致性 / 区分度的客观闸门。实测 WavLM 分不开两个角色(0.936 高于同角色克隆),且 CC BY-SA 3.0 不能进产品
  (调研 4.2 节)。声音描述过于相近只能靠人耳,面板上把同一部剧所有已定稿的音色并排放,方便对比。

## 4. 段落台词音频

- **任务**:`kind = 'tts'`,目标是段落。参数(规划时定死,快照):
  `lines: [[说话人, 台词]]`、`voices: {说话人: {path, sha256, ref_text}}`、`gap_sec`(句间停顿,0.4)、`lead_sec`(开头留白,0.3)、
  `tail_sec`(结尾留白,0.5)、种子。产物:一个 wav + `tts.json`(每句在音频里的起止)。
- **执行**:与字幕对齐同一套路(`serve/aligner.py` 的模式):worker 空闲时经 ssh 在云机跑 `serve/tts_remote.py`
  (用 `/root/autodl-tmp/qwen-tts/venv`,显存约 4 GB),**ComfyUI 队列有任务就留在 pending 不打断**;
  合成后同一次 ssh 里跑 Whisper 转写,结果拿回本机判卷。
- **判卷(本机,纯函数)**:每句转写与台词按**无声调拼音**比(先繁转简;实测 10 条里不满分的 4 条全是同音字 / 繁体,调研 4.2 节),
  每句拼音命中率 ≥ 0.9。不过换种子重合成,最多 3 次,再不过任务失败、写明哪句。
- **写回**:`segment.line_audio_path`(v24 新列),只填空位(与 collect 一致);已有就进历史等人挑。
- **段长由音频定**:规划视频时 `duration_sec` = 音频时长,`MINIMAX_H3.frames_for` 对齐到帧网格;
  超出 H3 训练区间(124–362 帧 ≈ 5.2–15.1 秒)规划时拦:太短在结尾补静音到下限,太长要求拆段或删句(不压缩语速)。
- **过期**:台词(`dialogue_lines`)或任何说话人的定稿音色变了 → 当前台词音频算过期,视频规划拦,面板提示重合成。

## 5. 视频

- `build_h3(..., guide_audio=名字)`:加 `LoadAudio` + 串一个 `MiniMaxH3AddGuide(audio, audio_vae, frame_idx=0)`,
  接在图片锚点之后(spike `tmp/spike_audioguide/run.py` 的接法,实测音轨与给定音频相关 0.945–0.994)。
- `plan_video`:参数 `audio_guide`(台词音频路径)+ 台本快照记音频 sha256;dispatch 一并上传(`upload_image` 传音频实测可用)。
  删掉提示词里的「XX 的声音:……」与 `SILENT`;台词照旧逐字写进提示词(帮模型对口型与表演)。
- 旧的 `audio_ref`(参考音频喂 ref2va)保持拒绝 —— 闸门 0-4 实测会复读内容,与这里的 guide 不是一回事。

## 6. 闸门

### 6.1 每段都有台词

- 分镜判卷(拆分镜、分镜修改):段落里没有一句角色台词 → 打回,要求补一句画面内角色说的话。
- `video_problems`:没有台词的段落不许规划视频(老库里已有的无台词段,如第 1 集第 2 段,走分镜修改补台词)。

### 6.2 语音检查改拼音

`cut/subtitles.align` 的逐字比对换成逐字拼音比(新依赖 `pypinyin`,MIT);判卷阈值不变。
成片转写同样会出同音字,不改会把对的判错。

### 6.3 口型检查(新,`cut/lipsync.py`)

- 量法沿用调研 4.1 节:本机 CPU 跑 mediapipe FaceLandmarker(Apache-2.0,模型 `face_landmarker.task`),
  每帧内唇张开度 / 脸高;音轨每帧 RMS;按鼻尖位置串成人脸轨迹;**在每句台词的时间段里**取相关最高的那条轨迹。
- 判定:每句(≥ 1 秒)都要有一条轨迹 r ≥ **0.30**、滞后在 ±3 帧内;没有正脸轨迹的句子记「无法判定」。
  合格线暂定,依据:钉音频后 0.66、原片好片 0.39、画外音 −0.77(样本 5 条);前几集出片后按实测重标,写回调研文档。
- 结果按视频 sha256 缓存在 `<视频>.lipsync.json`(与 textscan 同法),单测里由 conftest 换成假读者。
- **只判「嘴随声动」,不判「是对的人在动嘴」**(v1 不做人脸 ↔ 角色的身份对应)。

### 6.4 自动重出

段落的语音检查或口型检查不过(「无法判定」不算不过)→ 同一份台词音频、新种子自动规划一次视频,
**每份台词音频最多 2 次**,之后停下交给人。重出的视频进历史,当前视频不自动替换;按 `flow_auto` 开关,默认关时只提示不排。

### 6.5 导出

导出 begin 时每段必须:有台词音频且没过期、当前视频的 `audio_guide` sha256 等于当前台词音频、语音检查过、口型检查过或人填理由放行
(复用 `blank_override` 的思路:只认那条视频的 sha256)。

## 7. 库结构 v24

- `character.voice_ref_text TEXT`
- `segment.line_audio_path TEXT`
- `task.kind` 的 CHECK(现为 `image` / `video` / `align`)加 `voice`、`tts` —— SQLite 改 CHECK 要重建表,迁移按现有 MIGRATIONS 写法
- `asset_approval.slot` 的 CHECK(现为 `image` / `fourview`)加 `voice`,同样重建表

## 9. 分期(每期单测 + 有头自测绿才提交)

1. **音色**:v24 库结构、`voice` 任务、云机脚本、资产图审里的声音行与定稿;
2. **台词音频**:`tts` 任务、拼音判卷、段长由音频定、过期判断;
3. **视频接音频**:`build_h3(guide_audio=)`、规划 / dispatch / 台本快照,删声音描述与 SILENT;
4. **闸门**:每段有台词(分镜判卷 + 规划)、语音检查改拼音、口型检查、自动重出、导出闸门;
5. **真链路验收**:第 1 集:两人定音色 → 5 段台词音频 → 重出(第 2 段先走分镜修改补台词),记口型分数,标定合格线。

## 10. 不做 / 已知限制

- 不做 MuseTalk 口型后处理(兜底留到 6.4 自动重出仍大量不过时再评估)。
- 不做音色区分度的客观闸门(第 3 节)。
- 口型检查不认人(6.3);背影、侧脸为主的段判「无法判定」,靠看片确认。
- 情绪 / 语气:v1 只用声音描述 + 台词,不按句控制情绪(VoiceDesign 的 instruct 可加,留待需要时)。
