## 0. 目的与边界

- **目的**:自动发现、监控、获取热门短剧与小说,拆解「为什么能成为爆款」,产出**拆解卡**供子项目 2 的创作参考。**不直接使用原作内容**。
- **用户要求**:全自动检索、扒内容、监控热度;既能把数据拉回让人挑,也能由人给关键词;三种模式(A 全自动 / B 监控自动、人挑 / C 全手动)都支持;所有操作在控制台里。
- **不做**(规避技术措施,《著作权法》第 49 条):签名或设备标识伪造、CENC 解密(含缓存文件)、番茄字体反解或 OCR、过验证码或风控、盗版镜像站、无人值守看广告、绕过录屏屏蔽。
- **范围内来源**:红果(榜单 + 详情 + 剧评 + 登录后网页前 5 集录屏)、晋江 / 17K / 纵横 / 七猫(元数据 + 免费明文章)、番茄(只有元数据)、人工投递。抖音、B 站、快手、起点不做。

## 1. 结构与数据

参考库**全局**,不挂在某部剧下。代码在 `tools/refs/`,数据库单独一个文件 `refs.db`(库结构从 v1 起,和剧库的版本号无关),控制台启动参数 `--refs-db`;
`start.bat` / `start.ps1` 默认显式传 `outputs/refs/refs.db`,参考库的文件根与 `journal/refs/` 在同一目录下。不带参数时参考库面板显示「未配置参考库」,不偷偷建库。
创作任务按卡片编号跨库只读卡片。

### 1.1 分层

1. **适配器** `refs/sources/<平台>.py`:统一契约 `list_ranks` / `fetch_meta` / `fetch_content` / `fetch_reviews`。
   - 解析结果过 schema 校验;**缺关键字段、榜单 0 条都算失败**,不当作「今天没有新作品」。
   - **抓取方式每个适配器写死**:先用普通 HTTP(标准库);HTTP 抓不到的页面用 Playwright **无头**(用户 2026-11-06 定的唯一无头例外,只限参考库后台抓取)。运行时不悄悄从 HTTP 换浏览器;用了哪种写进 `journal/refs/`。纵横、17K 的 https 主域 curl 连不上,实现时用真请求核实。
2. **本机抓取队列** `ref_job`:单独的后台线程一次跑一条,**不进 GPU worker**。按域名限速(请求间隔数秒),UA 写明身份。
   - **每轮抓取前重读 robots**;变成禁止 → 来源**暂停**(要人看过后手动恢复)。每次抓取把 URL、状态码、当时的 robots 快照写进 `journal/refs/`(**不存页面正文**);来源设置与作品详情里有只读的抓取记录查看。
3. **录屏**(红果网页,第 1–5 集):标签页录制(`--auto-accept-this-tab-capture`、`getDisplayMedia` 带 `audio: true`、`MediaRecorder` vp9 + opus),播放器全屏后再录。
   - **任何模式下都要人点「录这部」才开始**,一次一部,实时播放(robots 禁止 `/player/*/*`,不能由程序自己批量打开)。
   - 登录状态存在专门的浏览器配置目录 `outputs/refs/profile/`(gitignored,调研时的配置目录不迁移,重新扫码),只给录屏线程用;录前检测登录,过期就挡住任务、待办里提示扫码。建议用小号。
   - 录屏用**有头**浏览器。
4. **整理**:
   - 小说章节入库前过三条判定:私用区字符 ≤ 1 %、没有「去 App / 开通会员 / 订阅」截断提示、正文汉字 ≥ 本章自报字数的 80 %(有自报时)。不过就标「不收」并写原因。
   - 视频转写是 `ref_job` 里种类为「转写」的任务。控制台的 worker(`Runtime`)多拿一个 `refs.db` 句柄:判断机器空闲时**先派剧库的生产任务**,没有了才看 `refs.db` 有没有转写;不新开第二个 worker。
     **转写结束就删云机上的副本**(成功失败都删,worker 日志记一笔)。
   - 关键帧在本机抽:开头 0–3 秒每 0.5 秒一张(7 张),之后每 10 秒一张(单测锁住)。
   - 剧评**去掉昵称**再入库。
5. **拆解**:见第 2 节。
6. **调度** `refs/monitor.py`:每个来源单独选模式 A / B / C,见第 3 节。
   - 「涨得快」由代码定义(日增量与名次跳升),阈值放进配置。
   - 每天只拉榜单 + 已关注的作品;sitemap 每周增量一次。
   - 控制台关着时不拉,重新开起来补拉一次,热度曲线上标出缺口。
   - 「当天」一律按北京时间零点切换。

### 1.2 库表(`refs.db` v1)

| 表 | 内容 | 不可改 |
|---|---|---|
| `ref_source` | 每个来源的模式、两个每日上限(★)、保留天数(★)、小说拆前 N 章(★)、熔断 / 暂停状态与原因 | — |
| `ref_work` | 作品:平台 + 外部 ID 唯一,标题、类型、标签、链接、关注 / 拉黑 | — |
| `ref_heat` | 热度时间序列:名次、热度、点赞等,原始字段存 JSON | 写入后不改 |
| `ref_job` | 抓取、录屏任务 | 参数不可改 |
| `ref_content` | **每个文件一行**,「种类」一列区分(章节 / 录屏 / 转写 / 关键帧 / 剧评):所属集或章、路径、sha256、来源、判定与原因、到期时间;清理覆盖全部种类 | — |
| `ref_fingerprint` | 小说章节、视频转写、剧评三类原文,每个 12 字滑动窗口一个哈希,**永久保留**,供重叠检查与子项目 2 的原创度闸门(粗算百万行级,标定实验时实测行数) | ✓ |
| `ref_unit` | 第一层逐单元标注(第 2.1 节) | 被已批准的卡片引用后 ✓ |
| `ref_card` | 拆解卡(审阅视图 + 创作视图),批准后锁定;再拆出新版,旧版标「已被取代」 | 批准后 ✓(触发器) |
| `ref_setting_log` | 上限等设置的每次改动:时间、从几改成几 | ✓ |

不可改由**数据库触发器**强制。

### 1.3 两条代码强制的规矩

- **隔离**:创作任务**只能读卡片的创作视图**(第 2.4 节),读不到 `ref_content` 的文件,也读不到审阅视图里的引用。
- **保留期**:★ 必填,不填就不让抓。从抓取那天开始算;到期删原文,指纹与卡片保留。
  **可选「永久」**(用户 2026-11-07 定红果「永久,需要的时候手动删」,结构 v3 `ref_source.retention_forever`):永久的内容不会被自动清理;
  作品详情有「删除这部的原文(保留指纹)」,两态确认后立刻删文件、指纹留着、作品不拉黑。
  **顺延**:有待审 / 刚被驳回的拆解时顺延;还没拆解的作品也可以顺延,但最长只到保留天数的 2 倍,到了就删,不管拆没拆。每天跑一次清理,删除失败要报出来。
- **拉黑**:之后不再抓;已抓的原文走清理流程删,指纹保留。

## 2. 拆解卡

两层:第一层逐单元标注,第二层汇总成整部作品一张卡。**数字一律由代码算**,LLM 只给闭集取值与逐字引用。
两个 LLM 任务(单元标注、整卡汇总)各自登记进 `service.TASKS`,走 `gate.run_gated`,各有一条真 LLM 契约测试;fake 产物打标、不许通过审批。

### 2.1 第一层:逐单元(一集短剧或一章小说)

| 字段 | 取值 | 来源与核对 |
|---|---|---|
| 钩子 / 反转 / 压放 | 沿用 `beats.FIELDS` 的闭集 | LLM |
| 卡点 | 短剧:**这一集结尾够不够强、适不适合放付费点**(对内容的判断,不是猜平台把付费点设在哪);小说:章末悬念(有 / 无) | LLM |
| 画面钩子(仅视频) | 有 / 无 + 依据是第几秒那一帧 | 视觉模型看关键帧;代码核对这一帧存在 |
| 这一单元发生了什么 | 一两句,用自己的话说 | LLM |
| 依据 | 一句逐字引用 | 小说逐字核对(`verbatim.restore`);视频转写**按拼音**核对(沿用 `cut/speech.py` 口径);对不上就回炉 |
| 出场人名 | 名单 | 代码核对每个名字都在原文里出现 |

- 小说每部只拆前 N 章(N 在来源设置里,★ 必填、没有默认值,没填不拆);依据范围写明「第 1–10 章(共 32 章免费)」。每部作品有 token 上限。
- 单元判卷超过轮次上限就标失败,不进汇总;汇总照样能出,依据范围写明「第 3 集拆解失败,未计入」,卡片醒目提示。

### 2.2 第二层:整卡

| 部分 | 内容 | 谁出 |
|---|---|---|
| 类型 | 题材、爽点、冲突、开场钩子类型。**题材用拆解卡自己的宽闭集**(含玄幻、仙侠、科幻、无限流等),每个取值标明对应 `premise.DIMS` 的哪个题材;`premise.DIMS` 不动 | LLM |
| 人设 | 主角和对手的身份标签、反差点,只写类型不写名字 | LLM |
| 节奏 | 反转间隔、钩子密度、开头和结尾两段的统计 | 代码(`pacing.py`,从第一层算) |
| 热度 | 峰值、日增量、在榜天数;第一次见到的作品写「无历史」 | 代码(`ref_heat`) |
| 为什么爆 | 3–6 条假设,每条标依据类型:剧情(引第几集)/ 剧评(引哪几条)/ 热度(引哪段时间) | LLM 出假设,代码核对 |
| 冷门对照 | 每个特征在同平台、同题材的热门与冷门作品里各占多少,例如「热门 8/10、冷门 7/10,区分度低」 | 代码 |
| 可借鉴的手法 | 抽象成「怎么做」 | LLM |
| 不可借鉴 | 特有设定、名字、标志性情节;人可以补充 | LLM + 人 |
| 依据范围 | 例如「第 1–5 集 + 剧评 141 条,后面的集数没看过」 | 代码 |

**冷门对照**:
- **冷门的定义**(代码):同平台、同标签组里,热度低于这一组中位数的作品。红果从 sitemap 与详情页抽样;小说从分类页抽样,分类页 robots 不允许或抓不到,这个平台就不做对照,卡片写「无对照」。
- **分组**用平台自己的标签,由代码按对照表映射到拆解卡的题材(冷门作品只做第一层,没有 LLM 给的题材)。
- **只比第一层的闭集字段与节奏统计**;「为什么爆」的自由文本假设不直接对照,卡片上写明。
- 冷门作品只做第一层标注;抽样也算进每日上限。

### 2.3 用数据审 LLM

- 「为什么爆」引的剧评不存在或逐字对不上 → 整卡回炉。
- 说热度涨得快,但 `ref_heat` 那段时间没涨 → 标「与数据不符」。
- **出自正片的断言**不许超出依据范围(按集号拦);**出自剧评的断言**可以超出,但要标「据剧评(二手)」并引具体剧评。

### 2.4 两个视图

- **审阅视图**:给人看,带全部引用与原文出处。
- **创作视图**:由代码从审阅视图生成,子项目 2 只读这个 ——
  去掉所有引用;按「出场人名」把名字换成角色类型(「女主」「反派婆婆」),换完再查原文里还剩没换的高频专名,有就拦;
  再拿永久指纹比一遍,与原文**连续 12 字以上相同就拦**(12 是暂定值,1a 末尾做标定实验后定;这里只拦逐字照抄,换了说法的剧情雷同由子项目 2 的原创度闸门拦)。
  被驳回的假设不进创作视图。
- **创作视图带 sha256**,格式本期定稳:子项目 2 的创作任务把用到的创作视图**全文与 sha256 快照进自己的任务输入**,不只记编号 —— `refs.db` 挪走或换了,剧库这边照样能逐字节复现。

### 2.5 审阅与锁定

人在「拆解卡审阅」面板逐条采纳或驳回「为什么爆」的假设,存进批准时的选择(照 `decision_json` 做法:批准必须带选择、序号严格校验),然后批准、锁定。

### 2.6 跨作品趋势

只用代码统计已批准卡片的闭集字段和热度(例如「近一个月古装复仇在红果热门里占比在涨」),不让 LLM 参与,放在「榜单与趋势」面板。

## 3. 控制台

导航栏单独一项「参考库」,带**待办数**(待审的卡、登录过期、来源熔断 / 暂停)。

### 3.1 五个面板

| 面板 | 看到什么 | 能做什么 |
|---|---|---|
| 来源设置 | 每个来源的模式、两个每日上限、保留天数、拆前 N 章、熔断 / 暂停与原因、robots 状态、今天与近 7 天的 LLM 调用次数和耗时;红果另有登录状态 | 改设置(改动进 `ref_setting_log` 与 `journal/refs/`)、解除熔断 / 暂停、红果「打开浏览器扫码」(有头) |
| 榜单与趋势 | 当天榜单、热度曲线(缺口标出)、「涨得快」、按题材 / 标签筛选、跨作品趋势 | 关注、拉取、拉黑;关键词检索(注明「只覆盖已见过的作品」) |
| 作品详情 | 元数据、热度曲线、每集 / 每章判定与原因、到期时间、任务状态 | 拉取正文、录屏(红果)、拆解、拉黑、人工投递(视频或文本,来源必填) |
| 录屏 | 队列、进度(如「第 3/5 集,0:42/1:16」)、每集检查结果 | 点「录这部」;单集重录 |
| 拆解卡审阅 | 审阅视图、冷门对照、依据范围;可切换预览创作视图 | 逐条采纳 / 驳回、补「不可借鉴」、批准 |

**每集录完的代码检查**(不过就标失败、不进拆解):时长与片长相差 ≤ 2 秒;`volumedetect` 不是静音;抽一帧不是黑屏或白屏。

### 3.2 A / B / C 三种模式下谁做什么

| 步骤 | A 全自动 | B 监控自动、人挑 | C 全手动 |
|---|---|---|---|
| 拉榜单和热度 | 自动 | 自动 | 人点 |
| 选作品 | 按规则自动(「涨得快」或进前 K 名,K 在配置里) | 列候选并写明入选原因,人勾选 | 人用检索或链接加 |
| 抓正文、剧评 | 自动,受上限 | 勾选后自动 | 人点 |
| 红果录屏 | **永远人点**;A 只挂「建议录屏」 | 人点 | 人点 |
| 冷门对照抽样 | 自动,算上限 | 自动 | 人点 |
| 拆解 | 自动,受上限 | 内容齐了就自动 | 人点 |
| 批准拆解卡 | 人 | 人 | 人 |

**每日上限**(每个来源两个数:自动抓几部、自动拆解几次):
- ★ 必填、没有默认值,没填就切不到 A;填 0 = 这一项不自动做;
- 改了马上生效(调高就接着跑,调到比今天已用的还小就立刻停);
- 到上限就停,来源设置里标「今日已满 10/10」,北京时间零点清零;**不补跑**,第二天按当天榜单重新选;
- 人手动点的抓取和拆解不受上限限制。

### 3.3 自测

五个面板登记进 `REGISTRY`,在 `selftest.KEY_SELECTOR` 给判据;自测用快照假适配器,不联网、不开录屏;每个面板的自测库预置一部「已拆解待审」的作品。

## 4. 错误处理、测试、验收、分期

### 4.1 错误处理(fail-loud,不兜底)

| 情况 | 处理 |
|---|---|
| schema 不符、0 条 | 任务失败写明缺什么;连续 3 次失败 → 来源熔断 |
| 验证码、风控、412 | 当天熔断,不重试 |
| 网络超时 | 下一轮重试,最多 2 次,之后失败 |
| robots 变成禁止 | 来源暂停,人看过后手动恢复 |
| 红果登录过期 | 录屏任务挡住,待办提示扫码 |
| 录完检查不过 | 那一集标失败,人点重录 |
| 云机不在线 | 转写等着;失败标失败;云机副本都删 |
| LLM 失败 | 走现有闸门;自动拆解连续 3 次失败暂停(沿用 `llm_queue`) |
| 到期清理 | 每天一次;删除失败报出来;按 1.3 节顺延 |
| 控制台关过 | 重开补拉一次,曲线标缺口 |

**线程**:抓取线程(HTTP / 无头浏览器)与录屏线程(有头浏览器、独占登录配置目录)各自独立,不在网页框架的事件循环线程里调 Playwright 同步接口;`refs.db` 单独一个连接,同样 `cached_statements=0`。

### 4.2 测试

- **单测**:适配器解析用页面快照 —— **入库前把正文换成同长度假字、去掉剧评昵称**,只留页面结构,版权内容与个人信息不进 git;判定规则(私用区、截断、字数);「涨得快」;每日上限;到期清理与顺延;创作视图(去引用、换名、12 字重叠);拼音核对引用;冷门对照统计;触发器(卡片、指纹、设置日志不可改)。
- **真 LLM 契约测试**:单元标注、整卡汇总各一条。
- **Playwright 自测(有头)**:五个面板全过,用快照假适配器。

### 4.3 验收

现有四层不变,另加一步**来源冒烟**(不依赖云机):每个来源真联网拉一次榜单,过 schema 校验,逐个来源列结果。
- 网站返回 200 但解析失败 = 我们的适配器坏了 → **验收失败**;
- 连不上、验证码、风控 = 外部不可用 → 报告单列标红、该来源熔断,**不算验收失败**;
- **所有来源都外部不可用**(例如断网)→ 冒烟判 SKIP,总判决 PARTIAL,不算通过。

真录屏要真账号登录、真播放,**不进验收**(验收只跑假适配器那条路),报告里写明这一项没有自动验。
