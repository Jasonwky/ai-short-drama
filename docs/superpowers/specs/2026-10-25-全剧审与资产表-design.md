# 全剧审与 AI 资产表(P20)设计

- **日期**:2026-10-25
- **用户原话**:
  - 「分镜没有 AI 自动生成呢」—— 剧本全批准后分镜被「缺资产」拦住,AI 流程停在建资产这一步;
  - 「剧本,分镜 AI 整体审批也需要加到控制台中」;
  - 选定:「AI 全剧审,人拍板」;范围「全剧剧本、全剧分镜、AI 出角色 / 场景表,**每一个大类之后分别加一个 AI 整体审批**」;
  - 第二轮:「全剧审一次的集数按照实际集数来」「(资产表)可以自动出图」「再全剧审查下上面的内容是否合理,是否有漏洞」。
- **实战起因**:《回到古代做将军》10 集剧本逐集批准后,人工通读才看出跨集问题 —— 同一人三种叫法(陈老三 / 老陈 / 老兵)、
  泛称说话人(兵卒甲、粮官……)、第 10 集人设与穿越设定冲突、第 9 集旁白重复第 7 集、第 4 集还没进先锋队就指挥先锋队;
  逐集评审团(`critique`)一次只看一集,看不出这类毛病。

## 0. 流程总图

```
逐集剧本(已有)
  └─ 全集都有剧本 → ①全剧审·剧本 ─ 有采纳 → 按集排「剧本修改」→ 都处理完 → 再跑① ─┐
                                    └ 没采纳(通过) ─────────────────────────────┘
  └─ ①通过 → ②AI 出资产表 → ③全剧审·资产 ─ 有采纳 → 带意见重出② → 再跑③
                                          └ 没采纳 = 资产定稿
  └─ 资产定稿 → 自动:出资产图(正面 → 四视图)、角色声音、每集拆分镜
  └─ 全集都有分镜 → ④全剧审·分镜 ─ 有采纳 → 按集排「分镜修改」→ 都处理完 → 再跑④
                                    └ 没采纳(通过)→ 进首帧 / 视频(已有,人点)
```

- 每一步都是 LLM 出、**人在审阅页批准才写回**(本仓 LLM 纪律不变);「自动」只指**排进队列**,不指替人批准。
- 全剧审**只提问题不改东西**,改由已有的修改回路做。循环由人收口:人一条都不采纳 = 这一关通过。
- 推进由一个纯函数决定(第 4 节),每次 LLM 批准、GPU 任务完成后调用一次,不靠散落在各处的钩子。

## 1. AI 出资产表 `cast`(目标是剧)

「资产表」= 控制台「资产」面板里的角色 / 场景 / 道具三张表(`character` / `scene` / `prop`):
名字、外貌、造型、地点、光线、陈设、**生成描述**(`final_prompt`,英文,出图用)、声音描述、参考图。
拆分镜要从这张表里挑人和场景绑到每一段,出首帧要用角色的四视图和场景图 —— 所以它是剧本到画面之间的那一层。

- **前提**:①已通过;队列里 / 审阅页上没有这部剧的剧本类任务。
- **输入**:立项、全部剧本(`<episode n="…">` 数据标签)、现有资产表、代码抽出的**说话人清单**(`rules.dialogue_lines`)与
  **地点清单**(`batch._PLACE`)、`notes`(来自③采纳的意见,可空)。
- **输出**:
  - `characters`:`name` / `aliases` / `appearance` / `styling` / `final_prompt`;
  - `scenes`:`name` / `places` / `location` / `time` / `lighting` / `furnishings` / `final_prompt`;
  - `props`:`name` / `description` / `final_prompt`(剧情里反复出现、要在画面里认得出的物件;不做覆盖检查);
  - 有 `notes` 时外加逐条回应(`revise.response_schema`)。
- **判卷**(代码,回炉):
  - 说话人清单里每个名字**恰好**落在一个角色的 `name` 或 `aliases` 里;
  - **不同的人不许并成一个**:同一场里一问一答的两个说话人不能归到同一个角色(代码按相邻台词查);
    提示词写明「兵卒甲、兵卒乙是两个人,各建一个角色」;
  - 地点清单里每个地点恰好落在一个场景的 `places` 里;
  - 名字两两不重(含别名);现有资产的名字必须原样出现,不许改名、不许丢;
  - 文字字段非空;`final_prompt` 英文、≤ 600 字符(同 `describe` 的判卷);`notes` 的回应过 `revise.response_problems`。
- **批准写回**(`repo` 白名单;写前 / 写后存 `llm_run.applied_json`):
  - 新名字 → 新建资产;
  - 现有资产:**没带意见时**只填空字段;**带意见时**按意见逐字段替换,审阅页逐个字段列旧 → 新,人按意见整组接受 / 驳回(修改回路的做法);
  - 已经出过图的资产,外貌 / 造型 / 生成描述不许改(批准时拒,写明「先删图或手动重出」)—— 防止图和描述对不上;
  - **别名不在这里改剧本**:有别名的集,批准时按集排一条 `script_revise`(意见「把『老陈』统一写成『陈老三』,包括台词标签和叙述」,
    必须改),由修改回路改、人批准。只换说话人标签会留下叙述里的旧称呼,拆分镜时又对不上;
  - 「回到这一轮之前」(两态):删本轮新建且**还没出图、没被段落引用**的资产,恢复本轮改过、之后没再改过的字段;不满足的逐项列原因。

## 2. 全剧审 `drama_review`(目标是剧,参数 `stage`)

一次审**全剧所有集**(用户定)。三个阶段,每个阶段一个固定视角、一份类别闭集,其余同评审团(只列问题、逐字引用、不打分、人逐条采纳 / 驳回):

| stage | 看的材料 | 参照(只读,不许引用) | 类别闭集 |
|---|---|---|---|
| `script` | 全部剧本 | 立项、骨架、各集大纲 | 称呼不一致、人设冲突、与立项冲突、情节重复、台词重复、时间线或因果错、前后集接不上、伏笔没回收 |
| `assets` | 资产表 | 全部剧本 | 漏了角色或场景、不同的人并成一个、造型与剧本冲突、陈设与剧本冲突、生成描述与中文描述不符 |
| `storyboard` | 全部分镜(逐段:场景、角色、景别机位运镜、描述、场记) | 全部剧本、资产表 | 分镜与剧本不符、场景用错、造型或姿态前后不连续、跨集重复镜头、景别单调 |

- **前提**:`script` 每集有剧本;`storyboard` 每集有段落;`assets` 资产表非空。不满足就拒并说缺哪集。
- **每条问题**:`episode`(集号闭集;`assets` 阶段为资产名闭集)、`quote`(逐字引自那一集 / 那个资产)、`category`、`severity`、`suggestion`,
  可选 `also`:跨集问题的另一处(集号 + 逐字引用,比如「第 9 集旁白重复第 7 集」)。修改落在 `episode` 那一集。
- **判卷**:1–20 条;引用逐字(`verbatim.restore`)且在所标那集里;`storyboard` 阶段引用要能定位到唯一一段;改法非空。
- **批准**:`decision = {"adopt": [...], "reject": [...]}`,每条都要表态。**批准即确认排修改**(审阅页在批准按钮上方逐集预览将排的意见),
  批准时当场检查,有一项不过就拒批准、写明哪条:
  - 一集采纳超过 10 条(`revise.MAX_NOTES`);
  - `script`:引用在剧本里定位不到唯一一行(`script_revise.locate`);
  - `storyboard`:改法要增删 / 拆并段落(`storyboard_revise.STRUCTURE_WORDS`)—— 这类请驳回后用「LLM 重拆分镜」。
- **写回**:全剧审本身不写剧本 / 分镜 / 资产,只在批准时入队 —— `script` → 各集 `script_revise`(意见 = 「[类别] 改法」,针对 = 引用),
  `storyboard` → 各集 `storyboard_revise`(针对 = 定位到的段号),`assets` → 一条带 `notes` 的 `cast`。
- **一次全剧的规模**:按集数不切批。输入超过 `drama_review.MAX_INPUT_CHARS`(初值 15 万字,按 Claude 命令行实测再定)就**拒并报字数**,
  不静默截断、不自动拆批;分镜阶段的材料只渲染判卷用得到的字段(不带英文提示词),先压体积。命令行超时 900 秒同样 fail-loud。

## 3. 自动出图、声音、拆分镜(资产定稿后)

「资产定稿」= 最近一次 `cast` 批准之后,有一次 `drama_review(assets)` 批准且**一条都没采纳**。定稿后自动:

- **资产图**:对缺图的角色 / 场景 / 道具走 `fill.plan_fill("assets")` → `confirm_fill`(复用增量补全:在途的不重交、内容不就绪的跳过并记原因),
  种子由代码随机;GPU 任务由已有 worker 推进;
- **四视图**:角色正面图出来后(且这个角色还没有四视图、没在途),自动 `plan_fourview`;
- **角色声音**:没有 `voice_desc` 的角色各排一条 `voices`(LLM,人批准);
- **拆分镜**:每集调 `batch.after_script_approved`(没段落、不在途、资产够才排)。
  现在只有整集剧本批准会调它,剧本**修改**批准不会 —— 别名统一的修改批完后,由 `flow.advance` 补排。
- 没开云机时 GPU 任务照常排队等机器(`waiting_host`),不报错;开销在逐集面板上方显示「将出 N 张图,估时 …」(`estimate.basis`,没登记卡 = 无法估时)。
- 人不满意某张图:在资产面板手动重出 / 上传,和现在一样。

## 4. 推进:`flow.advance(store, drama_id)`(纯规划,不调 LLM)

每次 LLM 批准(`panels/llm.py` 批准之后)、每次 GPU 任务完成(worker 推进之后)调用,在队列锁里:

1. 算这部剧各关的状态:`script_ready` / `r1_passed` / `cast_approved` / `assets_final` / `storyboard_ready` / `r4_passed`;
2. 「这一关该跑、队列里和审阅页上都没有同一条」才入队 —— 幂等,重复调用不重复排;
3. 有任何同类任务在途 / 待审,就等(比如①的修改还没全批完,不重跑①)。

各关的判法写成纯函数单测;逐集面板顶上的「全剧流程」一栏就是把这份状态画出来。

**不自动重跑的情况**(写进面板提示):某一关通过之后人又手动改了剧本 / 资产 / 分镜,不会自动重审 —— 面板上那一关标「通过后又改过」,给「再审一次」按钮。
否则别名统一这类小修改会把①、③反复重跑。

## 5. 控制台

- 「逐集」面板顶上加「全剧流程」一栏:①②③④ 和「出图 / 声音」五格,每格写状态(未就绪 + 原因 / 排队 / 生成中 / 待你审 / 有 N 条修改在处理 / 通过)、链接、
  手动「跑这一关」按钮(前提不满足置灰写原因);「暂停自动推进」开关(存在剧上,库结构 v21:`drama.flow_paused`),关掉后只能手动点。
- 审阅页:
  - 全剧审按集分组列问题(引用、`also`、类别、严重度、改法),勾采纳 / 驳回,批准按钮上方预览将排的修改;
  - 资产表按「新建 / 补字段 / 改字段(旧 → 新)/ 不变」列,别名列「将给第 N 集排统一称呼的修改」,覆盖检查的结果(每个说话人 / 地点归到谁)整表列出。
- **资产图要在控制台里看得见**(用户 2026-10-25 定):
  - 「全剧流程」的「出图」格展开是一张资产图墙:每个角色一行(正面图、四视图)、每个场景 / 道具一格,
    缩略图可点开大图;没图的格子写状态(排队 / 生成中 / 失败 + 原因 / 内容不就绪 + 原因),失败的带「重出」;
  - `cast` 审阅页与 `drama_review(assets)` 审阅页,资产已有图的把缩略图列在文字旁边,对着图审描述;
  - 资产面板照旧可手动重出 / 上传 / 挑版本,图墙上每格链到资产面板对应的那一项。
- 新任务登记 `service.TASKS`;自测 `KEY_SELECTOR` 加判据;遍历全部面板截图。

## 6. 残余风险

- 全剧审「schema 全合法但挑得平庸」抓不到 —— 只能靠人逐条采纳;按阶段统计采纳率,长期没人采纳说明那个阶段的提示词要改。
- 长剧(上百集)全剧一次可能超输入上限 —— 超了明确报错,到时再定是换长上下文模型还是分批(本次用户定不分批)。
- 角色并错(不同的人当成同一个)代码只能抓「互相对话」这一种,其余靠③与人审。
- 自动出图的第一张不一定好看;花的是云机时间,开销提前显示,人可以随时「暂停自动推进」。

## 7. 测试与验收

- 单测(FakeLLM 只测确定性路径):`cast` 的覆盖 / 并错判卷、只填空字段、带意见的整组替换、出过图拒改、别名排修改、回滚拦截;
  `drama_review` 三阶段的前提 / 引用判卷 / `also` / 分段定位 / 批准时的三项检查 / 入队内容 / 输入上限;
  `flow.advance` 各关状态与幂等;定稿后的出图 / 四视图 / 声音 / 拆分镜入队。
- 真 LLM 契约:`cast` 一条、`drama_review` 每个阶段一条。
- Playwright 有头全面自测:逐集面板「全剧流程」一栏、两个新审阅页。
- 实战:在《回到古代做将军》上从①跑到④(含云机出图),人审每一步。
