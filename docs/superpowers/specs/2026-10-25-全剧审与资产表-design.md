# 全剧审与 AI 资产表(P20)设计

- **日期**:2026-10-25
- **用户原话**:
  - 「分镜没有 AI 自动生成呢」—— 剧本全批准后分镜被「缺资产」拦住,AI 流程停在建资产这一步;
  - 「剧本,分镜 AI 整体审批也需要加到控制台中」;
  - 选定:「AI 全剧审,人拍板」;范围「全剧剧本、全剧分镜、AI 出角色 / 场景表,**每一个大类之后分别加一个 AI 整体审批**」。
- **实战起因**:《回到古代做将军》10 集剧本逐集批准后,人工通读才看出跨集问题 —— 同一人三种叫法(陈老三 / 老陈 / 老兵)、
  泛称说话人(兵卒甲、粮官……)、第 10 集人设与穿越设定冲突、第 9 集旁白重复第 7 集、第 4 集还没进先锋队就指挥先锋队;
  逐集评审团(`critique`)一次只看一集,看不出这类毛病。

## 0. 流程总图(做完后)

```
逐集剧本(已有) ─→ ①全剧审·剧本 ─→ 采纳的意见按集排「剧本修改」(已有回路)
      ↓
②AI 出角色 / 场景表 ─→ ③全剧审·资产 ─→ 采纳的意见带回②重出一版
      ↓  资产够了 → 已批准剧本、没段落的集自动排拆分镜(已有,P19-B)
逐集分镜(已有) ─→ ④全剧审·分镜 ─→ 采纳的意见按集排「分镜修改」(已有回路)
```

每一步都是 LLM 出、人在审阅页批准才写回(本仓 LLM 纪律不变)。全剧审**只提问题不改东西**,改由已有的修改回路做。

## 1. AI 出角色 / 场景表 `cast`(目标是剧)

- **前提**:至少一集有剧本。参数:`notes`(可空;来自③采纳的意见,格式同修改回路 `revise.check_notes`,空表时不检查条数)。
- **输入**:立项(有就带)、全部有剧本的集(`<episode n="…">` 数据标签)、现有角色 / 场景表(名字与文字字段)、
  代码从剧本里抽出的**说话人清单**(`rules.dialogue_lines`)与**地点清单**(`batch._PLACE`)、`notes`。
- **输出**:
  - `characters`:`name` / `aliases`(剧本里指同一人的其他叫法)/ `appearance` / `styling`;
  - `scenes`:`name` / `places`(归进这个场景的剧本地点名)/ `location` / `time` / `lighting` / `furnishings`;
  - 有 `notes` 时外加逐条回应(`revise.response_schema` 那套,「改 / 不改 + 理由」)。
- **判卷**(代码,回炉):
  - 说话人清单里每个名字**恰好**落在一个角色的 `name` 或 `aliases` 里 —— 泛称(兵卒甲、粮官)也要有归属:
    要么自成一个角色(群演也要有长相才能出首帧),要么并进某个角色;
  - 地点清单里每个地点恰好落在一个场景的 `places` 里;
  - 名字两两不重(含别名);现有资产的名字必须原样出现(只能补字段,不许改名、不许丢);
  - 文字字段非空;`notes` 的回应过 `revise.response_problems`。
- **批准写回**(`repo` 白名单;写前 / 写后存 `llm_run.applied_json`,同修改回路):
  - 新名字 → 新建角色 / 场景(只有文字,参考图之后人点生成,要用云机);
  - 现有资产 → **只填空字段**,人写过的字不覆盖;审阅页逐个标「新建 / 补字段 / 不变」;
  - 别名 → 把**还没有段落**的集里的说话人标签 `别名说:「` 换成 `正名说:「`(只换说话人标签,纯代码);
    已有段落的集不动,审阅页列出来,提示用分镜修改;
  - 「回到这一轮之前」(两态):删本轮新建且**还没出图、没被段落引用**的资产,恢复本轮改过、之后没再改过的剧本;
    条件不满足的逐项列原因,不硬删。
- 批准后照 P19-B 的规则检查:资产够了,就给已批准剧本、没段落的集排拆分镜(复用 `batch.after_script_approved`)。

## 2. 全剧审 `drama_review`(目标是剧,参数 `stage` / `start` / `end`)

一个任务三个阶段,每个阶段一个固定视角、一份类别闭集,其余同评审团(只列问题、逐字引用、不打分、人逐条采纳 / 驳回):

| stage | 看的材料 | 类别闭集 |
|---|---|---|
| `script` | 第 start–end 集剧本 | 称呼不一致、人设冲突、情节重复、台词重复、时间线或因果错、前后集接不上、伏笔没回收 |
| `assets` | 角色 / 场景表 + 剧本 | 漏了角色或场景、该合并没合并、造型与剧本冲突、陈设与剧本冲突 |
| `storyboard` | 第 start–end 集分镜(`storyboard_revise.view` 逐段渲染) | 分镜与剧本不符、场景用错、造型或姿态前后不连续、跨集重复镜头、景别单调 |

- **范围**:`start–end` 一次最多 30 集(`outline.MAX_EPISODES`,同展开分批);`assets` 阶段不分批(资产表本身不大)。
  前提:`script` 要求范围内每集有剧本,`storyboard` 要求每集有段落,`assets` 要求资产表非空 —— 不满足就拒并说缺哪集。
- **每条问题**:`episode`(范围内集号闭集;`assets` 阶段改为资产名闭集)、`quote`(逐字引自那一集 / 那个资产的材料)、
  `category`、`severity`、`suggestion`;`storyboard` 阶段代码按引用定位到段号。
- **判卷**:1–12 条;引用逐字(`verbatim.restore`)且在所标那集 / 那个资产里;改法非空。
- **批准**:`decision = {"adopt": [...], "reject": [...]}`,每条都要表态(复用 `critique.decision_problems` 的口径)。
  全剧审本身不写任何剧本 / 分镜 / 资产。

## 3. 采纳的意见怎么变成修改(两态)

审阅页批准后出现「按集排修改」:确认页逐集列出将要排的意见,人点确认才入队(`llm_queue`,一集一条):

- `script` → 那一集的 `script_revise`:意见 = 「[类别] 改法」,针对 = 引用原文;
- `storyboard` → 那一集的 `storyboard_revise`:针对 = 定位到的段号;
- `assets` → 排一条带 `notes` 的 `cast`。
- 一集采纳超过 10 条(`revise.MAX_NOTES`)就拒并说哪集,让人少采纳几条或分两次排 —— 不静默截断。
- 修改回路出的结果照旧逐集等人审、按意见整组接受 / 驳回。

## 4. 控制台

- 「逐集」面板顶上加「全剧流程」一栏,按 ①②③④ 排四个按钮,每个按钮旁写状态(没跑 / 生成中 / 待你审 / 已批准 + 采纳几条)与链接;
  前提不满足的按钮置灰并写原因(比如「第 3 集还没剧本」)。集数超过 30 时 ①④ 按批出多个按钮。
- 审阅页:全剧审按集分组列问题,每条显示引用、类别、严重度、改法,勾采纳 / 驳回;资产表按「新建 / 补字段 / 不变」列,
  别名替换逐集列出「将把 老陈说 → 陈老三说(N 处)」。
- 新增 LLM 任务登记进 `service.TASKS`,审阅页靠 `panels/llm.py` 现有分发;自测 `KEY_SELECTOR` 加判据。

## 5. 残余风险

- 全剧审本身「schema 全合法但挑得平庸」抓不到 —— 只能靠人逐条采纳;按阶段统计采纳率,长期没人采纳说明这个阶段的提示词要改。
- 30 集一批时跨批问题(第 30 集和第 31 集接不上)看不到:每批的输入额外带上一批最后一集的材料作上下文(只读,不许引用)。
- 资产表的「长相 / 造型」是文字,出图还要人点、要云机;本设计不自动出图(花钱的事人决定)。

## 6. 测试与验收

- 单测(FakeLLM 只测确定性路径):`cast` 的覆盖判卷、只填空字段、别名只换没段落的集、回滚的拦截条件;
  `drama_review` 三阶段的前提 / 引用判卷 / 分段定位 / 30 集上限;「按集排修改」的分组、10 条上限、入队内容。
- 真 LLM 契约:`cast` 一条、`drama_review` 每个阶段一条。
- Playwright 有头全面自测:逐集面板「全剧流程」一栏、两个新审阅页。
- 实战:在《回到古代做将军》上从①跑到④,人审每一步。
