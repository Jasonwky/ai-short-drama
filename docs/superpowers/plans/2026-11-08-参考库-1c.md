# 参考库 1c 期 实施计划(拆解卡)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把参考库里收进来的原料(小说免费章、红果录屏的转写与关键帧、剧评、热度)拆成人能审、能批准的**拆解卡**:
第一层逐集 / 逐章标注,第二层整部汇总「为什么爆」;批准后生成给创作用的**创作视图**(去引用、换名、查重叠)。

**Architecture:**
- 两个 LLM 任务 `ref_unit`(目标 = 一条内容:章节或转写)、`ref_card`(目标 = 一部作品),登记进 `tools/llm/service.TASKS`,走 `gate.run_gated`(strict 结构化、判卷回炉、落 journal)。
- **LLM 运行记录放在参考库 `refs.db` 里**(结构 v4 加 `llm_run`,DDL 与剧库同一份、目标类型换成 `ref_content` / `ref_work`)。
  `service` / `runs` 只依赖传进来的库,直接复用;剧库不动。拆解卡、单元标注、运行记录都在参考库,和剧库隔离(spec 1.3「创作只读创作视图」)。
- **单元标注不单独审批**:人在拆解卡审阅页一次看完整部(卡 + 逐单元表),批准卡时**连带批准**它引用的单元运行(`apply` 写 `ref_unit`)。
  这样仍是「人批准才写回」,又不用逐章点批准。
- 编排:`ref_job` 新种类 `breakdown`(一部作品);`Runtime` 的 LLM 线程池跑:缺哪个单元的运行就开哪个,单元齐了开卡。A 模式自动排,受 `cap_breakdown`。

**Tech Stack:** 现有 `tools/llm`(service / runs / gate / verbatim / claude_cli)、`tools/cut/speech`(按拼音比)、`tools/drama/pacing`、`tools/llm/premise.DIMS`、FastAPI 面板。

**依据:** spec `docs/superpowers/specs/2026-11-07-参考库-design.md` 第 2 节(2.1–2.6)、3.1(拆解卡审阅面板、LLM 调用统计)、3.2(A 模式拆解上限)、4.4(1c);
**用户 2026-11-08 定**:冷门对照只用库里已有标注的作品,自动抽样以后再做。

**完成标准:** 单测绿 + 两条真 LLM 契约测试绿 + 有头自测绿 + 验收(冒烟)通过 + **真机**:对《掌上珠》(5 集转写 + 关键帧 + 剧评)和一部小说各跑一次拆解,人在面板上批准,截图为凭。

### Task 1: 结构 v4

- `REFS_MIGRATIONS[3]`:
  - `llm_run`:**照抄**剧库当前的 llm_run DDL 与 5 个触发器(见 `tools/drama/db.py`:`LLM_RUN_DDL_V5` + 后续迁移加的 `decision_json`、`applied_json` 与它们的锁定触发器 —— 以剧库现在的 `sqlite_master` 为准),
    只把 `target_type` 的 CHECK 换成 `IN ('ref_content', 'ref_work')`。把这份 DDL 抽成 `tools/refs/db.py` 里的常量,新建库与迁移共用。
  - `ref_unit`:`id, work_id → ref_work, content_id → ref_content, unit INTEGER, run_id INTEGER(参考库 llm_run.id), fields_json, summary, quote, quote_at TEXT(视频:秒;小说:空), names_json, visual_json, created_at`;
    **只许追加**(no update / no delete 触发器)。同一内容重拆 = 新行;读取取同一 content_id 的最新一行。
  - `ref_card`:`id, work_id, run_id, version INTEGER, review_json, creation_json, creation_sha, coverage, state CHECK IN ('approved','superseded'), decision_json, created_at`;
    触发器:除 `state` 从 approved → superseded 外不许改、不许删。**卡只在批准时写入**(待审的就是 llm_run 的 proposed,不进这张表)。
  - `ref_job.kind` 加 `'breakdown'`:按 v2 的「改名 → 建新表 → 拷数据 → 删旧表 → 建触发器」重建(ref_job 没人引用)。
- 测试:v3 → v4 迁移数据不丢、`foreign_key_check` 空;新表触发器拦改 / 删;新建库 `sqlite_master` 与迁移库逐行一致(沿用 v2 的写法)。
- 提交 `feat(refs): schema v4 (refs llm_run, ref_unit, ref_card, breakdown jobs)`

### Task 2: 题材闭集与原文 / 引用核对(纯函数)

- `genres.py`:`GENRES`(宽闭集,含 `premise.DIMS["genre"]` 的全部取值,外加:玄幻、仙侠、科幻、无限流、末世、宫斗宅斗、种田、校园青春、豪门、年代、悬疑推理、刑侦 …,`其他` 兜底),
  `TO_PREMISE: dict[str, str]`(每个取值都要有对应,单测守住「全覆盖、对应值都在 premise.DIMS['genre'] 里」);
  `tag_group(source, tags) -> str | None`:平台标签 → 题材(简单关键词表,红果「古风爱情 / 逼婚」→ 古装甜宠 之类;认不出返回 None,冷门对照里这类作品不进分组)。
- `evidence.py`:
  - `unit_text(refs, root, content_row) -> {"kind": "chapter"|"transcript", "text": str, "chars": list | None}`(章节读 txt;转写读 json)
  - `check_quote(unit, quote) -> (ok: bool, restored: str | None, at: float | None)`:小说 `verbatim.restore`;转写:在转写全文上滑窗,用 `cut.speech.hit(quote, 窗口)` ≥ `QUOTE_HIT = 0.8`(常量注出处:拼音判,Whisper 同音字;阈值沿用 `speech` 现有台词判定口径 —— 先读 `cut/speech.py` 现在的合格线,用同一个值),命中返回该窗口首字秒数
  - `check_names(unit, names) -> list[str]`(不在原文里的名字;转写按拼音)
- 单测覆盖:逐字 / 全角半角、同音字转写命中并给出秒数、找不到、名字检查。
- 提交 `feat(refs): genre set with premise mapping; unit text and quote checks for chapters and transcripts`

### Task 3: LLM 任务 `ref_unit`(逐单元标注)

- 模块形状照 `tools/llm/beats.py`(SYSTEM / schema / user_message / judge_factory / apply,`TOOL = "submit_unit"`),`TARGET = "ref_content"`;
  `context(refs, content_id, data_root)`:内容必须是 ok 的 chapter 或 transcript、未清理;带作品名、第几集 / 章、原文;视频带关键帧图片(开头 0–3 秒 7 张 + 之后每 10 秒最多 6 张,共 ≤ 13 张,`images(ctx)` 返回 jpg 字节)。
  `service.Spec(..., model=VISION_MODEL, needs_root=True)`,`max_tokens` 3000。
- schema(闭集,`additionalProperties: false`):`hook`(有 / 无)、`reversal`(无 / 小 / 大)、`emotion`(压 / 放 / 平)、`paywall`(短剧:这集结尾够不够强、适不适合放付费点 是 / 否;小说:章末悬念 有 / 无 —— 同一个字段,SYSTEM 里按 kind 讲清)、
  `summary`(一两句,用自己的话)、`quote`(逐字一句)、`names`(出场人名数组)、视频另有 `visual_hook`(有 / 无)与 `visual_sec`(enum = 给出的关键帧秒数)。
- 判卷:引用 `evidence.check_quote` 不过 → 回炉;名字不在原文 → 回炉;视频 visual_sec 不在关键帧里 → 回炉;小说 summary 与原文连续 12 字以上相同(`fingerprint` 窗口比对,只比这一单元)→ 回炉(「用自己的话」)。
- `apply(refs, content_id, args, ctx)`:写一行 `ref_unit`(quote 存原文写法 / 秒数)。**只由 `ref_card.apply` 连带调用**(见 Task 5),审阅页不单独批准单元。
- 测试:schema 结构、判卷四类打回、apply 写行;用 `FakeLLM`(只测确定性路径)。
- 提交 `feat(llm): ref_unit task annotates one chapter or episode with checked quotes and keyframes`

### Task 4: 冷门对照与跨作品趋势(纯函数 + 查询)

- `contrast.py`:
  - `features(unit_rows) -> dict`:一部作品的第一层统计(钩子覆盖率、反转次数 / 间隔、情绪压放占比、卡点、画面钩子占比,`pacing.stats` 能用就用)
  - `groups(refs, source, group) -> (hot_ids, cold_ids)`:同来源、同 `tag_group`、有单元标注的作品,按最新详情热度中位数分(热度为空的作品不进分组;七猫没有热度 → 按榜单名次中位数,名次小 = 热)
  - `table(refs, work_id) -> {"rows": [{"feature", "hot": "x/n", "cold": "y/m", "distinct": 高 / 中 / 低}], "note": "..."}`;没有冷门样本 → `{"rows": [], "note": "无对照:库里同平台同类作品还没有冷门样本(用户 2026-11-08 定:自动抽样以后再做,可在热榜手动加冷门作品)"}`;
    区分度阈值放 `config.CONTRAST`(暂定:差 ≥ 30 个百分点高,≥ 15 中,否则低),注明暂定。
- `trends.py`:`by_month(refs, source=None) -> [{"month", "n", "genre": Counter, "payoff": Counter, ...}]`(只数已批准、未被取代的卡)。
- 测试:分组、中位数、无对照、区分度档位、趋势计数。
- 提交 `feat(refs): hot/cold contrast over annotated works and cross-work trends`

### Task 5: LLM 任务 `ref_card`(整部汇总)+ 创作视图

- `context(refs, work_id, data_root)`:作品元数据;**每个 ok 单元的最新单元运行**(proposed 或 approved;没有的单元列为「缺」—— 有缺的不让开卡,ValueError 写明缺哪几集);
  剧评(红果:最新一份剧评文件,逐条带序号,不带昵称);热度摘要(代码算:峰值、最近日增量、在榜天数,`heat` 模块);
  节奏统计(代码,`contrast.features`);依据范围文字(代码:「第 1–5 集 + 剧评 9 条(平台共 142 条)」「第 1–5 章(共 16 章免费)」,拆解失败的单元写明)。
- schema:`genre`(`genres.GENRES`)、`payoff` / `conflict` / `hook_type`(`premise.DIMS`)、`persona`:`protagonist` / `antagonist` 各 `{label, contrast}`、
  `cast_types`:`[{name, type}]`(type 是「女主」「男主」「反派婆婆」这类角色类型)、
  `hypotheses`(3–6 条):`{claim, evidence: 剧情 / 剧评 / 热度, units: [集号], review_ids: [序号], quote}`、`techniques`(可借鉴的手法,抽象的「怎么做」)、`not_borrowable`(特有设定、名字、标志性情节)。
- 判卷(代码):
  - `cast_types` 必须覆盖所有单元标注里出现过的名字(不多不少);
  - 剧情类假设:`units` 必须都在依据范围内、`quote` 能在其中某个单元原文里核对上(`evidence.check_quote`);
  - 剧评类:`review_ids` 都存在、`quote` 逐字在其中一条剧评里;可以说依据范围外的剧情,但显示时标「据剧评(二手)」(apply 里由代码标);
  - 热度类:不回炉,由 apply 用 `heat.rising` / 日增量核对,不符就标「与数据不符」;
  - 3–6 条、techniques / not_borrowable 不能空。
- `decision_problems(args, decision)`:照 `critique.decision_problems`:每条假设都要表态(采纳 / 驳回,序号严格),另可带 `extra_not_borrowable: [str]`(人补的「不可借鉴」,每条非空、≤ 60 字)。
- `apply(refs, work_id, args, ctx, decision)`:
  1. **连带批准**这张卡用到的每条单元运行(`service.approve(refs, run_id)` → `ref_unit.apply` 写 `ref_unit`;已批准的跳过);
  2. 组 `review`(args + 代码标注:每条假设的核对结果 / 「据剧评(二手)」/「与数据不符」、对照表 `contrast.table`、依据范围、热度摘要、节奏统计、人的选择);
  3. `creation.view(review, decision)` → 创作视图;`creation.gate(refs, view)` 有 ≥ 12 字重叠就 **ValueError 拒绝批准**(列出重叠片段,人可以驳回那条假设或改补充后再批);
  4. 旧的已批准卡 → `superseded`;写新 `ref_card`(version + 1,creation_sha)。
- `creation.py`:`view(review, decision) -> dict`(只留:题材类、人设类型、采纳的假设 claim(不带 quote / units / review_ids)、techniques、not_borrowable + 人补的、节奏统计、对照表结论、依据范围);
  名字按 `cast_types` 换成类型(长名先换);换完若还有任何单元名字残留 → 拒绝;`gate(refs, view) -> list[片段]`;`sha(view)`。
- `service.TASKS` 登记两条(`ref_unit` 视觉、`ref_card` 文本 `max_tokens` 8000、`max_rounds` 4)。`service.approve` 的 `reset_cost` 只对 `resets_segments` 生效,参考库任务都是 False,不碰 segment 表 —— 加一条测试确认用 RefStore 跑 begin / finish / approve 不访问剧库表。
- 测试(FakeLLM):判卷各分支、decision 校验、apply 连带批准单元并写卡、创作视图去引用 / 换名 / 去驳回假设、重叠拦批准、旧卡被取代。
- 提交 `feat(llm): ref_card task with checked hypotheses, human adopt/reject and a creation view`

### Task 6: 编排(`breakdown.py`)+ Runtime + 到期清理接卡

- `breakdown.progress(refs, work_id) -> {"units": [{content_id, unit, state: 缺 / 跑中 / 待审 / 已批 / 失败, run_id}], "card": {...}, "next": ("ref_unit", content_id) | ("ref_card", work_id) | None, "blocked": 原因 | None}`
- `ref_job(kind='breakdown')`:人点「拆解这部」排一条(`auto=0`);A 模式下 monitor 对自动抓过内容、有 ok 内容、还没有卡的作品排 `auto=1`,当天自动 breakdown 数 ≥ `cap_breakdown` 就停(和 cap_fetch 同口径:现算、立即生效、不补跑)。
- `Runtime`:
  - `start_ref_llm(task, target_id, params)`:`service.begin(self.refs, …)`;后台 `service.finish(self.refs, rid, llm, self.refs_root / "journal", data_root=self.refs_root)`;
  - 每轮(refs-fetch 线程之外,用现有 LLM 单线程池的回调)推进:取一条 running 的 breakdown 任务 → `progress.next` 有就开下一条运行(同一时间参考库只跑一条 LLM),全部单元有运行且卡运行已 proposed → breakdown 任务 done;LLM 失败 → breakdown 任务失败写原因(不自动重试,防空转)。
  - 启动时 `runs.fail_stale(self.refs)`。
- `retention.has_breakdown`:这部作品有 proposed 的 `ref_card` 运行或已批准的卡 → True。
- 测试:进度各状态、按顺序开运行、单元失败停住、A 模式上限、清理顺延条件变化。
- 提交 `feat(refs): breakdown orchestration, auto breakdown cap, cards end the retention deferral`

### Task 7: 面板

- 提交 `feat(refs): breakdown card review panel, creation preview, trends and LLM usage`

### Task 8: 真 LLM 契约测试 + 真机拆解 + 文档

- 契约测试(放现有 `real_llm` 测试旁,先找它们在哪个目录、怎么标记):
