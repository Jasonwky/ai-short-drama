# AI 短剧成熟工作流调研

- **日期**:2026-09-22
- **触发**:用户「先去调研下市面上做 AI 短剧的工作流,看看成熟的工作流怎么做」
- **用途**:`ai-short-drama` 项目的设计输入(尚未产生任何代码改动)

---

## 一、结论先说

1. **环节切分全行业已收敛,没有分歧**。四个独立开源项目(星 1.8k–15.9k)各自实现的流水线几乎一字不差:
   `剧本 → 分集 → 角色/场景/道具资产 → 分镜(景别/运镜/台词) → 逐镜首帧图 → 逐镜视频 → 配音/字幕 → FFmpeg 拼接成集`。
   **这不是一个需要再设计的问题,照抄即可**,设计精力应该花在别处。

2. **一致性靠「实体资产库」,不靠提示词**。所有成熟实现都把**角色/场景/道具/服装**做成
   跨镜头复用的一等实体,镜头只持引用。LTX Studio 叫 Elements,Jellyfish 叫 entity model,
   LocalMiniDrama 叫全局素材库 —— 三家独立收敛到同一结构。**在提示词里描述角色长相是被淘汰的做法。**

3. **「一键生成整集」在 2026 年已被证伪,行业反向回摆到「人在中间控」**。
   这条与 CLAUDE.md 里继承来的「不做 AI 自动编排、人手工流转」**方向一致** —— 但要注意,
   收敛点不是「纯手工」,而是 **AI 做繁重解析 + 人在每个环节挑选/干预**(见 §六,那里有反证)。

4. **三个高价值机制是本项目该抄的**,它们不在「环节切分」这一层,而在「怎么把随机性变成可控生产」:
   - **首尾帧衔接**(上一镜尾帧 = 下一镜首帧)解决镜头间跳变
   - **下一镜构图参考上一镜 + 全局站位规划**(天工短剧工作台)解决站位漂移
   - **工作流组框选整组重跑**(LocalMiniDrama)解决「改一处要重跑一串」

5. **合规是硬约束,不是可选项**:2026-07-01 起 AI 微短剧必须**画面显式标注「AI 辅助制作」
   + 元数据隐式溯源**,未标注批量下线,按投资额三级备案。
   **产物导出环节必须内建标注,否则做出来不能用。**

6. **许可证有一条真红线**:`huobao-drama`(★15.4k,看起来最像现成答案的那个)是
   **CC BY-NC-SA 4.0 —— 非商用 + 传染性 ShareAlike**,已读 LICENSE 原文核实,不可借用代码。
   Toonflow / Jellyfish / LocalMiniDrama 三家 Apache-2.0 / MIT,原文已逐一核实,可参考。

## 三、维度一:环节切分 —— 四家独立实现的对照

| 环节 | LocalMiniDrama (MIT, ★1.8k) | Jellyfish (Apache-2.0, ★6.5k) | huobao-drama (CC-BY-NC-SA, ★15.4k) | Toonflow (Apache-2.0, ★15.9k) |
|---|---|---|---|---|
| 入口 | 梗概 + 风格 | 章节剧本 | 原著小说 | 原著小说 + 章节事件提取 |
| 剧本 | AI 生成多集剧本,可编辑 | script understanding | `script_rewriter` agent 改写成拍摄剧本 | ScriptAgent 出故事骨架/改编策略 |
| 资产 | 角色 / 场景 / 道具 分别生成形象图 | characters/actors · scenes · props · costumes 统一实体 | `extractor` agent 抽取并去重 | 数字资产 |
| 分镜 | 按集生成,含**景别/运镜/台词** | script breakdown → shot | `storyboard_breaker` agent | ProductionAgent 在无限画布编排 |
| 确认闸 | 智能跳过已有内容 | **shot preparation → candidate confirmation → shot ready** | — | 人在画布上编排 |
| 图 | 逐镜首帧/尾帧图 | keyframe + reference image | 角色设计图 + 场景背景图 | 分镜图节点化精调 |
| 视频 | 逐镜生成片段 | shot 级生成工作区,支持单镜/批量 | T2V / I2V 逐镜 | 视频节点 |
| 成片 | 自动合成完整剧集 | export | **FFmpeg 逐镜合成 + 字幕 + 整集拼接** | 工作台内拼接导出 |
| 任务 | 每步最多重试 3 次,实时进度 | **统一异步任务中心**(状态/取消/恢复/耗时) | 任务进度跟踪 | — |

**读出来的三件事**:

1. **`shot`(分镜)是整个系统的主键**。图、视频、台词、参考图、任务全挂在 shot 上。
   Jellyfish 甚至给 shot 设了 `ready` 状态机,**「准备好了」与「正在生成」是两个独立状态** —— 这个区分很关键。
2. **异步任务中心是必需品不是加分项**。单镜视频生成是分钟级,四家有三家专门建了任务系统
   (状态/进度/取消/恢复)。这与 micro-video 的「记账壳」是同一个东西。
3. **增量补全是刚需**:「智能跳过已有内容」「accept or ignore candidates」—— 人改了一处,
   系统只重跑受影响的部分。**不能做成「一按就全量重跑」。**

## 四、维度二:产品形态 —— 三种流派

| 流派 | 代表 | 组织方式 | 适用 |
|---|---|---|---|
| **列表/分步** | Jellyfish · huobao-drama | 左侧进度导轨,一步一页:`script → shot prep → confirm → ready → 生成工作区` | 流程固定、要可审计;新手不迷路 |
| **无限画布** | Toonflow · LocalMiniDrama · LibTV | 节点图:剧本节点 → 首帧/尾帧节点 → 视频节点,可框选成组、整组重跑 | 非线性返工、并行生产;**改一处重跑一串**的场景 |
| **3D 导演台** | 天工短剧工作台 | 轻量 3D 空间搭场景做**场面调度**,产出构图参考再喂给生成模型 | 站位/构图/光源这类「提示词说不清」的控制 |

**与 CLAUDE.md 控制台纪律的对应关系**(本调研对本项目最直接的一条):

> 纪律原文:「每个环节是它自己真正的操作面板,不是通用的 run + 看 JSON:该调参的要有参数/曲线编辑器、
> 该看效果的要能看到效果」「prompt 调不动的东西,就给一个能拖的界面」

3D 导演台正是这条纪律在短剧场景的极端形态 —— 它承认**站位和构图用提示词根本调不动**,
干脆给个能拖的 3D 空间。**这条纪律不是个人偏好,行业头部独立收敛到了同一结论。**

## 五、维度三:四个老大难怎么解

### 1. 角色一致性(所有资料一致认为这是「生命线」)

枚举到的机制,按地基程度排序:

| 机制 | 说明 | 出处 |
|---|---|---|
| **实体资产库 + 参考图锚定** | 角色存成可复用实体,每镜带同一张参考图;锚定五官/服装/身材比例 | LTX Studio Elements · Jellyfish entity model · LocalMiniDrama `@图片N` 多图参考 |
| **Face Reference / Face-lock** | 模型原生的人脸锁定入参 | Kling 3.0 · Veo 3.1「Ingredients to Video」 |
| **LoRA 微调** | 给角色训专用 LoRA | 开源栈常用 |
| **ControlNet** | 姿态/构图约束 | 开源栈常用 |
| **多视角数字资产** | 一次生成角色的多个视角,按镜头取用 | 天工短剧工作台「多视角细节数字资产」 |

⚠️ 这五条里,**只有第一条是所有项目都做了的**,后四条依模型/技术栈而异。第一条是地基。

### 2. 镜头连贯(比角色一致性更少被讨论,但同样致命)

- **首尾帧衔接(FLF2V)**:上一镜的尾帧作为下一镜的首帧。Wan2.1/2.2 原生支持首末帧,
  LocalMiniDrama 有专门的「尾帧衔接」功能。
- **下一镜构图参考上一镜**:天工短剧工作台的导演 Agent 显式做这件事。
- **全局站位规划**:先规划整场的人物站位,再逐镜生成 —— 解决「站位漂移」。

### 3. 配音 / 口型

- 链路:**剧本标注 → 多角色声线分配 → 情感参数调控 → 音画同步**。
- TTS 侧点名的有 Qwen3-TTS(阿里,2026-01,流式首包最低 97ms)、IndexTTS2 系、Fish Audio、VoxCPM 2。
- 口型侧是独立一步:音频驱动面部,音画同步。
- 🟡 **这一环查得最浅**,各家 README 提及最少(huobao 只写了字幕,LocalMiniDrama 的配音藏在「工作流组可勾选」里)。
  **若本项目要做配音,需要单独一次调研。**

### 4. 拼接成集

- 统一答案:**FFmpeg**。huobao-drama 直接用 `ffmpeg-static` / `ffprobe-static` npm 包免安装。
- 包含:逐镜合成 → 字幕烧录 → 整集拼接 → 导出。
- 画幅在**建项目时就定死不可改**(huobao 明确 "fixed after creation"),9:16 竖屏为主。

## 六、维度四:一键全自动 vs 人工流转 —— 证据与反证

**正方(支持「人在中间控」)**:

- > 「所谓『一键成片』在简单演示场景里成立,真要做一个有连续剧情的短剧,几乎没有一键完成的可能。
  > 生成失败、画面崩坏、人物脸不一致、口型对不上,都是高频问题。」
- > 「2026 年行业洗牌后,纯 AI 全自动量产的内容已经全面失效……能跑出流量、实现变现的 AI 短剧,
  > 全部是人工精调、创意差异化、逻辑完整的人机协同作品。」
- 天工短剧工作台的整个卖点就是「**告别随机抽卡**」:把导演职能拆成**六个可视化、可干预的标准环节**,
  「把随机生成变成可控生产」。
- 行业黑话「**抽卡废掉 80% 时间**」—— 同一提示词生成两次结果完全不同。

**反方 / 反证(必须记下来,否则这份调研是选择性举证)**:

- ⚠️ **上述「痛点」论述大量来自内容农场和产品软文**(D 级证据)。「告别抽卡」是天工的**营销话术**,
  它自己也承认创作者仍要「手动选择或调整资产」。**没有任何一家给出抽卡率/废片率的实测数字。**
- ⚠️ 与此同时,**全自动派并没有消失**:huobao-drama(★15.4k)的口号就是
  「一句话生成完整短剧,从剧本到成片全自动化」,Toonflow 用**三层 Agent(决策/执行/监督)**自动编排,
  两者都是星数最高的项目。**「行业已回摆到人工」这个说法被这两个项目直接反驳。**
- ⚠️ 更准确的读法是:**收敛点不是「人工 vs 自动」二选一,而是「全自动能跑通 + 人可在任意环节介入 + 只重跑受影响部分」。**
  四个项目全都同时具备「一键生成/补全并生成」和「逐环节手工编辑」,**没有一个是纯手工的**。
- ⚠️ 这对继承来的纪律是个**需要重新审视的点**:micro-video 的「人是编排者,不是 LLM」在短剧场景下
  可能过于保守 —— 短剧的环节数(剧本/角色/场景/道具/分镜/图/视频/音/拼接)比短视频多得多,
  **每环都纯手工点,人会被点击量淹死**。建议的落点见 §十一.7。

## 十一、对本项目的直接影响

**本次调研未产生任何代码或阈值改动**(本仓尚无代码)。以下是设计输入,待 brainstorming 阶段决策:

1. **环节切分照抄行业共识**,不要自创。省下的设计精力投到 §一.4 的三个机制上。
2. **`shot` 作为主键实体**,配 `ready` 状态机,区分「准备好」与「正在生成」。
3. **资产库(角色/场景/道具/服装)是一等公民**,不是附属品 —— 一致性全靠它。
4. **异步任务中心不可省**,与 micro-video 的「记账壳」同构,可直接复用那套思路。
5. **增量补全是硬需求**:改一处只重跑受影响部分,禁止全量重跑(成本 92% 在视频模型上)。
6. **导出环节内建合规标注**(画面 + 元数据),否则产物违法。
7. 🟡 **需要拍板的分歧点**:micro-video 继承来的「纯人工流转」在短剧的九个环节上可能过重。
   行业收敛的是「**全自动可跑通 + 人可在任意环节介入 + 只重跑受影响部分**」。
   这与「不做 AI 自动编排」是否冲突、如何取舍,是设计阶段的第一个决策点。
