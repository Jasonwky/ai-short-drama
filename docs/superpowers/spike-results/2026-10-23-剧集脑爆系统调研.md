# 剧集脑爆系统调研(2026-10-23)

- **起因**:用户要加「脑爆系统」完善剧集创作,三种形态都要(多方案发散 + 人挑、多角色评审团、人机对话共创),覆盖立项、大纲、单集剧本、分镜四个环节
- **做法**:派一个调研子 agent 限定 4 个问题(约 32 次搜索、12 次抓页),我核验了两条关键数字(下文标「已核验」)
- **证据等级**:网络资料;竖屏短剧编剧惯例大多是从业者经验,**没找到平台官方编剧指南**

## 结论

1. **多 agent 编剧室比「一次端到端生成」好,但没有证据说明它比「同样分阶段的单 agent」好。**
   - Agents' Room(ICLR 2025)的编排器本身是确定性的固定顺序;
   - HoLLMwood 的主评委 GPT-4 与生成骨干同族,有自我偏好风险,自动多样性指标三种方法几乎没差别;
   - Wang et al.(ACL 2024,推理任务)发现,提示写得好的单 agent 几乎追平多 agent 讨论。

   → 评审团的价值在于**用不同视角列出问题清单交给人**,不在 agent 互相辩论。
2. **LLM 当评委,在创意质量上不可信。**
   - 《Art or Artifice》:三个 LLM 与专家判断的相关性接近 0;
   - Agents' Room 的 LLM 评委与人按样本只有 ρ=0.41;
   - LLM 偏爱自己写的东西(NeurIPS 2024,本仓 CLAUDE.md 已引用)。

   → 评审结果只能当「问题清单 + 改法」,**不能当分数排序,也不能自动采纳**。
3. **发散有「多样性塌缩」问题:措辞和温度都救不了,结构化发散有效。**
   - **已核验**:Echoes in AI(PNAS)摘要原文「LLM-generated stories often contain combinations of idiosyncratic plot elements echoed frequently across generations」,而人写的情节「rarely recreated」。报告转述其换 20 种指令几乎不变,我没核;
   - Artificial Hivemind(NeurIPS 2025):不同模型之间也趋同 → 「换个模型再来一版」收益有限;
   - 温度与新颖性只有弱相关(β≈0.31),却拉低连贯性(Peeperkorn,ICCC'24);
   - 有效做法:
     - **先列维度,再按维度强制分化**(Luminate,CHI 2024);
     - **一次出多个候选并写出各自概率**(Verbalized Sampling)。**已核验**摘要原文「in creative writing, VS increases diversity by 1.6-2.1x over direct prompting」;报告里「找回 66.8% 多样性」不在摘要里,没核。
4. **用 LLM 帮忙的人点子更多,但人与人之间更趋同**(Doshi & Hauser,Science Advances 2024;Anderson 等,C&C 2024)。
   → 发散阶段不能只给模型最可能出的几条,要把「套路款」标出来。
5. **竖屏短剧的结构惯例有具名出处的不多**,可做成代码统计的检查项见第 3 节。

## 1. 学术与开源系统

| 系统 | 流程 | 角色 | 结论与证据强度 |
|---|---|---|---|
| Dramatron(DeepMind) | 梗概 → 标题 → 人物 → 情节节拍 → 场景 → 对白,分层生成,每层人可改可重出 | 单模型 | 15 位从业者共写,参与者认可分层可改;剧作家说输出「formulaic」,适合「exploring alternative stories」 |
| Agents' Room(ICLR 2025) | 4 个规划 agent(冲突 / 人物 / 场景 / 情节)写进共享草稿板,5 个写作 agent 分段写;编排器确定性 | 9 个 | 人评优于端到端基线,但人写的仍最受偏好;故事长度约是基线 2 倍,是混杂因素 |
| Re3 / DOC | 规划 → 草稿 → 重排 / 细化层级大纲 + 控制器 | 单模型 + 判别器 | DOC 比 Re3 情节连贯 +22.5%、贴合大纲 +28.2%;去掉了事后编辑步骤 → **大纲越细越可控,比写完再改划算** |
| HoLLMwood(EMNLP 2024 Findings) | 编剧 → 编辑反馈(≤2 轮)→ 演员角色扮演 | 3 类 | 赢基线 76–84%,但主评委是同族 GPT-4,人评仅 30 个样本 |
| StoryVerse(FDG 2024) | 作者写抽象幕 → 规划器展开 | — | 没有定量评估 |

人机交互研究:
- **Luminate**:先生成维度,再按维度组合出回答、铺成空间浏览。这和我们「结构化 JSON + 人挑」最贴近;
- Anderson 等:用 ChatGPT 的人点子之间更趋同、归属感更低;
- Doshi & Hauser:单篇更好,但篇与篇更相似。

## 2. 发散的缓解方法

| 方法 | 证据 | 数据 |
|---|---|---|
| 调高温度 | Peeperkorn ICCC'24 | 与新颖性弱相关,与不连贯中度相关 —— 不是创意旋钮 |
| 先列再逐条展开 | Meincke, Mollick, Terwiesch | 多样性最高(具体数值没核) |
| 一次出多个 + 各自概率 | Verbalized Sampling | 创意写作多样性 1.6–2.1 倍(已核验) |
| 先定维度再强制分化 | Luminate | 交互研究,无定量多样性数据 |

## 3. 竖屏短剧编剧惯例(可做成检查项)

档位:A = 具名从业者原话;B = 媒体或二手转述;C = 普遍流传。

| 检查项 | 内容 | 档 |
|---|---|---|
| 时长 / 集数 | 单集 1–2 分钟,全剧 80–100 集 | A(36氪 / 后浪研究所 2023-12) |
| 反转密度 | 甲方要求「3 到 5 集内」的最低反转数 | A |
| 付费卡点 | 设在快要反转前 | A |
| 前 10 集 | 每集有钩子;第 9–10 集卡付费点;之后每 10 集一个强反转;结尾 3 集回收伏笔 | B(虎嗅,原文没读到) |
| 套路化风险 | 2025 下半年起纯套路爽剧频繁被退稿 | B |
| 开场钩子 | 3 秒 / 15 秒定去留:直接冲突、强悬念、极致反差 | C |
| 单集节奏 | 「10 秒一个冲突,30 秒一个反转」 | C |
| 情绪曲线 | 每集要么「压弹簧」(憋屈)要么「放弹簧」(打脸) | C |
| 合规红线 | 广电总局 2024-11「霸总」管理提示、2025-03「爽而有度」:不靠拜金炫富制造爽点、片名不用「霸总」类字眼 | B(新闻转述) |

**能用代码统计的**:
- LLM 按枚举标注每集的「结尾钩子 / 反转 / 压或放 / 付费点候选」,代码算覆盖率、间隔、连续憋屈集数;
- 片名过敏感词表。

钩子抓不抓人、人设够不够极致,只能当评审意见。

## 对我们的建议(子 agent 提出,我按本仓纪律筛过)

1. **立项**:LLM 先列维度(题材、爽点类型、主角身份、核心冲突,闭集),再出 N 个在维度上互不相同的方案。
   - 代码判卷:维度组合两两不重复、片名过敏感词表;
   - 人逐字段从不同方案里拼,拼由代码完成,不再问 LLM。
2. **发散一律「一次出多个 + 相对典型度 0..1」**:典型度只用来标「套路款」让人知情,不用它淘汰。
3. **大纲**:LLM 逐集标注结构字段,判决交给代码统计(钩子覆盖率、反转间隔、付费点、连续憋屈集数)。
   - 阈值做成配置并标「经验值 + 出处」;
   - 只提示不拦。
4. **评审团 = 多个视角各跑一次,只出问题清单**:每条 `{目标, 类别 enum, 严重度 enum, 原文引用, 改法}`。
   - 代码校验引用必须逐字出现在原文里(防编造);
   - 人逐条采纳或驳回,采纳的再走一次改写、进 `llm_run` 待批;
   - **不辩论、不打分、不自动采纳**。
5. **剧本的对话共创做成「局部改写」**:人选中一场或一句,选意图(闭集),LLM 只回 2–3 个替换候选,diff 预览,人挑了才写回。
6. **分镜以发散为主**:关键段出 2–3 种镜头方案(景别、机位、运镜闭集),确定性检查复用场记表和陈设表;好不好看靠面板并排给人看。
7. **多样性度量**:同批方案的结构字段重合率由代码算,太像就提示「本批趋同」。
