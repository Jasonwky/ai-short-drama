# 配乐读回自检的阈值标定

- **日期**:2026-10-20
- **对应设计**:`specs/2026-10-20-配乐白屏与替换神情-design.md` 一「配乐混音」—— 读回自检加一项「配乐」
- **代码**:`tools/cut/music.py` 的 `readback` / `plateau` / `outside`,常量 `WANT_MARGIN_DB`、`OUTSIDE_BELOW_DB`、`FLOOR_DB`
- **脚本**:`tmp/music_proto2.py`、`tmp/calib.py`(tmp 不入库;做法见下)

## 结论先说

1. **参照音轨用「同一条音频链、不混配乐重编一遍」,不用原片直接解码。**
   这样第一条 cue 之前,成片音轨与参照**逐样本相同**(差异 = −∞);cue 之后只剩 AAC 码率分配(位池)带来的差异,
   比原音轨低 **38 dB 以上**。直接拿原片解码当参照,AAC 重编噪声一直在(比对白低约 37 dB),cue 之前也量不到 0。
2. **cue 内判「音乐在」:成片 − 参照 的电平 ≥ 按包络独立算出的音乐电平 − 6 dB**(只量满音量区间:扣掉淡入淡出、台词及前后 0.3 秒过渡)。
   预期电平由 Python 独立算:音乐文件解码 × `gain_at`,不经 ffmpeg 的音量表达式 —— 用数据审混音,不用混音审混音。
   没混的时候差异是 −∞(逐样本相同),混了的时候差异 ≥ 预期(AAC 噪声只会让它更大),6 dB 是余量。
3. **cue 外判「没漏混、原音轨没被压低」:差异 ≤ 原音轨电平 − 25 dB(或低于 −80 dBFS)。**
   按 cue 外的每一段整体量(不是逐 0.5 秒窗口:对白里的安静窗口会让相对值跳到 −33 dB,窗口太碎会误报)。
   实测正例离上限最近 **12.7 dB**;对白被压低 3 dB 的反例超出上限约 **14 dB**。
4. 没有 cue:PASS,写明「本集无配乐」。

## 反证:为什么不是别的解释

- **「cue 外差异小,是因为配乐本来就小」?** 不是:cue 之前的差异是 −∞,与配乐大小无关(配乐还没开始,两条链输入逐样本相同、编码器确定)。
  cue 之后的差异来自 AAC 位池:不混配乐时这段也是逐样本相同(「没混」反例的 cue 外 = −∞)。
- **「cue 内过了,是因为 AAC 噪声凑出来的」?** 没混配乐时 cue 内差异是 −∞,AAC 噪声只在**真混了东西**时才出现;
  而且和弦 −14 / −24 dB 两档测到的差异与独立算的预期相差 ≤ 0.4 dB,电平对得上。
- **「−34 dB 档测到的比预期高 10 dB 以上,是不是混多了」?** 那一档音乐本身(−62 dBFS)低于 AAC 位池差异,测到的是两者之和 —— 所以只设下限、不设上限。
  这是有意的:上限会在安静配乐上误报。

## 局限(如实)

- **没有用真实音乐标定**:本机没有有许可的音乐文件,用的是粉红噪声与合成和弦。真实音乐有静音段落 —— 量的区间里音乐本身低于 −80 dBFS 时,
  这一项判 FAIL 并提示「调整起止避开静音段」(fail-loud,宁可拦也不放过)。
- **两组真 H3 片、单一码率(AAC 128k)**;cue 外的 25 dB 余量(最近离上限 12.7 dB)在更长的成片、更多 cue 的情况下没测过。
- 这两组没有字幕,台词区间的扣除只在单测样片上走过(`tests/cut/test_export.py`)。
- 对白被压低不到约 0.5 dB 时测不出(按算:压低 0.5 dB 时差异 ≈ 对白 − 25 dB,正好在上限上)—— 混音链用 `amix normalize=0`,单测 `test_mixed_level_follows_the_envelope` 守住「原音轨不衰减」。
