## 结论先说

1. **命中的就是 task 82**(段落 2 第三轮,`outputs/tasks/82/h3_00053_.mp4`,也是段落 2 现在用的视频):报出 **2.33–6.21 秒**一段。
2. **它不是「整屏纯白 3 秒」**:抽帧看,2.33 秒起画面硬切成**人物站在白底前**(红衣女角色,白占画面 46%–64%),
   持续到约 5.8 秒,接着白底一路变亮、6.08–6.21 秒有约 0.15 秒的整屏白闪,6.25 秒切回厅堂实景。
   整屏 ≥ 98% 近白的帧连续不到 0.2 秒 —— **按「整屏近乎纯白 ≥ 0.5 秒」的字面判据,这条报不出来**(见反证 1)。
3. 所以判据改成「**近白像素占画面 ≥ 35% 的帧连续 ≥ 0.5 秒**」:task 82 白底段每帧占比 0.46–1.00;其余 23 条每帧最高 0.13。
   **全量 24 条:命中 1 条(就是 task 82),误报 0 条。** 阈值 0.35 离两边都有余量(下 0.13,上 0.46)。
4. 白底来源**高度疑似**四视图:task 82 的参考图里有角色 1(红衣女)的四视图,纯白底、同一身衣服;
   task 62 用**完全相同的三张参考图与锚点**、只是种子不同(1285067645 vs 20261019),就没有白底段 —— 是种子相关的偶发,
   不是参考图本身必然带出。因果没做对照实验,仍标「疑似」。

## 量法

每帧:缩到 160 宽 → `lut=y='gte(val,200)*255'`(亮度 ≥ 200 置 255,其余 0)→ `signalstats` 的 `YAVG / 255` = 近白像素占比。
亮度按视频原值比:H3 出的是有限范围 yuv420p(纯白约 235),200 ≈ 全范围 214、满亮度的 84%。
占比 ≥ 0.35 的帧连成段,每帧占到下一帧时刻为止,段长 ≥ 0.5 秒才报。一条 6–10 秒的视频本机 0.4–0.7 秒跑完。

## 反证

1. **为什么不用 `negate` + `blackdetect`(「整屏白」判据)**:对 task 82 跑 `negate,blackdetect=pix_th=0.10`,
   `pic_th` 取 0.98 / 0.90、`d` 取 0.5 / 0.1 四种组合,**一段都没报**。白底段里人物占三四成,整屏判据天然漏掉;
   真正的整屏白闪只有约 0.15 秒。所以拿「近白像素占比」当判据,而不是「整帧近白」。
2. **为什么不用 `signalstats` 的平均亮度 YAVG**:task 82 白底段 YAVG 137–170,而平均亮度高本身不代表白底
   (满屏浅灰也很亮);占比直接量「有多大一片是白的」,与人眼「白了一大片」一致。单测里满屏浅灰(0xC0C0C0)占比 0,不报。
3. **为什么阈值不是更低(比如 0.2)**:实战正常片最高 0.13;lavfi 的 `testsrc` 色条自带 0.21 的近白像素
   (单测改用 `testsrc2`,0.11),画面里一块大白墙也会到 0.2–0.3 —— 0.35 给正常内容留了余量。
4. **为什么不是更高(比如 0.5)**:task 82 白底段最低 0.46(3.83 秒附近人物靠近镜头),0.5 会把一段切成几截,
   且有截段不足 0.5 秒漏报的风险。
5. **亮度门 200 稳不稳**:同一批数据换 190 / 210 / 220,task 82 段内占比几乎不变(白底本身在 220 以上),
   其余片子最高占比 0.17 / 0.14 / 0.11(`format=gray` 旧脚本量的)—— 结论对 LUMA 不敏感。

## 残余风险(如实写明)

- **样本只有一部剧、24 条、1 个正例。** 雪景、白纱帐、大面积天空这类本来就亮白的镜头没见过;若画面里白占三成五以上持续半秒,
  会被拦。导出报的是具体秒数,人看一眼就能判断;但目前**没有「这条我确认不是白屏」的放行开关**(设计定了「拦住」,没设计豁免)。
  真碰到时再加豁免并落档。
- 只按亮度判,不看色度:大片高亮的浅黄 / 浅青也会算「近白」。实战没出现,单测也没覆盖。
- 全范围(yuvj420p)来源的片子纯白是 255,门限 200 同样适用,但没有实测样本。
