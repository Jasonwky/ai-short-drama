# 人数 / 手数 / 脸数检测标定(MediaPipe,2026-10-23)

- **起因**:P18 计划 Task 13(spec `2026-10-23-不穿帮验收-design.md` 第 3 节)。调研说人体异常靠确定性检测比视觉大模型靠谱,但要新增依赖,先在我们自己的首帧上标定;用户同意装 MediaPipe
- **证据等级**:B —— 29 张人逐张看过、知道真实答案的实战 / 对照首帧,本机 CPU 实跑
- **脚本**:`tmp/p27calib/calib.py`(阈值 0.5)、`calib_t03.py`(阈值 0.3);逐张结果 `tmp/p27calib/calib.csv`

## 结论

**不接进产品**。MediaPipe 在我们要防的那 4 张已知错图上**一张都没抓到**(0/4),换阈值也一样;清单的 `anatomy`(人数、手脚数)项继续人勾。

- 数人:阈值 0.5 时 19/29 对、0.3 时 22/29 对。错的方向几乎都是**少数**:躺着的人、被遮挡的人、宽袍古装常被漏掉。
- 同一人画两遍(task 99、105,画面里实际 3 人):两档阈值都只数出 2 → 没抓到。
- 多一只拿针的手(task 108、110):手数 0 → 没抓到。手部检测在这种画面里基本检不出手(29 张里多数是 0)。
- 人脸(短距离模型):0.5 时 1/29、0.3 时 5/29,画面里的脸对它来说太小,不可用。

## 量法

- MediaPipe 1.1(pip 包版本号显示 1.1.0)的 Tasks API:`PoseLandmarker`(`pose_landmarker_full`,最多 6 人)、`HandLandmarker`(最多 8 只手)、`FaceDetector`(`blaze_face_short_range`);模型文件从 Google 官方存储下载;
- 「真实人数」是画面里实际画出的人数(重复的算两个),来自我 10-22 / 10-23 逐张看图的记录(`2026-10-22-场记表实战首帧.md`、`2026-10-23-躺姿穿帮归因与规避方案.md`)。

## 反证

- **「阈值太严」**:降到 0.3 数人准确率升了 3 张,但已知错图仍是 0/4 —— 不是阈值问题。
- **「人脸模型选错了」**:短距离模型确实不适合远景;但重复人物那两张里,模型连人体都只数到 2 个,换人脸模型也补不上「数人」这件事的漏检(躺姿、遮挡)。没再试全距离模型,不再投入。
- **「样本太少」**:29 张不多,但 4 张已知错图全漏,这已经足以否定「接进来能自动拦这类错」。
