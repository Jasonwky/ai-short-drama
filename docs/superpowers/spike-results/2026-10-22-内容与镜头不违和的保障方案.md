# 内容与镜头「不违和、不穿帮」的保障方案(2026-10-22)

- **起因**:用户看完题甲第 1 集,问「如何保证出的短剧内容以及镜头切换符合实际,不违和,不穿帮」
- **范围(有界)**:只用本仓已有的实测与调研(下表出处列逐条可查),不做新的外部搜索;给出分层方案与优先级,不含实现
- **证据等级**:B —— 问题清单全部来自真片(实战库 + 云机对照);各项手段的**效果**多数还没实测,文中逐条标明

## 结论

1. **「保证」做不到,能做的是「挡住一部分 + 抓出一部分 + 剩下的让人一眼看出来」。**
   生成是随机的(同参数换种子,白底 2/5、道具重复 2/4),H3 在 8 秒内自己切 1–3 次镜头、提示词控制不了(2026-10-14 实测)。
   所以方案是三道防线:**生成前把该写的写清(规则 + 判卷)→ 生成后用确定性检测抓 → 人在看片面板上终审**。
2. 目前的问题**主要卡在「每段各出各的」**:每段首帧独立按提示词合成,上一段里谁站哪、谁拿着什么、谁跪着、帽子戴没戴,
   下一段一概不知道。这是「穿帮」的主要来源,也是最值得先补的一块 —— **场记表**(结构化的「这一刻的状态」)。
3. 今天加的「床不进厅堂、写朝向、写躺姿」是**点修**:一条问题一条规则,剧换了还会冒出新的。
   通用化的办法是把它们收进两张表:**场景陈设表**(空间合不合理)和**场记表**(前后接不接得上),判卷对表,不再逐条加词。

## 分层方案

### 第一道:生成前写清楚(剧本 / 分镜 / 资产)

| 手段 | 做什么 | 判卷怎么判(确定性) | 解决哪些 |
|---|---|---|---|
| **场景陈设表** | 场景资产多两个字段:用途(枚举:卧房 / 厅堂 / 庭院 / 街市……)与固定陈设清单(床、屏风、案几……);编剧选地点、分镜写首帧时只能用清单里的陈设 | 首帧提示词里出现陈设词表里的词、但不在本场景清单上 → 打回 | 床进厅堂这一类(把今天的点修换成通用规则) |
| **场记表** | 分镜 LLM 除了自由文本的提示词,再交一份**结构化状态**:每段开头每个角色 在不在场 / 姿态(站、坐、跪、躺,枚举)/ 面朝谁 / 画面左右 / 手里拿什么 / 服饰变体;道具 在谁手里或在哪 | 相邻段对表:没交代动作就从跪变站、上一段被拖走的人下一段又在场、同一道具同时在两处、同场景里左右站位对调(越轴)→ 打回或列出来让人确认 | 跪向、躺姿、道具重复、人物凭空出现、越轴 |
| **提示词由表拼** | 首帧提示词里的姿态 / 朝向 / 位置 / 道具大小由代码按场记表拼,LLM 只写表外的氛围 | 拼的那部分是代码,不用判 | 把「写没写」从判卷问题变成不可能漏 |
| 道具尺寸 | 道具资产多一个「相对尺寸」枚举(指尖 / 手掌 / 小臂 / 身长),拼进提示词 | 枚举闭集 | 银针变长棍(**效果待云机对照**,`tmp/p23cloud`) |

LLM 只填枚举与闭集(角色名、姿态、左右、尺寸档),符合 CLAUDE.md「LLM 只输出受限结构化数据」;绝对位置、像素一律不让它出。

### 第二道:生成后用确定性检测抓

| 检测 | 量法 | 现状 |
|---|---|---|
| 白底 / 灰底 | 平底像素占比 | 已有;2026-10-22 补标定:雪景、白纱帐、浓雾不拦,**阴天大片天空、白粉墙会误拦**(靠人工放行) |
| 烧字幕 | OCR 对台词 | 已有 |
| **接缝检查** | 第 N 段尾帧 vs 第 N+1 段首帧:同一场景里背景色调 / 亮度直方图差太大 → 疑似换屋;两帧几乎一样但不是一个镜头 → 疑似跳切 | **没有**;量法沿用 10-14 的帧差,阈值要在实战 26 条上标定 |
| **段内切镜计数** | 相邻帧差 > 30 算硬切(10-14 量法),切镜时刻标在视频卡片上 | 研究脚本有,**没进产品**;切镜后正是背景换屋、帽子丢失的高发处 |
| 视觉模型抽检(可选) | 对切镜后那一帧,按场记表问闭集问题(「沈玉瑶是否面朝萧珩:是 / 否 / 看不出」),印校验数字防瞎答 | **没做、没标定**;只能当「提示人看」,不能当闸门(模型判模型) |

### 第三道:人终审(残余风险的唯一防线)

- **看片面板**:每段按切镜点抽帧成条 + 段与段接缝并排 + 场记表对照,人逐段勾「看过」;没勾完不让导出(或导出时列出来)。
- 理由:「schema 全合法但结果平庸 / 违和」抓不到(CLAUDE.md 残余风险条),而且本项目每次看片都发现了检测之外的新问题。

## 建议的先后

1. **场记表 + 相邻段对表**(第一道的核心):覆盖面最大,把今天的朝向 / 躺姿点修也收进去;要改分镜 schema、判卷、首帧拼提示词,
   要一条真 LLM 契约测试(**SynScale 当前拒绝连接,恢复后才能做契约**)
2. **接缝检查 + 切镜计数进视频面板**:纯本机 ffmpeg,不花云机;先在实战 26 条上标阈值
3. **场景陈设表**:替换今天的「床进厅堂」点修
4. **看片勾选**:改动小,立刻能用
5. 视觉模型抽检:最后做,先拿今天这 6 个真问题当正例标定准不准

## 反证与局限

- 场记表只保证**写对了状态**,模型画不画对仍随机 —— 例如「面朝萧珩跪下」写了,出图是否真面朝,要多种子实测才知道(今天的朝向判卷同样没验证效果)。
- H3 段内自己切镜是模型行为,任何一道都挡不住,只能抓(切镜计数)和锁时刻(关键帧)。
- 「越轴」等镜头语法规则来自影视常识,本项目没有真片证据证明观众会因此觉得违和;列为对表项时先做「提示」不做「打回」。
