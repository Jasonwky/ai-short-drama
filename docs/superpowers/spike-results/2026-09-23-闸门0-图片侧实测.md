## 一、结论先说

| 闸门 | 判定 | 一句话 |
|---|---|---|
| **0-1 装得下/多快** | ✅ **通过** | Q4_K_M **完整驻留显存**(full load),峰值 21.8 / 24.1 GB;4 步档单张采样 **9 秒**,20 步 **58 秒** |
| **0-2 四视图** | ✅ **通过** | 多视角 LoRA 出的正/四分之三/侧/背**是同一个人**,服装细节逐处对得上 |
| **0-3 多图合成首帧(总闸门)** | ✅ **通过(单样本)** | 角色+场景+道具三图合成,三者都保真;**两个不同角色同框不串脸** |

**三个会改设计的发现**:

1. 🔴 **输出画幅由 latent 决定,不由提示词决定**。编辑模型默认 latent 取自参考图 1,
   参考图 1 是横向四视图拼图时,提示词写了 "vertical 9:16" 照样出 2.3:1 横屏。
   **合成首帧必须显式给目标尺寸。** 已修(`--size`)。
2. 🟢 **4 步 Lightning 档画质不输 20 步档,快 4.5–6.4 倍**。
   三图合成:4 步 **25 秒** vs 20 步 **114 秒**,4 步档更锐、更干净、没有接缝。**建议作为默认档。**
3. 🔴 **被挤出槽位的道具,设计必然丢失**。两次实测里,只靠文字描述的玉佩都成了通用造型
   (雕龙淡青玉 → 绿色团块)。印证设计 §6.1 「降级必须报出来,不许静默」。

## 四、踩到的坑(均已处理)

| 坑 | 现象 | 处理 |
|---|---|---|
| **画幅跟随参考图 1** | 提示词要竖屏,出了 2.3:1 横屏 | 工作流加 `EmptySD3LatentImage`(16 通道 /8,与 Qwen VAE 对得上),执行器加 `--size`;不给尺寸时仍跟随参考 1(改背景、出四视图正需要) |
| **标签校验过严** | 多视角 LoRA 的格式不提 `Picture N`,被双向校验拒绝 | 规则改为:**越界引用恒报;「每张图都要被引用」只在 ≥2 张图时成立** |
| **ComfyUI 执行缓存** | 同输入同种子重跑 0.2–0.6 秒返回 | 测时必须变种子;**反过来这是增量补全白捡的能力** |
| **中断的命令其实已执行** | 用户打断的那次提交,云机上照样跑完了,重跑时命中缓存 | 印证 CLAUDE.md「长任务先问心跳」—— 本地中断 ≠ 远端停止 |
| **溯源路径悬空** | provenance 记的是会话临时目录 | 执行器改为把参考图复制进每次运行的 `refs/`;已有 16 份溯源改写为仓内路径 |
| **`.gitignore` 忽略了全部 outputs** | 溯源 JSON 一份都没入库 | 改为忽略大文件、放行 `*.json` |
| **`setsid` 在 Git Bash 不存在** | 隧道拉起失败,ssh 根本没起 | 改用 `subprocess.Popen` + Windows `DETACHED_PROCESS`;**正式的隧道模块不能依赖 setsid** |
| **「角色 B」其实是同一人** | `CHARACTER_s403.png` 与角色 A 是同一角色的另一张渲染,两角色测试无效 | 另行生成一个明显不同的角色重测 |

## 五、反证与局限(必读)

1. ⚠️ **n=1**。每个条件只跑了一个种子。「4 步不输 20 步」「两角色不串脸」都是**单样本观察**,
   换种子、换角色可能翻车。**要做结论,每个条件至少 5 个种子。**
2. ⚠️ **只测了二次元画风**。源图是动漫风格。写实风格下的一致性**完全没测**
   (设计已砍掉真人写实风格,但「半写实 3D 漫剧」是主流风格,未覆盖)。
3. ⚠️ **判读全靠人眼**,没有量化的身份相似度指标(如人脸 embedding 余弦相似度)。
   这是后续要补的机械层闸门(对应 CLAUDE.md M-5:能确定性测的不交给人眼)。
4. ⚠️ **测试素材来自云机上其他项目**(角色 A 源图),仅作内部闸门实验,**不得用于任何对外产物**。
5. ⚠️ 场景、道具、角色 B 都是**从同一张角色图整幅替换生成**的。这条路径能用,
   但它意味着我们**还没有纯文生图能力**(Qwen-Image-Edit 必须有输入图)。
   正式流程里「从文字生成场景空镜」要么继续走这条替换路,要么补一个文生图模型 —— **待定**。
6. ⚠️ 构图控制弱:双人镜头两人被推到画面边缘。**「空间合同」(layout)能不能管住这个,尚未验证。**
