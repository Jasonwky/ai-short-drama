### 🔴 在这个已出片的工作流里抓到的 bug

提示词原文:
> "Use \<Picture 2\> and \<Picture 1\> as reference frames and **\<Audio 1\> exactly as it is**"

但全工作流**没有任何音频输入节点**(只有解码端的 `VAEDecodeAudio`),`ref_audios` 槽位为空。

> **模型收到一个指向不存在素材的 `<Audio 1>`,ComfyUI 不报错。**
> 这是设计 §6.1「标签零校验,静默错位」的活案例,而且发生在一个已经出片的工作流里。
> **双向断言必须做**:①每个标签有对应素材 ②每个素材被引用过。

## 六、Qwen-Image-Edit 的节点约束(新发现)

### 6.1 🔴 只有 3 个参考图槽位

`comfy_extras/nodes_qwen.py` 的 `TextEncodeQwenImageEditPlus`:

```python
io.Image.Input("image1", optional=True)
io.Image.Input("image2", optional=True)
io.Image.Input("image3", optional=True)
```

**固定三槽,不是 Autogrow。** 对比 H3 的 `ref_images` max=9。

> **对设计的影响**:「角色四视图 + 场景空镜 + 道具白底」= **正好 3 张,一个不剩**。
> 一个镜头里有两个角色就放不下。**必须定取舍规则**,例如:
> 主要角色 > 场景 > 次要角色 > 道具;或把多个角色合成一张拼图送入。
> **这条要写进设计,闸门 0-3 要专门验「两个角色同框」的情形。**

### 6.2 引用标签与 H3 同源

```python
image_prompt += "Picture {}: <|vision_start|><|image_pad|><|vision_end|>".format(i + 1)
tokens = clip.tokenize(image_prompt + prompt, images=images_vl, llama_template=llama_template)
```

节点**自动**在提示词前拼 `Picture 1: …Picture 2: …`,正文里用 "Picture 1" 指代。

> 🟢 **与 H3 的 `<Picture i>` 是同一套心智模型**,设计里 `@角色名 → 序号` 的映射
> 在图、视频两端可以共用一套上层语法,只是展开形式不同。

### 6.3 `vae` 不接就没有 reference_latents

```python
if vae is not None:  ...  ref_latents.append(vae.encode(...))
```

不接 `vae`,参考图只走 VL 条件(384×384),**没有 latent 级参考**。
与 H3「不接 VAE 参考图只作用于文本编码器」是同一个陷阱。**必须接。**

### 6.4 官方 2511 模板的参数

模板 `image_qwen_image_edit_2511.json`(随 ComfyUI 附带)的子图:

```
UNETLoader → ModelSamplingAuraFlow(3.1) → LoraLoaderModelOnly(Lightning-4steps-V1.0-bf16)
CLIPLoader(qwen_2.5_vl_7b_fp8_scaled, type=qwen_image) ; VAELoader(qwen_image_vae)
LoadImage×2 → TextEncodeQwenImageEditPlus(正/负,均带 vae)
FluxKontextMultiReferenceLatentMethod['index_timestep_zero'] ×2
VAEEncode → CFGNorm(1,False) → KSampler(euler/simple, denoise=1) → VAEDecode → FluxKontextImageScale
档位:PrimitiveInt 4/40 + PrimitiveFloat 4/1 + ComfySwitchNode(与 H3 工作流同一套路)
```

**官方参数建议表**:

| | Qwen 官方 | Comfy |
|---|---|---|
| Steps | **40** | **20** |
| CFG | **4.0** | **4.0** |

加速档:**4 步 + CFG 1.0**。

⚠️ 模板里的 Note 说 `FluxKontextMultiReferenceLatentMethod`
「not needed if you use Comfy files, but may be needed…」——
我们用的是 unsloth 的 GGUF 不是 Comfy 打包文件,**可能需要接**,待验。
