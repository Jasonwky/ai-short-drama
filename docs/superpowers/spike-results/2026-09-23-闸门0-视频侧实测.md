# 闸门 0 · 视频侧实测(0-4 / 0-6)

- **日期**:2026-09-23
- **机器**:AutoDL RTX 4090 24 GB · RAM 1007 GiB(带卡模式)· ComfyUI 0.34.0
- **模型**:`minimax_h3_ref2va_pruned_fp8_scaled` + `qwen3vl_32b_minimax_h3_int8_convrot` + 视频/音频 VAE
- **执行器**:`tools/gate0/run_video.py`;溯源在 `outputs/gate0/0-4-*/`、`0-6-*/`(已入库)
- **评测工具**:`tools/gate0/asr_check.py`(Whisper 转写)· `tools/gate0/eval_voice.py`(声纹相似度)
- **证据等级**:A(本机实测,种子固定,可复现)

## 一、结论先说

| 闸门 | 判定 | 一句话 |
|---|---|---|
| **0-6 H3 加速档** | 🔴 **未过** | PDD 8 步 LoRA 与云机的**剪枝版**底模不兼容,50 层 adaln 打不上;ComfyUI **不报错照样出片**。用户决定先接受 20 步 |
| **0-4 音色一致性** | ✅ **通过(不靠参考音频)** | 不给参考音频,同一首帧+同一角色描述下各片与参考声 0.919/0.933(阈值 0.86);负对照(不同声音)仅 0.55 —— **尺子有效** |
| **0-4 参考音频机制** | 🔴 **不推荐** | 没有可测收益(0.910),却引发**内容复读**(2 条中 1 条) |

**四个会改设计的发现**:

1. 🔴 **LoRA 与底模形状不符时,ComfyUI 只打日志、照样出片。** 必须在提交前做确定性预检
   (已写 `tools/gen/lora_compat.py`,只读 safetensors 头,精确复现了 ComfyUI 的 50 处失败)。
2. 🔴 **H3 的 `ref_audios` 不只是音色参考,会被当作「在同一时间位置复现的声音内容」。**
   段 B 开头 0–5 秒复读了参考音频的「这块玉佩」,时间位置与参考完全对齐。
3. 🟢 **不给参考音频,H3 也能在同一首帧 + 同一角色描述下产出很接近的嗓音**(对参考声 0.919 / 0.933)。
   → `voice_ref` **不应作为默认必喂项**;音色一致性可能主要靠固定首帧与固定声音描述。
4. 🟢 **速度只取决于步数**:8 步与 20 步的每步耗时几乎相同(42.8 vs 44.4 s/it)。
   加速的唯一杠杆就是少走步 —— 而当前可用的少步方案一个都没有。

## 二、实测数据

**量法**:采样耗时取 ComfyUI 日志进度条;台词用 Whisper large-v3-turbo 转写后与要求台词做字符级相似度
(去标点);声纹用 WavLM-base-plus-sv x-vector 余弦相似度(模型卡给的同人阈值 0.86)。
**样本量**:每个条件 **n=1**。

### 2.1 耗时(8 秒片 = 192 帧,768×1344)

| 片段 | 档位 | 采样 | s/it | 执行器总耗时 |
|---|---|---|---|---|
| A | 8 步(PDD **部分生效**,无效档) | 5 分 42 秒 | 42.84 | 7.2 分钟 |
| B | 20 步 | 14 分 48 秒 | 44.4 | 15.7 分钟 |
| C | 20 步 | 同上 | 44.4 | (接管取回,见 §四) |
| B′ | 20 步 | 14 分 14 秒 | ≈44.4 | 21.9 分钟(含排队) |
| C′ | 20 步 | 14 分 15 秒 | ≈44.4 | 16.0 分钟 |

**单集估算**(20 步):8 秒片约 15 分钟 → 每秒成片约 1.9 分钟 → 3 分钟一集约 **5.5–6 小时**。
⚠️ 这是按 8 秒片线性外推;片长越长单位秒越贵(ai-ecommerce 实测 13.7 秒片 36.4 分钟 = 2.7 分钟/秒),
**用短段落比长段落省**,这是个可利用的设计杠杆,待验证。

### 2.2 0-4 台词与声纹

参考声 = 段 A(台词「这块玉佩,是我母亲留给我的。」,Whisper 转写**一字不差**)。

| 片段 | 参考音频 | 种子 | 台词字符相似度 | 转写 | 对 A 声纹 |
|---|---|---|---|---|---|
| B | 有 | 1001 | — | **这块玉佩**,她却再也没有回来 | 0.981 ⚠️ 被复读抬高 |
| C | 有 | 1002 | **1.00** | 如果你真的在乎我就把真相告诉我 | **0.910** |
| B′ | 无 | 1001 | **1.00** | 我等了他整整三年他却再也没有回来 | **0.919** |
| C′ | 无 | 1002 | **1.00** | 如果你真的在乎我就把真相告诉我 | **0.933** |

**完整声纹矩阵**:

|  | A | B | C | B′ | C′ |
|---|---|---|---|---|---|
| A | 1.000 | 0.981 | 0.910 | 0.919 | 0.933 |
| B | | 1.000 | 0.916 | 0.910 | 0.926 |
| C | | | 1.000 | 0.896 | **0.973** |
| B′ | | | | 1.000 | 0.948 |
| C′ | | | | | 1.000 |

**读出来的**:
- 给参考音频(C 0.910)**不比**不给(B′ 0.919、C′ 0.933)更像参考声
- **C 与 C′(同台词同种子,只差有无参考音频)0.973** —— 台词与种子对声纹的影响**大于**参考音频
- B 的 0.981 是**复读造成的**:B 与 A 的波形在零滞后处互相关 0.42、能量包络相关 0.73,
  转写证实 0–5 秒就是 A 的原话

### 2.3 负对照(尺子能否分辨 H3 的不同声音)—— ✅ 能

N 与 B′ **同台词、同种子、同为普通话**,只有声音不同(中年男声)。N 的转写一字不差(字符相似度 1.00)。

| 对比 | 声纹 |
|---|---|
| N vs B′(只差声音) | **0.551** |
| N vs A / C / C′ | 0.604 / 0.533 / 0.606 |
| 女声片段之间 | 0.896 – 0.973 |

**分辨力足够**:同一把女声 0.90+,不同声音 ≈0.55。前面 0.91/0.92/0.93 的判读因此成立。

## 三、0-6:PDD 加速 LoRA 为什么打不上

| 模型 | `blocks.N.adaln_proj` 形状 |
|---|---|
| 云机底模 `minimax_h3_ref2va_**pruned**_fp8_scaled` | weight **(96768, 8)** |
| PDD 8 步 LoRA | lora_A (64, **2688**) · lora_B (96768, 64) → 增量 (96768, **2688**) |
| Turbo 4 步 LoRA | 不含 adaln_proj 键,**208 层全匹配** |

**「pruned」剪的正是 `adaln_proj`**,输入维从 2688 压到 8。PDD 插件 README 原话是配「bf16 原版或 int8 版」,
即未剪枝底模 —— 选型时没追问剪枝版兼容性,是调研遗漏。

**现象**:208 层打上,50 层 adaln(0–49 全部)打不上;ComfyUI 每层记一条 ERROR,
**并且每次权重换入显存都重打一次补丁、重报一次**(一条 8 步片累计 300 行),任务照常完成、产物照常落盘。

**段 A 就是在这个半蒸馏模型上跑的**,画面干净、台词正确 —— 但这不说明它可用:
「打了一半」的配置不受支持,画质不可预期,且会被误当成已加速。执行器已拒绝该档位。

**加速的剩余选项**(均未做):

| 方案 | 代价 |
|---|---|
| Turbo 4 步 | ai-ecommerce V13 实测否决:「人物形象崩坏:头发红绿花色、脸部塑料感、嘴部畸形」 |
| Spectrum(免训练跳步,约省 45%) | 要往**共享的** ComfyUI 装自定义节点,需用户批准 |
| 未剪枝底模 + PDD | int8 约 32 GB,磁盘不足;24 GB 卡能否跑未知 |

**用户决定(2026-09-23)**:先接受 20 步。

## 四、踩到的坑(均已处理)

| 坑 | 现象 | 处理 |
|---|---|---|
| **LoRA 形状不符静默降级** | 见 §三 | `lora_compat.py` 预检 + 执行器拒绝 PDD 档 |
| **瞬时网络异常让执行器崩掉,云机任务成孤儿** | C 跑到一半执行器抛出未处理异常(超时/连接重置**不是 `URLError`**);批次继续提交下一条,C 的产物落在云机无人取回 | 客户端把超时/连接异常归为「连不上」;`wait()` 在 10 分钟预算内持续重试;`history()` 不再把「连不上」吞成「查不到」;执行器新增 `--attach PROMPT_ID` 接管在途任务 —— **C 就是这样救回来的**,溯源标 `attached: true` |
| **批次脚本在源头 `grep`,吃掉了失败信号** | C 的 Traceback 被过滤,监控什么都没看到 | 批次不再过滤输出,筛选交给监控端 |
| **监控解析写错** | 反转日志后取到进度条首帧,误报「12 分钟停在 0/20」 | 改为取最后一个进度片段 |
| **`--exclude` 多模式被当成文件名** | Whisper 下载只落了 4 KB | 改为显式列出所需文件 |
| **声纹模型许可证** | 模型卡 license 字段为空,母仓库 unilm 是 MIT;但模型卡指向的 UniSpeech LICENSE 原文是 **CC BY-SA 3.0** | 仅限内部评测,**不得进产品** |
| **「无关说话人」基线无效** | 两条旧片转写只有「you」「¡Yo mío!」,几乎无人声 | 另跑负对照 N,见 §五 |

## 六、反证与局限

1. ⚠️ **n=1**,且复读只在 2 条带参考音频的片子里观察到 1 次,**比例不可信**。
2. ✅ ~~声纹尺子的分辨力未经校准~~ —— 负对照已校准(§2.3)。但**只有一个负样本**,换性别之外的差异(同性别不同人)能否分开,未测。
3. ⚠️ **没有人耳复核**。转写证明了内容,声纹给了一个数,但「听起来是不是同一个人」最终要人听。
4. ⚠️ 所有片段用**同一张首帧**、同一段角色描述 —— 「不给参考音频也像」可能**只在这种强约束下成立**。
   跨场景、换首帧、换情绪时是否还稳,**没测**。
5. ⚠️ 只测了 8 秒片。更长片段下复读、音色漂移是否加重,未知。

## 七、对设计的影响

| # | 改动 |
|---|---|
| 1 | **LoRA 形状预检是硬门**:任何不符即拒绝提交 |
| 2 | `character.voice_ref` **不作为默认必喂项**:实测不喂也一致、喂了有复读风险。角色的**声音描述**(如「清亮女声、平静略带忧伤」)应成为角色资产的正式字段,每段都带 |
| 3 | 若使用参考音频,**必须对每条成片做转写核对**,抓复读;复读 = 内容错误,不许放行 |
| 4 | 任务盯梢必须容忍断线并支持**接管**;这也是控制面重启后恢复在途任务的机制 |
| 5 | 产能按 20 步估:**3 分钟一集约 5.5–6 小时**(待更多样本校准) |
| 6 | 待定:段落时长偏短是否更省(单位秒成本随片长上升) |
