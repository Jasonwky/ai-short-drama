# 平底背景检测标定:白屏检测扩到灰底(2026-10-21)

- **问题**:白屏检测(`2026-10-20-白屏检测标定.md`)按「亮度 ≥ 200 的近白像素占比」判。四视图对照(`2026-10-21-白屏诱因四视图对照.md`)
  里种子 20261023 那条切到「李福站在浅灰影棚底前」(亮度约 190),**漏报**。用户定:扩检测,灰底也拦
- **代码**:`tools/cut/blankscan.py`(`flat_ratio` / `measure`),阈值 `LUMA = 160` / `SAT = 0.12` / `GRAD = 5` / `RATIO = 0.35` / `MIN_SEC = 0.5`

## 结论先说

1. 判据改成「**平底像素**占比」:亮度 ≥ 160、饱和度 (max−min)/max ≤ 0.12、3×3 邻域内相邻像素亮度差都 ≤ 5(160 宽尺度)。占比 ≥ 0.35 连续 ≥ 0.5 秒报出
2. **41 条视频:正例 4/4 报出,负例 0/37 误报**。正例每帧峰值 0.50–1.00,负例 ≤ 0.12(产品代码复跑,`tmp/flatcal/product.txt`)
3. 灰底那条报 0.83–3.92 秒;task 82 报 2.33–6.29(旧判据 2.33–6.21,结尾那 0.08 秒白闪叠化)
4. 旧判据会把**浅黄平墙**(亮度高、有颜色)当白屏;新判据看饱和度,不报 —— 单测覆盖

## 样本

- 正例(人眼逐帧确认是棚拍底 / 白底):实战 task 82(白底)、`p20cloud/four_20261023`(浅灰底)、`p19cloud/noqh`(发白天空底)、`p19cloud/oneshot`(白底)
- 负例:实战其余 25 条(含白墙、白衣、烛光、窗光、萧珩白色中衣近景)+ 对照实验其余 12 条
- **存疑,不当正例**:实战 task 65(第 5 段第二轮)李福近景身后一面虚化米色墙 —— 饱和度 0.19–0.32、亮度 100–170,像虚化的室内墙也像棚拍,
  人也判不准;这类在正常近景里很常见,硬拦会误报。新判据峰值 0.005,不报

选中间那组 L160 / S0.12 / G5(余量 +0.386),离各边都不贴。连段比例 0.25 / 0.30 / 0.35 三档报出的条目完全相同(`tmp/flatcal/spans.txt`),沿用原来的 0.35。

## 反证与局限

- **为什么不只降亮度门槛**(近白 → 「≥ 160 就算」):浅黄平墙、烛光照亮的墙面亮度都过 160,没有饱和度与纹理约束会误报;旧判据已经误报浅黄平墙(单测)
- **为什么要纹理约束**:实战负例里亮而中性的像素不少(白衣、窗纸),但它们有褶皱 / 窗格;棚拍底平滑(样块标准差 ≤ 3)
- 样本仍只有一部剧、4 个正例;雪地、雾、白纱帐这类「本来就该是平的浅色」画面没见过 —— 命中时报出秒数,人可在视频卡片上**填理由放行**(已有机制)
- 每条 8 秒片耗时约 2 秒(旧判据 0.5 秒),导出前逐段跑,一集 9 段约 20 秒
- 缓存参数(`PARAMS`)变了,旧的 `<视频>.blankscan.json` 自动作废、导出时重扫;人工放行按视频 sha256 记,不受影响
