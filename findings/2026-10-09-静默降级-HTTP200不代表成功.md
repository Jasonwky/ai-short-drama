# 静默降级:HTTP 200 不代表成功

## 一句话

外部服务最危险的失败不是报错,而是**返回 200、结构也像样,但做的不是你要的事**。本项目踩到 4 次,
每次都靠一个**确定性的旁证**(token 数、印在图上的数字、元数据原文)才发现。

## 案例

| # | 现象 | 表面 | 实际 | 旁证 | 落点 |
|---|---|---|---|---|---|
| 1 | SynScale `response_format: json_schema` | 200,返回 JSON | schema **没送进模型**,输出是自由发挥 | `prompt_tokens` 不随 schema 变化 | 只用 strict 工具调用;客户端再校验(`tools/llm/gate.py`) |
| 2 | strict 工具调用 | 200,工具参数齐 | **不是服务端约束解码**:出过非法 JSON、多余字段、enum 外的值 | 客户端 JSON Schema 校验报错 | 校验失败带错误回炉、轮次上限 fail-loud |
| 3 | 默认模型 `deepseek-v4-flash` 看图 | 200,照样填工具参数 | **图没进模型**:蓝底红方块答成「没有形状」 | `prompt_tokens` 只有 803;图上印校验数字,读不对 | 看图用 `gpt-5.6-luna`;校验数字印在同一张图上(第二张图不可靠) |
| 4 | 同一模型名被路由到不同上游 | 时好时坏的 400 | 各上游只认一种 `tool_choice` 拼法 | 报错原文「缺 tool_choice.name」 | `82e7ba5`:按报错切换拼法 |

**同类但方向相反的一例**:ComfyUI 生成的每个 mp4 元数据里**嵌着完整工作流**(提示词、种子、模型名、参考图文件名)——
不报错、不显眼,导出时若不清空就把这些外发出去,且违反 GB 45438「只保留一份隐式标识」。落点:导出前清空原有元数据再只写 AIGC。

## 反证:是不是偶发 / 是不是我们用错了?

- #1:三种传法 × 7 个模型对照,只有强制 strict 工具这一种让 `prompt_tokens` 随 schema 涨 —— 不是偶发
- #3:同一张图换 `gpt-5.6-luna` 就答对、token 随图涨(448 → 2181)—— 不是图的问题
- #4:同一请求在不同时段 12/12 通过与全部 400 交替出现 —— 是路由,不是我们的拼法单方面错
- 样本量都小(每组 3–12 次),结论按「倾向」读;但每一条都有**可复查的调用记录**

## 改变了什么

- LLM 一律经 `gate.run_gated`:strict 工具调用 + 客户端 JSON Schema 再校验 + 代码判卷 + 回炉 + 轮次上限(CLAUDE.md「LLM 调用纪律」)
- **要测 LLM 就用真 LLM**:真 LLM 契约测试(`pytest -m real_llm`),Fake 只测确定性路径 —— Fake 会把上面这些全部盖住
- 看图任务必须有「真看到了」的判据(校验数字),不能信 200
- 导出读回自检逐项核对元数据(含「只有一份 AIGC」)

## 还没解决

- SynScale 只有 http,key 与剧本原文明文传输(用户已知情选择,控制台按钮旁有提示)
- 上游路由随时可能再变,只能靠契约测试定期跑来发现
